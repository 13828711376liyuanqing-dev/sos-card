# OTA Boot 启动选择与首次迁移边界

SAM | 2026-10-20 +08:00 | 实现可恢复事务的启动选择候选模块，移除隔离入口中的厂商安装绕行；首次迁移仍拒绝未证实的SCA更新。

## 本轮实现

新增 `tools/ota/boot/yp001_ota_start.c/.h` 的 `yp_boot_select_start`。调用方必须先读取持久日志、每次启动只调用一次；成功返回经过验签的A槽镜像描述，失败清零输出。它不授予安装权限、不改SCA、不跳转、不代替业务健康确认。

| 持久状态 | 启动选择行为 |
|---|---|
| EMPTY/未知 | 拒绝；空日志不能证明当前镜像可信，首次可信配置另行提供 |
| PREPARED | 只验旧镜像并选旧程序；不调用activate，不因候选损坏阻止可信旧程序运行 |
| INSTALL | 继续已提交的交换事务，完成后进入试运行选择 |
| TRIAL | 启动前持久记录尝试次数；次数耗尽或新镜像校验失败时走核心回退，再选旧程序 |
| ROLLBACK | 完成反向交换，再验旧镜像，才允许选择 |
| CONFIRMED | 验新镜像后选择；失败拒绝，不编造自动恢复策略 |
| REVERTED | 验恢复后的旧镜像后选择 |

安装/回退恢复处理的是已经持久提交的未完事务，不是在开机时自行创建新升级。PREPARED仍必须由上层重新满足固定70%、充电、稳定静止、无报警及其他安全条件，持久提交后才能转INSTALL。

输出结构不能与Boot上下文别名；失败禁止跳转。试运行次数会因调用累加，不能将此接口放入业务轮询循环。实际跳转还需要后续验证向量表、栈和入口范围，不能把本函数成功直接等同于可安全执行任意地址。

## 移除厂商安装绕行

发现：关闭 `BOOTLOADER_DFU_ENABLE` 不会自动删除厂商 `bootloader_dfu_task` 的所有复制分支。该函数仍能识别已有DFU元信息并调用普通复制、APP_INFO改写和复位；超时函数也可擦DFU_INFO。这些路径不经过新白名单。

因此隔离工程 `logs/ota_preflight_20261020/boot_min_signed/Src/user/main.c` 移除以下调用：

- bootloader_dfu_task、bootloader_verify_task、bootloader_jump_task。
- bootloader_timeout_task。

隔离入口仍执行原外围初始化、只读函数指针保留探针，然后看门狗循环；没有批准布局/可信包/迁移后端时不实际执行新选择器，也不启动应用。Map核实厂商DFU任务、超时擦除、跳转、复制和APP_INFO改写函数不再保留为实际代码。签名实现、新选择器、事务核心和Flash后端均实际保留。

厂商源文件仍属于参考工程输入，SDK原文件没有改。正式Boot发布前仍需审查其他启动/库副作用；移除这些已知路径不是全固件无旁路的最终证明。

**本目标仍禁止烧录。** 入口地址与现有应用重叠，而且当前是安全停留的构建验证目标，不会正常启动产品业务。没有生成要用户下载的新主工程HEX。

## 首次迁移为何仍未开放

官方开发指南当前证据确认：SCA位于前两个4KiB扇区，下载算法/GProgrammer用APP_INFO生成启动信息。SDK参考从0x00200000读取Boot信息，从0x00200040枚举镜像信息，但这是二级Boot源码，不是ROM选择规则与掉电恢复保证。

当前未取得ROM对SCA两扇区的完整冗余/代际选择/提交标记规则，不能自行推断“有两个扇区就能原子更新”。普通先擦后写SCA可能在中断后失去启动入口；将备份放在用户Flash中也不能证明ROM会读取它。

正式首次迁移准入需要：

1. 核实ROM/SCA冗余及失败恢复官方规则或可复现证据；若不支持可证明的掉电恢复，不能把现场远程首次迁移当成已经支持。
2. 按最终Boot产物验证不重叠的存放区和可信包，盘点其与当前应用、未来A/B、用户区关系。
3. 准备完整可恢复的启动元信息备份与受控写入步骤，只涉及批准的启动区域，不格式化/移动NVDS或恢复旧用户快照。
4. 逐步故障注入验证每次擦写中断后的ROM启动选择，随后经授权进行设备试验。工装可救回不等于无人值守迁移通过。

在这些证据齐备前，当前主工程继续正常运行，首次迁移功能不启用。不要求用户继续重复下载已有主工程HEX。

- 空日志拒绝且没有写擦，PREPARED不自动提交；候选验签失败仍选旧程序。
