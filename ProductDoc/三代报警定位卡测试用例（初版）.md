# 三代报警定位卡 测试用例（初版）

> 版本：V0.2（基于 PRD V0.12 / 软件技术文档 basic / 端侧功能与交互规格 V0.6；在 V0.1 基础上按 2026-10-15 定位顺序调整同步：新增 3.14 定位策略用例组，更新 TC-SOS-01 / TC-SLEEP-SOS-01 / TC-ON-01 / TC-PWR-03 / TC-SEARCH-01 取位预期）
> 目的：根据产品定义与墨水屏交互情况，梳理初版功能测试用例，供固件开发、联调与测试参考。初版聚焦功能正确性，性能与可靠性边界留待样机实测补充。
> 标注【待确认】的用例或步骤，依赖后续会议 / 联调结论回填。

## 1. 测试范围与术语

- **范围**：活动态 / 静止态切换、上线流程、周期扫描、SOS 报警（活动态 / 休眠态）、一键寻人、VoIP 通话与白名单、VoIP / VoLTE 互斥、OTA、低电量、墨水屏显示与交互、消息确认超时、NFC、异常恢复。
- **术语**：见端侧功能与交互规格第 1 章（BLE SoC / Cat.1 / 活动态 / 静止态 / 低功耗模式 / 常规模式）。
- **优先级**：P0（核心安全功能，必过） / P1（重要） / P2（一般）。

## 2. 测试前置

- **设备**：三代样机（蓝牙 GR5512 主控 + Cat.1 受控从机），500mAh 电池，27×27mm 墨水屏。
- **平台**：IOT 平台 + 泰康之家联络中心 VoIP 账号；`phoneBindMsg`（CallOut 呼出号 + CallInList 呼入白名单）已正确配置。
- **环境**：园区 Seekcy iBeacon 覆盖；可模拟静止（无运动）、运动、按键、断网、充电等条件。

## 3. 用例

### 3.1 状态机与电源管理

| 编号 | 标题 | 优先级 | 前置 | 测试步骤 | 预期结果 |
|------|------|--------|------|----------|----------|
| TC-PWR-01 | 三轴运动唤醒 | P0 | 静止态（Cat.1 真断电 0 电流） | 1. 静置 >5min 进入静止态；2. 模拟运动 | Cat.1 上电注册入低功耗模式；发 `onlineMsg`；平台 `paraSetMsg(查)` 后决策；进入活动态 |
| TC-PWR-02 | 按键唤醒（静止态） | P0 | 静止态 | 1. 双键长按 3s（SOS）或连续按查 IMEI | 按键同样唤醒：先给 Cat.1 上电入活动态再执行对应逻辑；不依赖三轴运动 |
| TC-PWR-03 | 静止判定 5min | P0 | 活动态 | 无运动持续 5min | 先 `periodicMsg` 清 beacon 缓存 → `offlineMsg`（电量+位置；**取位顺序：Beacon → WIFI → LBS → GPS → 空位置**）→ Cat.1 硬断电 0 电流 → BLE 低功耗 |
| TC-PWR-04 | 活动态低功耗↔常规 | P1 | 活动态 | 触发上报 / VoIP | Cat.1 自动切常规模式，完成回低功耗；不随单次业务硬断电 |
| TC-PWR-05 | 充电 / 电量门槛 | P2 | — | 电量 <25% / OTA 提交 | 低电量提醒 + `lowBatteryMsg`；OTA 提交需 充电中 + 电量 ≥70%（端侧固定阈值） |

### 3.4 SOS 报警（活动态）

| 编号 | 标题 | 优先级 | 前置 | 测试步骤 | 预期结果 |
|------|------|--------|------|----------|----------|
| TC-SOS-01 | 活动态 SOS | P0 | 活动态 | 双键长按 3s | 切常规 → `sosMsg` → `sosReplyMsg`（60s 内未确认重发，最多 3 次）→ `sosLocationMsg`（**取位：有Beacon 报 Beacon；无 Beacon 则 LBS/WIFI/GPS 各自扫描、完成一路传一路；均无则只报空位置**）→ `sosLocationReplyMsg`（60s 内未确认重发，最多 3 次）→ VoIP 单次拨打（不重拨）→ 报警进行中至长按 / 平台取消 |
| TC-SOS-02 | 防误报 | P0 | 活动态 | 单键 / 两键时差 >500ms | 不触发 |
| TC-SOS-03 | 报警中再按 | P1 | 报警进行中 | 再次双键长按 | 忽略不打断（不重拨） |
| TC-SOS-04 | 单次拨打不重拨 | P0 | 活动态 | 报警且对端不接听 | 拨一次即止；报警保持进行中，不因未接通结束 |
| TC-SOS-05 | 长按取消 / 挂断 | P1 | 通话中 | 长按按键 | 挂断 + 语音提示；报警结束 |

### 3.14 定位策略（2026-10-15 取位顺序调整）

| 编号 | 标题 | 优先级 | 前置 | 测试步骤 | 预期结果 |
|------|------|--------|------|----------|----------|
| TC-LOC-01 | 顺序链逐级回退 | P0 | 活动态，逐项屏蔽来源 | 上线 / 下线 / 寻人取位：仅 Beacon→仅 WIFI→仅 LBS→仅 GPS | 按 **Beacon → WIFI → LBS → GPS** 依次尝试，取到即用；每级屏蔽后自动落到下一级 |
| TC-LOC-02 | 顺序链全失败 | P0 | 活动态 | 屏蔽全部来源 | 上报**空位置**（onlineMsg / offlineMsg / personSearchReplyMsg 均适用） |
| TC-LOC-03 | SOS 有 Beacon | P0 | 报警 + 园区 Beacon 覆盖 | 双键长按 | `sosLocationMsg` **只报 Beacon**（短路，不触发 LBS/WIFI/GPS） |
| TC-LOC-04 | SOS 无 Beacon 逐路传输 | P0 | 报警 + 无 Beacon | 双键长按 | LBS、WIFI、GPS **各自扫描各自，扫描完成一路就传输一路**（每路独立 `sosLocationMsg`，PositionType 0/1/2 对齐协议 V1.3；非等待汇聚） |
| TC-LOC-05 | SOS 全失败空位置 | P0 | 报警 + 无 Beacon/蜂窝/GPS | 双键长按 | `sosLocationMsg` **只报空位置**（PositionType=3） |
| TC-LOC-06 | WiFi 定位精度 | P2 | WIFI 覆盖环境 | 触发 WIFI 定位 | 定位成功、半径合理（数据格式对齐协议 V1.3 WIFI 数据包） |
| TC-LOC-07 | WiFi 扫描与传输时分 | P1 | 联调环境 | WiFi 扫描期间观察数据传输 | 联调确认：若 WiFi 扫描影响数据传输，扫描时暂停数据传输、避免上传丢失（以联调结论为准） |

## 4. 初版未覆盖 / 待补充

- **性能边界**：报警响应 3~15s 实测校准、续航 ≥7 天实测、蓝牙定位精度 ≤3m。
- **物理 / 环境**：IP68、1.2m 跌落、按键寿命 ≥10 万次、重量 45–48g。
- **墨水屏资源存储策略**（PRD 待确认事项 7）：字库 / 图片建议优先本地固化，网络下发可行性待评估。
- **VoIP / VoLTE 互斥**：切换时序、优先级与生效通道选择（待确认）。
- **呼入白名单缺配**：设备的具体行为（告警 / 记录 / 拒所有呼入）。
- **屏显刷新节奏**：事件驱动 vs 定时（待确认）。
