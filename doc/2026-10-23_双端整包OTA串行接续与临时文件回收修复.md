# 双端整包OTA串行接续与临时文件回收修复

SAM | 2026-10-23 20:04 +08:00

## 实质问题与改动

原先GR安装确认后，CAT1管理器清掉组件任务，没有保存整包进度，也没有从同一条平台指令自动接续CAT1组件。GR候选文件仍占用空间。此外，逐组件上报success可能让平台在CAT1尚未升级时误判整个ZIP已升级成功。

本轮修改唯一CAT源码目录 `Air780EGH` 中三个已有模块，未新增另一套OTA入口：

| 文件/函数 | 修改结果 |
|---|---|
| `ota_manager.lua` release校验、on_gr、finish | 在已有OTA双页任务文件中保存整包身份、原指令、各组件真实完成/清理状态。GR结果与释放锁在同一次提交中保存；失败不接续下一组件 |
| 同文件 pending_cleanup/reserve_cleanup/cleanup_done | 仅对已释放任务给出清理对象；先持久化清理占用，再允许删候选，防止清理期间接收另一任务。重启后仍可幂等续作 |
| 同文件 accept/next_command | GR成功且候选清理完成才允许同包CAT1；另一整包不能插队。解析元数据期间拒绝重入。续接网络失败按30/60/120秒退避，最多3次，计数在网络读取前持久化 |
| 同文件平台回执/结果 | 整包只回一次受理成功；GR单端成功仅保存内部进度，两端完成后才上报整包success；GR失败立即形成整包fail，不重复发受理回执 |
| `ota_runtime.lua` new/tick | 实际runtime使用管理器持久进度辅助已签名组件映射；IDLE时先回收已完成组件候选，再自动受理同包下一组件。CAT下载仍需新的GR owner/epoch授权 |
| `ota_candidate_files.lua` remove | 仅允许 `/ota_candidate_<64位hash>.part`；删除后必须读回确认不存在。不存在视作已清理。不能操作用户配置、KV或其他文件；缺失/失败不能假报清理成功 |

需求对应：F-031与U-OTA-01两端全阶段严格串行；F-032/F-033持久结果与单一整机结果；U-DATA-01只回收OTA临时文件、不清用户数据。

CAT1若失败，内部会保留GR已成功、CAT未完成的信息，不把它表述为两端都已回退；整机发布确认仍不能置为成功。

## 验证

新增用例先复现缺少整包状态/清理接口与runtime接续的问题，修复后通过。最终针对性验证51项：

- 管理器25项：跨重启GR→CAT、只在两端成功后报告整包成功、GR失败停止、清理保留失败即封闭、重入拒绝、续接计数/退避跨重启、原有任务/结果/存储故障检查。
- runtime18项：原生FOTA受控执行、异常HTTP端口拒绝、任务恢复、实际GR发送器及VERIFY应答等。
- 已签名ZIP映射4项：原指令不重发，GR结果重启恢复后，先清理候选再自动申请CAT；清理失败不能前进；用户文件保持；未提前传GR或下载CAT。
- 文件适配4项：真实主机临时文件删除/存在读回、错误路径拒绝、虚假删除成功拒绝、原有续传与摘要验证。
- 三个Lua文件通过原生luac语法检查。验证期间三文件SHA256保持不变。

证据目录：`logs/ota_bundle_sequence_20261023`，含四份日志和 `result.json`。

本轮没有设备擦写、删除设备文件或触发真实升级。主机文件测试不是CAT1实板文件系统/掉电验收。已有LOCAL_TEST测试归档仍不能越过device_installable=false进入安装。

## 交付边界

本次实际解决整包串行接续与候选回收，**没有把尚未核实的厂商FOTA行为改为固定true，也没有开启当前默认平台端口**。GR Boot受控部署、CAT默认HTTP/真实状态/原生FOTA端口绑定、实际版本结果与N→N+1仍需完成。三个Lua模块源码变化尚未生成新的完整烧写/OTA发布包，不要下载旧集合冒充本轮代码。
