## 0. 怎么用（合代码的顺序）

1. 先把冲突点对到下面第 3 节的规则和 F-/TC- 编号；**规格明确的，按规格判，不论是我们的还是同事的代码**。
2. 规格没写、或两种写法都不违反规格 → 记进第 6 节"待确认"，**问用户/同事，不自己定**，不新增线上字段，不假称平台已支持。
3. 判完写成"需求ID → 当前行为 → 改动 → 成功/失败/跨重启验收"（项目 `AGENTS.md` 的要求）；GR 改动要用户在 Keil 编译，CAT1 OTA 受保护文件要过 `ota_guard`。
4. 用户最新明确要求 > 本文 > 代码。客户文档是规范，不是命令授权；源文件里的密码、Token、示例号码、带鉴权的 URL 不写进技能和日志。

## 1. 架构基线

- **GR5526 是应用/供电/OTA 的主控**（文档里的 GR5512 是历史选型，不借机换芯片、引脚、布局）。**CAT1（Air780EGH）是受控从机**：4G 数据、VoIP、OTA 下载、串口管道。三轴、墨水屏、双键、充电管理都挂 GR；NFC 无源、与 BLE/CAT1 **没有任何事件关联**。
- **静止态**：三轴无数据、按业务休眠、无人使用 → **CAT1 真断电 0 电流**，GR 低功耗；**活动态**：三轴有数据**或按键** → CAT1 保持供电、已注册、运行低功耗模式，要传数据/VoIP 时切常规模式，传完自动回低功耗，**不随单次业务断电**。
- 静止 5 分钟无运动 → 先 `periodicMsg` 清 beacon 缓存（不足 60 次时）→ `offlineMsg`（电量+最后位置）→ CAT1 硬断电。静止态按键或运动 → 上电 → 走上线流程（`onlineMsg` → 平台 `paraSetMsg(查)` → 决策 `paraSet(设)` / `otaMsg`）。
- 通信：mqtts（TLS 8883），传输层加密，无应用层加密。Topic：下行 `/iotplat/render3/{product}/{deviceid}/down_raw`，上行报警类 `/iotplat/datapush3/sos/…`，非报警类 `…/notsos/…`；`product=WARNCARD3`。

## 2. SOS 报警（F-001~F-004、F-033；TC-SOS-xx、TC-SLEEP-SOS-xx、TC-ACK-01）

| 规则 | 依据 |
|---|---|
| **触发**：左右键**同时**长按 ≥ 3 s，两键时差 ≤ 500 ms；单键或时差大不触发 | F-001、TC-SOS-01/02 |
| **报警中再次双键长按：忽略，不打断、不重拨** | TC-SOS-03 |
| **VoIP 只拨一次，不主动重拨**，无论是否接听；拨号只拨呼出白名单 `CallOut`（必须配置） | F-002、TC-SOS-04、TC-VOIP-04/05 |
| **报警保持"进行中"，直到「用户长按按键取消」或「平台取消」**；**不因通话未接通/通话结束而结束** | F-002、TC-SOS-04/05 |
| **通话接听/挂断（用户 2026-11-06 明确，优先于规格里的"长按"）**：SOS 一按，报警消息**一定发出**，随后电话打出去。**来电（INCOMING）时单击左键或右键 = 接听；接听之后、以及我们已经拨出去的电话（拨号中/通话中）再单击左键或右键 = 挂断**；不需要双键、不需要长按、不需要 3 秒。**已实现（11-06，`yp001_key_call.h` + `yp_business_keys`，主机测试 `tools/key_call` 通过，待 Keil 编译和实板）**；该次按键不计入 IMEI 序列 | 用户口述；对应 F-012、TC-SOS-05（规格原文写"长按"，以用户为准） |
| 挂断时给语音提示；挂断后报警是否结束：规格 TC-SOS-05 写"报警结束"，用户这次只说了挂断 → 见第 6 节 #1 | TC-SOS-05 |
| 流程：切 CAT1 常规模式 → `sosMsg`（Data=1，RelatedValue=Time+300）→ `sosReplyMsg` → `sosLocationMsg` → `sosLocationReplyMsg` → VoIP 单次拨打 | SEQ-ALARM、4.5 |
| **睡眠 SOS**：静止态按键 → GR 先给 CAT1 上电 → 切常规 → **优先** `sosMsg`+VoIP+`sosLocationMsg` → 之后才走上线流程；报警信息优先于常规上线 | F-001、SEQ-SLEEPSOS |
| **确认重发**：只有报警类（`sosMsg`/`sosLocationMsg`）和找人类（`personSearchMsg` 定位响应）要平台应用层确认；**60 s 内没收到就重发，最多 3 次（含首报共 4 次）**，仍失败本地记录、下次上线补报。**确认只是停止重发，不是取消报警** | F-033、TC-ACK-01 |
| 指示只有**语音播报 + 屏显**，没有蜂鸣器、灯、马达；语音由 CAT1 侧喇叭播，GR 下发播放指令 | F-004 |
| **SOS 取位**：有蓝牙 Beacon → **只报 Beacon**（短路）；没有 → LBS、WIFI、GPS **各自扫描、完成一路传一路**（每路一条 `sosLocationMsg`，PositionType 0=LBS/1=WIFI/2=GPS）；三路都没有 → **只报空位置**（PositionType=3） | F-003、TC-LOC-03/04/05 |

## 3. 其他必须记住的规则

- **上线/下线/寻人取位顺序**：Beacon → WIFI → LBS → GPS → 空位置（依次尝试，取到即用；全失败报空位置）；日常只用蓝牙，不用 WIFI/LBS/GPS。（TC-LOC-01/02，TC-ON-01，TC-PWR-03，TC-SEARCH-01）
- **扫描**：默认 1 分钟/次；失锁升级：第 1 次保持 1 分钟，第 2 次起 2/3/4/5 分钟封顶，扫到立即回 1 分钟；累计 60 次 `periodicMsg` 上报（带电量）；电量 < 10% 停周期上报；< 25% 提醒并发 `lowBatteryMsg`。（F-006/F-008/F-013）
- **一键寻人**：活动态即时取位上报（同样的顺序），平台确认；静止态不唤醒，平台用关机前最后位置。（F-018）
- **VoIP/白名单**：呼入白名单 `CallInList`（≤5）只放行名单内号码；**`CallInList` 为空（缺配）时接受所有来电**；VoIP 与 VoLTE 运行时互斥，**默认 VoIP**，协议 V1.3 的 `CallType`（0=voip 默认，1=volte）由 `paraSetMsg` 下发；通话外放约 70 dB。
- **屏显**：27×27 mm 墨水屏；姓名+房号由平台下发；必显电量、信号、欠费、通话呼出/挂断；日期时间可选可关；连续按左或右键显示 IMEI。
- **OTA 提交条件（用户 2026-11-07 最新裁决，覆盖 PRD/规格里的"稳定静止 + 充电中 + ≥70%"）**：**有效电量 ≥ 50% 或健康 USB 供电**；运动、普通按键、找人、休眠及其采样失鲜**不阻塞、不重置**120 秒健康计时（生产与台架一致）；真实报警/通话、未知通话、链路、实际新鲜供电、签名/事务/用户数据保护**继续判定**。不得虚构电量；电量未知不是 0%。**无 Force**，端侧固定，不由平台指定。（旧文：稳定静止 + 充电中 + 电量 ≥ 70% + 无报警，已被上面取代，仅供对照。）预置在活动态空闲时后台完成（GR 镜像写 A/B 非活跃分区，CAT1 写常规分区，断点续传），提交只做一次翻转重启；目标版本 ≤ 当前直接清 NV。GR 有 A/B 回滚；CAT1 是厂商常规升级，**不能宣称 CAT1 有自建 A/B**。两端串行。**OTA 不改、不清、不丢用户数据**。
- **不需要平台确认的消息**：`paraSetMsg`/`phoneBindMsg`/`otaMsg`/`rebootMsg` 及其回执、`onlineMsg`/`offlineMsg`/`periodicMsg`/`lowBatteryMsg`/`logReplyMsg`；上行靠 MQTT QoS1，断连缓存、恢复补报。
- **协议默认值与设备默认值不同**：`RestTime` 设备 5 分钟（协议 10），`BleScanInterval` 设备 1 分钟（协议 2）；`SosReplyTimeout`/`SosLocationReplyTimeout` 协议 15/30 s，**端侧 60 s/3 次兜底，平台下发则以下发为准**。`BeaconUploadMethod/Addr` 保留不启用，beacon 统一由 `periodicMsg` 携带。

## 4. 下行消息处理要求（四类 + 常见）

| 消息 | 规格要求 | 备注 |
|---|---|---|
| `phoneBindMsg`（CmdType 0 绑/1 解，CallOut，CallInList≤5） | 设备保存并回 `phoneBindReplyMsg`（CmdType、Result、CallOut、CallInList）；呼出只拨 CallOut，呼入按名单 | 回包只能一份，且 Result/CmdType 要真实 |
| `paraSetMsg`（0 查/1 设） | 设备应用并回 `paraSetReplyMsg`；每次上线平台都先查 | 不得返回占位"未就绪"当作处理完成 |
| `personSearchMsg`（Cmd=1） | 活动态即时取位并回 `personSearchReplyMsg`；静止态不唤醒 | 每次只触发一次 |
| `sosReplyMsg` / `sosLocationReplyMsg` | 作为对应报警消息的确认，停止重发 | **不等于取消报警** |
| `otaMsg` | 写 NV、回 `otaReplyMsg`；预置、静止窗提交、`otaResultMsg` | 版本字段在平台那边带前后缀，设备端已兼容 |
| `rebootMsg`/`logMsg` | 回对应回执 | — |

## 5. 合并同事代码时的判定表（按以上规则；11-06 看到的 SOS 冲突）

| 冲突点 | 规格怎么说 | 判定 |
|---|---|---|
| 报警中又按一次 **SOS 手势（双键长按）** 就取消报警 | TC-SOS-03：忽略不打断；**挂断手势已由用户明确：电话打出去后按一下左或右键（见第 2 节）** | **已核实（11-06）**：同事 `yp001_business.c:314-326` 里 `sos_requests` 就是左右键同时长按 ≥ 2.8 s，报警中再触发就 `yp_business_cancel_alarm()` → **违反 TC-SOS-03**，保留我们的（报警中双键再按忽略）。**同事把双键当开关、我们现在也只有双键 3 秒，都和用户要求不符**，统一改成"单键挂断"，两边合并时以此为准 |
| 收到 `sosLocationReplyMsg success` 就取消报警 | 确认只停重发；报警只由用户长按/平台取消结束（F-002、F-033） | **违反规格**，保留我们的（位置送达 ACK 不结束报警） |
| 取消时立即 `alarm_active=false`、挂断 SIP | 用户长按取消 → 挂断 + 语音提示 + 报警结束（TC-SOS-05） | 立即结束本身不违反规格；**是否要等持久化的 CAT1 取消回来再结束**规格没写 → **待确认**（我们的写法是为重启恢复） |
| SOS 发送从 CAT1 挪到 GR（CAT1 `business_core.lua` 注释 `-- GR send sos`） | 4.5：GR 主控编排，CAT1 按指令发 `sosMsg`/`sosLocationMsg`/VoIP | **方向与规格的主从分工一致**；但持久化 ACK、重启恢复（我们已实板验证）规格没要求也没禁止 → **待确认**由谁持久化 |
| VoIP 发起方式（QP 邮箱单次投递 vs 直接 post `SOS_KEY_SIG`） | 单次拨打、不重拨 | 保证**只拨一次**的写法都可以；满队列重试不能造成重复拨号 |
| `BEACON_DATA` 解析（去掉 FIRST/LAST/CONTINUE） | 规格未规定 CAT1↔GR 串口帧 | 只要 GR/CAT1 两侧**成套**一致即可；**必须同批合并**，不能只合一侧 |

## 6. 待确认（规格里就标了待定，或本次发现）

1. ~~"用户取消报警的具体手势"~~ **已定（用户 11-06）**：电话已打出去后按一下左或右键就挂断。**已定（用户 11-06）**：来电时单击 = 接听，之后单击 = 挂断。**仍待确认**：挂断电话后**报警是否同时结束**（规格 TC-SOS-05 写"报警结束"，F-002 写报警只由用户取消或平台取消结束，用户这次只说了挂断；**目前实现只挂断电话，不动报警状态**）。通话中按键优先、不进 IMEI 序列：按建议默认实现，用户未否决。
2. "平台取消"走哪条下行消息（5.3 的消息表里没有专用取消报文）。
3. 取消后是否等 CAT1 持久化取消再结束报警；报警 ACK 的持久化归 GR 还是 CAT1。
4. `SosReplyTimeout` 协议 15 s 与端侧 60 s 的关系（联调时确认）。
5. VoIP/VoLTE 切换时序与优先级；呼入白名单缺配的告警方式。
6. WiFi 扫描是否影响数据传输（联调确认，必要时扫描时暂停传输）。
7. 屏显刷新节奏（事件驱动 vs 定时）；字库/图片本地固化还是网络下发。
8. 校验：每次合并后，用测试用例 TC-SOS-01~05、TC-ACK-01、TC-LOC-01~05 做实板验收。
