# 2026-10-31 把带保电逻辑的 GR 烧到板上：流程方案（待你评审，未执行任何写入）

SAM | 2026-10-31 17:50 +08:00

## 一、为什么要烧
板上 GR 是 1.5.4/b8，没有"OTA 期间不许断电"规则。CAT1 做 OTA 时电被断，GR 的 B 槽只写到 8192 字节就停（连续两轮一样）。靠 CAT1 发文本行重置同事 AO 定时器的办法不可靠。新 GR（1.5.5/b9，`test\GR5526_1.5.5_b9_signed.hex`，15:38 生成）带完整保电，但要先装到板上。

## 二、已查清的事实（只读）
- 备份：`logs\gr155_hold_flash\pre_flash.bin`（整片 1 MiB，烧写前）。
- Boot 日志最新记录 generation 1978，state 5，`new_desc` = 当前 A 槽（OTA 装上 1.5.4 时写入）。
- 历史上每次"成套交付"，Boot 里都内嵌一个 40 字节"基线描述符"，是 A 槽镜像的指纹；换 A 就要重新编译 Boot 并一起下载（`doc/2026-10-25_*` 系列、`tools/ota/pair_gr_*_build.py`、`finalize_gr_*_pair.py`）。
- 所以：**只写 A 槽、Boot 不动，很可能起不来。** 之前的 J-Link 流程假设板子是 1.0.2/b3 基线，不适用于 OTA 之后的状态。

## 三、不确定的地方（需要先只读确认，不能猜）
1. Boot 启动时到底拿哪个指纹核对 A：Boot 内嵌描述符，还是 Boot 日志里最新记录的 `new_desc`。
2. OTA 装完后 Boot 内嵌描述符有没有被更新（`boot_matches_previous_paired_boot=false`，说明和上次配对的 Boot 已经不同）。
3. 配对脚本是否还能用于现在的 SDK/布局（脚本是 10-25、10-26 写的，针对当时的产物）。

## 四、方案 A：成套交付（稳妥，工作量大）
1. 只读：按 `Boot` 源码 `tools/ota/boot/yp001_ota_entry.c` 确认核对逻辑，回答第三节三个问题。
2. 签名包用已有的 `test\GR5526_1.5.5_b9_signed.bin`，算出它的 40 字节描述符。
3. 生成 Boot 变更清单（只改 40 字节描述符；R6 范围数据 148 字节取自当前实时快照），你在 Keil 里编译 Boot（0 错误 0 警告）。
4. 核对：新 Boot 相对现有 Boot 只变 40 字节（`finalize_*` 同类检查）。
5. 你授权后用 Keil "只下载"工程依次下载 A 和 Boot，一次复位，读回核对。
6. 板子起来后：先 `cat1_power on` 再一次 `key`，刷 `receiver_reset_out_hold`，再走 OTA。
- 失败恢复：用 `pre_flash.bin` 按页写回（需另写恢复步骤，J-Link Commander 不能写 Flash，只能走 Keil）。

## 五、方案 B：不烧 GR，用硬件保 CAT1 的电
如果 CAT1 能由外部或 USB 独立供电（命令里 `USB may supply VBAT`），OTA 期间用外部电源给 CAT1 供电，GR 断不断轨都不影响，就不需要先烧新 GR。需要你确认板子能否这样接线。这是成本最低的验证办法，但不能替代最终的保电逻辑。

## 六、方案 C：同事把保电规则并入他的发布

## 九、只读核对结果（17:58，已读 Boot 源码，未写任何东西）
依据：`tools/ota/boot/yp001_ota_start.c`、`yp001_ota_entry.c`。
1. **Boot 启动时核对的是日志里的描述符，不是内嵌的**：状态为 CONFIRMED/TRIAL 时，取日志里的 `new_image`（长度+哈希），对 A 槽做 `verify_image`，不一致就返回 -1（不启动）。`yp001_ota_start.c` 第 15–19 行。
2. 内嵌的基线描述符只在两种情况有用：日志为 EMPTY（`yp_boot_start_baseline`），或日志为 PREPARED 时做 R6 维护修复。板子现在是 state 5（已确认），两种都不是。
3. 结论：**只重编 Boot、改内嵌描述符不够**，换 A 之后启动校验仍按旧日志失败。
4. 因此"成套交付"在这块板上的真实做法只有两种：
   - **方案 A1（建议）**：清空 Boot 日志两页（0x2F7000、0x2F8000，对应布局里的 `{0xf7000,0xf8000}`），让 Boot 走 EMPTY 路径，用新 Boot 内嵌的新 A 基线描述符启动。等于把板子重置回"基线交付"状态：A、Boot 重写，日志清空，B 槽、NVDS、owner 页不动。需要你编译新 Boot（只变 40 字节描述符）。
   - **方案 A2**：手工伪造一条新的 Boot 日志记录。这是伪造 Boot 自己的安全状态，我不建议，也不会做。
5. A1 的副作用和风险：
   - 丢掉回滚能力（旧日志没了；B 槽里的 1.5.3 不再被 Boot 引用）。
   - GR 的 owner 页（0x2F9000/0x2FA000）里的 OTA 记录还在，GR 新固件起来后会怎么看这条记录没验证过，要先在 `tools/ota` 的主机测试里确认，不能直接上板。
   - 这一步最终是写 Boot 区，只能用 Keil 下载，不能用 J-Link Commander；失败恢复靠 `pre_flash.bin`。
6. 另外确认：方案 B（给 CAT1 单独供电）这块板做不到，已排除。
