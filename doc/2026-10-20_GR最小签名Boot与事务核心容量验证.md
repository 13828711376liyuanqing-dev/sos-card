## 测量口径

| 指标 | 仅最小验签参考 | 加入完整事务核心 |
|---|---:|---:|
| Code | 29388 | 31324 |
| RO data | 344 | 352 |
| RW运行数据 | 3044 | 3072 |
| ZI运行数据 | 34240 | 34244 |
| Map Total ROM（压缩RW初值） | 30172 | 32140 |
| Load Region未压缩大小 | 32776 | 34748 |
| 未压缩大小按4KiB保守对齐 | 36864 | 36864 |

最终Map的加载大小为0x87BC、压缩大小0x7D8C。保守按36KiB保留，不能只因压缩ROM小于32KiB就认定最终Boot可限制在32KiB。当前 RAM 数值来自参考工程，尚不能当作本机栈深/恢复工作区验收。

核验Map的实际Thumb代码符号：sign_verify、六个yp_boot入口、bootloader_wdt_refresh均存在；ble_stack_init、bsp_log_init、bypass_sign_check、bypass_sign_write没有保留为代码符号。核心快照与生产源SHA256一致，Objects无HEX。

容量式：`1048576 - 2×479232 - 36864(Boot) - 8192(SCA) - 8192(NVDS) - 4096(交换) - 8192(Boot日志) - 8192(仲裁记录) = 16384`。

这是尚未分配地址的预算。16KiB须容纳后续真实后端/包身份/保护检查及其他未盘点保留项，不是已批准的自由用户区。

另核对当前SDK中DFU_SIGN_LEN=856、DFU_IMAGE_INFO_LEN=48：按当前应用477536字节再加这两项保守估算为478440字节，小于479232槽位，但只剩792字节。实际签名包结构、对齐和字段是否包含在镜像内仍须以正式打包器产物验证，不能仅据此批准包格式；后续应用增长很容易跨扇区。

## 下一阶段与保护边界

1. 盘点用户持久区及所有写擦入口，建立正式地址白名单；当前实机NVDS为0x002FE000–0x00300000，必须保持。默认拒绝触及SCA、Boot、NVDS及其他用户区。
2. 在独立Boot工程中接入真实读取/扇区擦写/读回校验、签名身份和布局兼容性检查、看门狗服务。逐个完成后重测体积；探针不能代替这些后端。
3. 把事务恢复、试运行计数、健康确认、回退选择接入启动流程。独立Boot运行时必须能在A槽部分被替换时继续执行；不能把交换代码放在待擦应用区。
4. 单独设计首次迁移：当前应用起点0x00202000、参考Boot起点0x00204000以及示例DFU_INFO=0x00203000互相冲突，禁止直接下载本参考目标。更新启动入口的掉电保护尚未解决。
5. 后端及迁移通过主机故障注入后，才准备经授权的实机N→N+1、任意掉电、回退、最新用户数据保持验收。
