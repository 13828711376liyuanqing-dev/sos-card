# 姓名字库下发：工作总结与后续改善

SAM | 2026-11-02 | 读者：项目负责人、GR/CAT1/后台开发、测试 | 详细过程见 `2026-11-02_姓名字形平台推送_实现与测试记录.md`

## 一、一句话结论
> SAM | 2026-11-03：按用户决定**只用 JSON，不用 zip**（工具、终端均已去掉 zip）。


**平台 → CAT1 → GR → 电子纸** 的姓名字形下发已实现，并在实板上打通：后台生成 1 个文件 → 上传平台（OTA 同款文件名的 zip）→ 设备按地址下载、校验、全程保电 → 屏幕正确显示含生僻字的姓名"欧阳䶮𠮷"（四字本地字库均无，含扩展 A、B 区）。固件版本保持 1.5.8/b12，不升级。

## 二、整体怎么工作

```
后台：姓名字形生成器（网页）→ residentNameMsg JSON（只用 JSON）
平台：上传 JSON 拿到下载地址（带 md5=）→ MQTT 发 residentNameUrl {Url, Md5}
CAT1：[OTA_HOLD] 1 保电 → HTTP 下载到内存 → 校验 MD5 → 校验内容 → 逐行 BUS_EVT 发 GR
GR  ：RAM 暂存 → CRC 逐字校验 → 收齐才整批切换 → NAME_RES 回执 → LVGL 动态字体显示
CAT1：收到回执 → 回平台 residentNameReply → 3 s 后 [OTA_HOLD] 0 释放（OTA 进行中不释放）
```

- 每个字给 32px（主页）和 16px（低电页）两份点阵；1 位/像素，每行补齐字节，CRC-16 校验。
- 字形**只放 GR 内存**，不写 Flash；CAT1 也**不写文件系统**（OTA 空间本来就紧）。
- GR 重启丢字形后，会自动向 CAT1 要缺的字：CAT1 内存里有就直接补发，没有就向平台发 `residentNameNeed`。

## 五、过程中解决的问题

1. **字形格式**：板上字库是"每行按字节补齐"，不是连续位流；改用与字库同源的 `lv_font_conv`，做到逐字节一致。
2. **测试数据覆盖姓名**：同事代码 `TEST_DATA` 每次电池采样把姓名改回"张秀芳"；改为只在没有姓名时填。
3. **扩展区生僻字**：GR 原先只收 U+FFFF 以内，放宽到完整 Unicode。
4. **生僻字发淡**：后备宋体笔画细，自动加粗。
5. **海外网盘连不上**：4G 访问海外地址失败，改用平台存储（与 OTA 同一下载路径）。
6. **平台拒收 zip**：按 OTA 包文件名规则命名 `YP001_1.5.8---1.5.8_NAME.zip`。
7. **下载期间掉电**：照 OTA 加保电锁，且不会误撤 OTA 的保电。
8. **回执丢失导致重试 3 次**：GR 回执早于 CAT1 开始等待；改为按编号存回执。
