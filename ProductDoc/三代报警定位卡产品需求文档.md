## 1. 产品概述

### 1.1 产品定位

基于**蓝牙 + Cat.1** 的智能硬件，核心功能为**紧急报警**，主打**高续航、低重量**，面向康养/养老社区住户。

### 1.2 目标用户

泰康之家等养老社区居民（以老年人为主）。

### 1.3 核心指标

| 指标   | 目标                                                    |
| ---- | ----------------------------------------------------- |
| 续航   | ≥ 7 天（按每日 8h 工作 + 16h 休眠占空比评估）                        |
| 重量   | 45–48g（保留全部核心功能下的现实区间；最终可接受阈值待 8/19 配重调研敲定）           |
| 语音   | Cat.1 数据通道 VoIP（非电路域语音）；服务器与账号由泰康之家联络中心提供             |
| NFC  | 无源 NFC，复旦微电子 CPU 卡（型号 1208-10），支持园区餐饮消费与门禁            |
| 防水   | IP68                                                  |
| 成本   | ≤ 200 元（整机成本）                                         |
| 尺寸   | ≤ 105 × 60 × 7 mm（长 × 宽 × 厚）；为尺寸底线，实际产品不得超过           |
| 屏幕   | 27 × 27 mm 正方形墨水屏（对角线约 1.5″），字大清晰可读（替代打印照片，显示姓名/房间号等） |
| 量产节点 | 2026-11-20                                            |

## 2. 核心使用场景

1. **突发状况**：用户触发报警，设备通过 VoIP 拨打急救电话并上报位置（**SOS 取位：有蓝牙Beacon 报 Beacon；无 Beacon 则 LBS、WIFI、GPS 各自扫描各自、完成一路传一路；均无则报空位置**）。
2. **日常活动**：三轴传感器检测到运动时启动蓝牙扫描（1min/次，第 1 次失锁保持 1min、第 2 次起递增 2/3/4/5 min、最长 5min/次，恢复扫描到时回 1min），仅用蓝牙定位，位置每累计 60 次扫描上报一次（或休眠前上报）。
3. **静止休息**：无运动满 5 分钟，Cat.1 硬断电休眠（关机前上报最后位置），蓝牙进入低功耗，由三轴传感器等待唤醒。
4. **园区通行/消费**：无源 NFC 刷卡用于餐饮消费与门禁出入，要求刷卡灵敏。

## 3. 功能需求

### 3.1 紧急报警

| 编号    | 功能        | 需求描述                                                                                                                                                                                                                                                                                                                                                                                        | 优先级 |
| ----- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| F-001 | 双键报警      | **左、右键同时长按**（建议 ≥ 2s）触发报警，降低误报；**静止态（睡眠）按键亦可触发**：双键挂蓝牙侧，静止态按键时蓝牙先给 Cat.1 上电联网、再优先上报报警信息（`sosMsg`+VoIP+`sosLocationMsg`），报警处理完再走上线流程，随后进入活动态。                                                                                                                                                                                                                                                | 高   |
| F-002 | VoIP 急救呼叫 | 报警时通过 Cat.1 数据通道发起 **VoIP 双向通话**，拨打**单个呼出白名单号码**（`CallOut`，由泰康之家联络中心负责调度响应，端侧仅拨打该号码）；建议配置**呼入白名单**（`CallInList`，最多 5 个）以规避骚扰电话——呼出号码与呼入白名单均由平台经 `phoneBindMsg` 绑定下发；**呼入白名单缺配（`CallInList` 为空）时，接受所有来电**（不限制呼入）。语音通道**默认使用 VoIP**，VoLTE 作为保留能力并存（二者运行时互斥，详见「语音通道（默认 VoIP，VoLTE 保留）」约束）。采用**普通通话流程，单次拨打即完成，不主动重拨**（无论对端是否接听）。报警保持“进行中”直至**用户长按按键取消或平台取消**，不因通话未接通而结束。VoIP 服务器与账号由泰康之家联络中心提供。 | 高   |
| F-003 | 位置上报      | 报警时上报位置，**SOS 取位规则**：**有蓝牙Beacon 即只报 Beacon；无 Beacon 则 LBS、WIFI、GPS 各自扫描各自、扫描完成一路就传输一路；三路均无结果则只上报空位置**。WiFi 定位已正式启用（进入定位链）。位置数据格式以协议文档为准（协议 V1.3 PositionType：Bluetooth / 0=LBS / 1=WIFI / 2=GPS / 3=空位置）。 | 高   |
| F-004 | 报警指示      | 通过**语音播报、屏幕显示**提示报警已触发与取消；**不配置蜂鸣器、指示灯与马达震动**（8/14 会议决议：整机移除振动功能以减重）。                                                                                                                                                                                                                                                                                                                       | 中   |

> 说明：定位顺序见第 5 章「定位顺序」约束（上线 / 下线 / 寻人按 Beacon → WIFI → LBS → GPS → 空位置；SOS 按 Beacon 短路 / 三路各自扫描完成一路传一路规则）。VoIP 支持双向通话与双向挂断；设备侧通话过程中**长按按键并有语音提示**即可挂断。报警采用**左、右键同时长按**触发，兼顾防误报与老年人可操作性。

### 3.2 日常蓝牙定位与监测

| 编号    | 功能     | 需求描述                                                                                                                                                                                                                                                                                                                                                                                                                       | 优先级 |
| ----- | ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| F-005 | 运动触发扫描 | 三轴传感器检测到运动时，启动蓝牙 beacon 扫描，**扫描对象为园区现有 Seekcy iBeacon（UUID `1918FC80-B111-3441-A9AC-B1001C2FE510`）**。                                                                                                                                                                                                                                                                                                                      | 高   |
| F-006 | 扫描频率策略 | 默认 **1 分钟扫描 1 次**；**失锁升级**：第 1 次扫描不到 beacon 时扫描间隔保持 1 分钟（基线），第 2 次起依次递增 1 分钟（2 / 3 / 4 / 5 分钟），**最长 5 分钟 1 次**；**恢复规则**：在 5 分钟间隔下再次扫描到 beacon，立即恢复 1 分钟扫描 1 次。                                                                                                                                                                                                                                                             | 高   |
| F-007 | 日常定位源  | 日常情况下**仅使用蓝牙定位**，不使用 WIFI、LBS 与 GPS。                                                                                                                                                                                                                                                                                                                                                                                       | 高   |
| F-008 | 位置上报   | 将蓝牙扫描到的位置（最近 beacon）上报平台：**蓝牙扫描累计达到 60 次（≈60 min）**&#x5373;上报一次（上报后计数器清零）；**Cat.1 硬断电休眠前**也须上报：若缓存 beacon 未满 60 次，先用 `periodicMsg` 清空缓存 beacon，再发 `offlineMsg`（电量+位置）完成全量 flush。每次上报均携带当前电量信息（仅在活动态执行；静止态 Cat.1 关机不主动上报，平台查询时采用关机前最后位置）。**本代不启用经 HTTP 历史轨迹接口单独上传 beacon 文件的方式（该接口保留为协议兼容占位，本代未启用），蓝牙 beacon 统一由 `periodicMsg` 周期性上报携带 Beacon[]（协议 `BeaconUploadMethod` / `BeaconUploadAddr` 参数与本代 HTTP 历史轨迹接口保留为历史兼容占位）**。 | 中   |

> 说明：日常定位仅用于位置跟踪；WIFI / LBS / GPS 不用于日常（避免日常功耗与对 4G 的干扰）。上线 / 下线 / 一键寻人取位顺序：蓝牙Beacon → WIFI → LBS → GPS → 空位置；SOS 报警取位：有 Beacon 报 Beacon，无 Beacon 则 LBS、WIFI、GPS 各自扫描各自、完成一路传一路，均无则报空位置。

| F-033 | 消息确认与超时 | 平台与设备间消息的确认规则：① **需平台确认的消息**：仅 **报警类**（`sosMsg`→`sosReplyMsg`、`sosLocationMsg`→`sosLocationReplyMsg`）与 **找人类**（`personSearchMsg` 触发设备上报位置、平台对该次上报确认）需平台应用层确认；设备发出后 **60s 内未收到确认则重发，最多重发 3 次**（含首报共 4 次），仍失败则本地记录、下次上线补报。② **无需平台确认的消息**：其余所有消息（含 `paraSetMsg`/`phoneBindMsg`/`otaMsg`/`rebootMsg` 等下行指令及其回执、`onlineMsg`/`offlineMsg`/`periodicMsg`/`lowBatteryMsg`/`logReplyMsg` 等纯上行通知）**均不要求平台应用层确认**；纯上行通知依赖 **MQTT QoS1** 可靠投递，断连缓存、恢复后补报。 | 高   |

> 说明：平台协议部分仅用于功能梳理参照，三代实际接入平台以最终方案为准。OTA 相关参数（如 auto-OTA）亦属平台可远程配置项，详见 3.8。

### 3.8 OTA 远程升级

| 编号    | 功能      | 需求描述                                                                                                                                                                                                            | 优先级 |
| ----- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- |
| F-029 | 版本与参数上报 | 设备每次上线通过 `onlineMsg` 主动上报当前版本号、电量、位置（**不携带 auto-OTA 字段**；auto-OTA 为平台可远程配置项，默认 1，由平台经 `paraSetMsg` 下发，详见软件技术文档 5.6）；**平台每次上线都主动下发 `paraSetMsg(CmdType=0 查)` 查询参数**，设备回 `paraSetReplyMsg`，平台据结果决策是否更新参数 / OTA。   | 高   |
| F-030 | 平台主动推送  | 平台依据 auto-OTA 决策：=1（默认）时主动检查版本，若存在可升级新版本则推送 OTA 命令（含当前版本、目标版本、下载地址、Md5）；=0 时不做检查、不主动推送；**平台每次上线经 `paraSetMsg(查)` 后确认是否需更新参数 / OTA**。命令**不指定升级时机与电量门槛**，由设备自调度执行。                                                | 高   |
| F-031 | 无感自调度升级 | 设备收到 OTA 命令后将目标版本写入 NV 持久化并回执；在**活动态空闲时后台预置**（蓝牙镜像写 A/B 非活跃分区、Cat.1 镜像写常规分区，报警 / VoIP / 定位全程可用，支持断点续传），并在**进入稳定静止态、且设备处于充电中、且电量 ≥ 端侧固定阈值 70%（非平台可配）、且非报警进行中**时执行"翻转重启"数秒提交；蓝牙支持 A/B 双分区、签名校验，失败可回滚拒绝成砖；全程不阻塞用户。 | 高   |
| F-032 | 版本校验与回执 | 若目标版本 ≤ 当前版本则直接清除 NV、不升级；升级成功上报新版本并清除 NV；失败经 `otaResultMsg` 回报，平台自动重推，无需人工介入。                                                                                                                                   | 高   |

> 说明：升级的"下载 / 写盘"与"切换生效"彻底分离——下载写盘在活动态完成（蓝牙写 A/B 非活跃分区、Cat.1 写常规分区），仅"翻转重启"为短暂不可用窗口、且约束在**静止态**（三轴无数据、设备已进入休眠、无人使用，重启对用户完全无感，而非"小心翼翼避开用户"）；**静止态不再为 OTA 引入周期性 RTC 唤醒**，保持 0 电流纯三轴唤醒睡眠，对续航无额外影响。执行细节、整包下载与蓝牙 DFU 流程见软件技术文档 4.3。

### 4.2 环境适应性

- 工作温度：-10℃ ~ 55℃
- 外形尺寸：≤ 105 × 60 × 7 mm（长 × 宽 × 厚）；为尺寸底线，实际产品不得超过该上限
- 防水等级：IP68（整机不可拆卸一体化密封工艺）
- 不做佩戴监测：因整机不可拆卸密封设计，不引入佩戴 / 离体检测功能。
- 跌落：1.2m 自由跌落正常工作
- 按键寿命：≥ 10 万次

### 4.3 可靠性与安全


- 设备与平台之间敏感数据经 **mqtts（MQTT over TLS）** 提供传输层加密（链路已加密，无需应用层加密）。
- 支持 OTA 远程升级，升级包需签名校验；**蓝牙固件采用 A/B 双分区**（升级失败或断电可回滚，拒绝成砖），**Cat.1 固件采用常规升级（单分区、重启生效、失败重推，不采用 A/B）**；采用**无感自调度升级**——活动态后台预置、安全静止窗"翻转重启"提交，详见 3.8。
- 网络异常、断连后自动重连并补报关键数据。

## 5. 关键设计约束

- **定位顺序（2026-10-15 定义，WiFi 正式启用）**：上线 / 下线 / 一键寻人取位顺序为 **蓝牙Beacon → WIFI → LBS → GPS → 空位置**（依次尝试，取到即用）；SOS 报警取位为"有蓝牙Beacon 报 Beacon；无 Beacon 则 LBS、WIFI、GPS **各自扫描各自、扫描完成一路就传输一路**；三路均无则报空位置"。WiFi 扫描与数据传输的时分安排：联调时若确认影响数据传输，扫描时可考虑暂停数据传输，避免数据上传丢失（以联调结论为准）。位置数据格式以协议文档为准（协议 V1.3 已定义 LBS/WIFI/GPS/空位置数据格式，PositionType：Bluetooth / 0=LBS / 1=WIFI / 2=GPS / 3=空位置）。
- **语音走 VoIP**：由 Cat.1 模组内置 VoIP 能力实现（底层信令/编解码由模组完成），设备侧仅需配置服务器地址、账号、密码（由平台下发），不使用电路域语音。
- **整机不可拆卸**：为达到 IP68 防水，采用整机一体化密封、不可拆卸设计；因此不引入佩戴 / 离体检测功能。
- **外形尺寸底线**：整机尺寸上限为 **105 × 60 × 7 mm**（长 × 宽 × 厚），为不可超出的硬性底线；实际产品须控制在该范围内（长宽可在不超上限前提下尽量压缩以辅助减重），与重量 / 续航目标共同约束结构设计与电池选型。
- **双按键防误报**：报警采用左、右键同时长按触发，兼顾防误报与老年人可操作性。
- **语音通道（默认 VoIP，VoLTE 保留）**：Cat.1 模组可同时具备 VoIP 与 VoLTE 两种语音能力，但二者**互斥**——同一时刻仅一种语音通道生效，不可同时使用；**默认启用 VoIP**，VoLTE 作为保留能力并存，运行时只启用其一；报警 / 通话统一经当前生效的语音通道（默认 VoIP）。
- **报警指示不含蜂鸣器 / 指示灯 / 马达震动**：报警与状态提示仅通过**语音播报与屏幕显示**实现（8/14 会议决议移除整机振动功能以减重），以简化结构与降低功耗。
- **无源 NFC**：采用复旦微电子 CPU 卡（1208-10），刷卡不消耗设备电池；NFC 为被动元件，**与 BLE/Cat.1 无事件关联**（刷卡不触发设备软件逻辑）；NFC 位置需避开天线布局区域，机身标注刷卡区域。
- **双面 PCB 布局**：厚度放宽至 7mm 后采用双面布板，元器件不再局限于单面。
- **电池 500mAh**：采用 500mAh 电池，以支撑 ≥ 7 天续航目标。
- **喇叭选型方向**：优先沿用 1511 型小功率喇叭（二代样机验证不破音音量，匹配老年听觉），音量不达标时评估 2512 型大喇叭备选（同步核算重量与空间）。
- **挂绳双孔设计**：主挂绳孔 + 居中副挂绳孔（副孔落地可行性待结构端评估）。
- **双状态机**：活动态（Cat.1 保持供电、运行于**低功耗模式**——已注册网络、具备收发能力；需传输数据/发起 VoIP 时自动切**常规模式**，传完自动回低功耗模式）/ 静止态（Cat.1 **硬断电、0 电流**、蓝牙低功耗），由三轴运动**或按键事件**驱动唤醒（静止态按键同样唤醒进入活动态），是实现高续航的核心机制。静止态真断电保持不变。
- **蓝牙 SoC 主控**：选用**汇顶 GR5512（Goodix）BLE SoC** 作为应用主控（自带 MCU，常驻低功耗），三轴加速度传感器、墨水屏、双按键、无源 NFC 均挂载其侧；Cat.1 为受控从机，由蓝牙经 GPIO→MOSFET **真断电**（大部分时间 0 电流）。此拓扑是"高续航"的核心落地方式。
- **语音播报载体**：报警语音提示由 **Cat.1 侧喇叭播放**，蓝牙 SoC 仅下发播放指令并负责屏幕显示（屏在蓝牙侧、语音在 Cat.1 侧，二者经串口协同）。
- **休眠寻人复用最后位置**：静止态下一键寻人直接采用关机前上报的最后位置，避免频繁唤醒 Cat.1；关机前取位顺序为 **蓝牙Beacon → WIFI → LBS → GPS → 空位置**（依次尝试）。

## 6. 待确认事项

> 截至 V0.2，8/14 会议已决议项均已落位正文。以下为会议明确待 8/19（下周三）会议敲定的开放项：

1. **最终重量阈值**：当前写 45–48g 区间，最终可接受重量阈值待 40/45/50g 三种配重基模的园区试戴调研结果敲定。
2. **屏幕是否上移**：初始方案屏幕置于机身下部，后续评估上移至电池上方（两键中间区域空间）的可行性，待结构端验证。
3. **副挂绳孔落地**：居中副挂绳孔的实际开孔可行性待结构端评估。
4. **墨水屏供货与更小尺寸**：待供应商确认 27×27mm 墨水屏供货稳定性；商务端评估更小尺寸的可行性及成本影响。
5. **喇叭选型标准依据**：需确定音量选型的标准依据（避免主观判断），1511 / 2512 选型以验证结论为准。
6. **商务变更流程**：本次尺寸/硬件调整属正式需求变更，商务端需启动成本评估与补充协议（不影响硬件规格，记录备查）。
7. **墨水屏资源（字库 / 图片）存储策略待确认**：墨水屏显示所需的字库与界面图片，**建议优先考虑本地固化存储**（节省运行时网络开销、离线可用）；同时需确认是否支持经网络下发（平台配置 / OTA 资源包）以远端更新样式——本地固化与网络下发的可行性及优先级待评估。
