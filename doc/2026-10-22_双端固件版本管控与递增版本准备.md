## 日常操作

统一从`OTA_Packager/启动OTA打包工具.bat`打开`YP001OtaPackager_Versioned.exe`。

1. 初次填源版本1.0.0、目标1.0.1，点击 **准备目标版本固件（更新两端版本、编译GR、生成CAT1）**。
2. 该版本已准备好时，明确复用冻结文件并自动选中HEX与SOTA；不覆盖旧目录、不暗中把当前源码变化混入相同版本。
3. 新目标如1.0.2：同步更新两端源码版本和GR构建号，独立编译两份GR，再生成CAT1原生包；通常耗时数分钟，不烧录。
4. 读取实际设备空间后，点击签名归档按钮。实际两端版本都必须对应整机目标，否则拒绝。
5. 修改业务代码后要提升版本。只有源码版本变更不代表HEX已更新；旧HEX缺少标记或仍是旧版会被拒绝。

准备新版本需要完整工程、SDK1.0.4、已验证的Keil 6配置和匹配Luatools；仅打包他人提供的受控HEX/SOTA不需要Keil。CLI辅助程序缺失时由发布脚本用系统.NET编译器生成，不依赖个人Python或已有logs缓存。

命令行等价操作：

```powershell
# 一次完成版本设置、两份GR编译、CAT1生成和版本目录冻结
& D:\CODEX\sos-card\tools\ota\Build-VersionedRelease.ps1 -Version 1.0.2

# 只更新源码版本；之后必须重新编译两份GR和生成CAT1，不能用旧HEX
& D:\CODEX\sos-card\tools\ota\Set-FirmwareVersion.ps1 -Version 1.0.2
```

已有版本目录不覆盖。版本回退、同版更换构建号、版本提高但构建号未提高都被拒绝。GR构建号限1～65535，不能回绕。整机版本支持规范数字，受控组件格式为三段三位；1.0.1对应001.000.001，1.4对应001.004.000。

## 初始化与实板测试顺序

首次应先部署基线并读取实际版本，再发目标版测试，不能直接把两端烧成目标版后声称N→N+1通过。

- GR基线：`firmware_releases/1.0.0/GR5526/YP001_GR5526.hex`；同目录AXF是对应符号文件。交付副本在GR5526_delivery。
- CAT1基线USB脚本集合：`firmware_releases/1.0.0/CAT1/luatools_precompiled`，35文件，总原始文件字节398981；main.lua保留文本供Luatools识别版本，其余脚本保留厂商编译器产生的字节码，音频不变。使用已匹配的V2052 Air780EGH_113底包，保留FS/KV。
- GR通过`fw_version`读取，预期包含`YP001_FW|GR5526|001.000.000|1|END product=1.0.0`。
- CAT1通过现有`cat_at AT_INFO`读取应用VERSION，应为001.000.000。其旧输出名“LuatOS Ver”实际来自应用VERSION，不是V2052底包版本或GR SDK1.0.4。
- 目标升级成功后分别应为001.000.001，GR app_numeric=2，并验证业务和用户数据。

本轮未重新读取设备空间；签名测试使用此前用户截图中的495616作为主机输入样本。实际提交前须重查电源、空间、版本、充电、≥70%、静止和无报警/通话等条件。

**递增版本是升级的必要条件，不等于整条安装链已具备。** 当前GR `ota_provisioned`仍为false，CAT1平台resolve/validate/activate等适配仍未启用；没有为演示触发升级而返回假成功。设备可信公钥/验签、持久互斥、GR Boot/布局及安装/回退能力仍须继续完成并验收。现有签名包仍device_installable=false。

## 实现文件与行为

| 文件/函数 | 修改前 | 修改后 |
|---|---|---|
| firmware_version.json | 无统一版本源 | 当前源版本、组件版本、GR构建号；编译状态与设备未知状态分开 |
| 两份Src/config/yp001_fw_version.h | 无 | 统一规范版本、整机版本、构建号和嵌入镜像的身份标记 |
| 两份custom_config.h | VERSION固定1 | 从受控构建号派生；保持Goodix 16位字段，禁止与受控值分叉 |
| 两份user_periph_setup.c / fw_version | 仅打印整数 | 打印实际编译版本、整机版本、构建号、provisioned状态；标记保留在HEX/BIN中 |
| Air780EGH/main.lua | 手工固定VERSION | VERSION/PRODUCT_VERSION/FW_RELEASE_BUILD由脚本一起维护；AT_INFO和上线消息继续读取实际VERSION |
| Set-FirmwareVersion.ps1 | 无 | 主/交付差异检查、同步版本、保留修改前快照、拒绝回退和构建号异常 |
| Build-VersionedRelease.ps1 | 无 | 两份Keil独立编译、镜像身份/容量检查、CAT1生成、冻结目录、明确未烧录 |
| FirmwareIdentity.cs / PackCore.cs | 可仅修改整机目标标签 | 从GR镜像和CAT生成文件取得实际版本；两端必须映射到目标 |
| BundleSigning.cs | schema4，无GR版本约束 | schema5签名绑定两端实际版本和GR构建号；读回复核GR镜像身份 |
| MainForm.cs | 手工选文件 | 新增准备目标固件按钮，已有目录明确复用；阻止并发版本准备/生成/查询 |

保持SDK唯一入口1.0.4；不使用旧SDK或旧cat_1。未修改GPIO、电源硬件行为、Flash布局、擦除算法、Keil下载配置或用户存储。GUI版本准备不调用烧录命令。
