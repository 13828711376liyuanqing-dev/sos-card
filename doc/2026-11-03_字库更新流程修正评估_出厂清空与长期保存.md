# 字库更新流程修正评估：出厂清空、长期保存、英文名、临时广播页

SAM | 2026-11-03 | 读者：项目负责人、GR/CAT1 开发、平台 | 前提：`2026-11-02_姓名字库下发_工作总结与后续改善.md`、`2026-11-02_字体整体规划方案.md`

## 一、结论

1. **出厂只清"姓名"，不清"全部中文字库"**。设备里的中文字分两类，性质不同：
   - **固定显示字**（"当前电量低""正在呼叫"、星期、房号/园区用字等）是**固件的一部分**，和程序一起烧在 GR 程序区，出厂、OTA 都不应该也不需要清；清掉了界面就会显示方框。
   - **姓名字形**是平台推送的**用户数据**，跟着居民走：出厂清空、换人时更新。
2. **姓名字形要改成长期保存**（现在只在内存里，重启就丢）。空间很小：一个姓名最多约 **1.5 KB**，实测"欧阳䶮𠮷"四个字约 0.6 KB。
3. **只有两种情况清空**：收到**恢复出厂设置**，或收到平台的**清空姓名**命令。其余时候（重启、断电、断网、OTA、没收到新命令）一律保留，不能掉字。
4. **英文字库已有**：每个字号都带全部 95 个英文字母、数字和符号。英文名不用推送就能显示；但现在的"最多 8 个字"限制对英文名太紧，需要调整（见第五节）。
5. **临时广播页**：内容和字形都只放内存，**不保存**，显示完或重启即丢，不能占用、也不能覆盖姓名的长期存储。

## 二、空间评估

### 2.1 姓名（需要长期保存）

| 项 | 大小 | 说明 |
|---|---|---|
| 单字 32px 点阵 | ≤ 132 B | 最大 32 宽 × 33 高，每行补齐 4 字节 |
| 单字 16px 点阵 | ≤ 34 B | 最大 16 × 17，每行 2 字节 |
| 每个字形的描述 | 约 12 B | 码点、宽高、偏移、前进宽度、长度 |
| **单字合计** | **最坏约 190 B，实测平均约 144 B** | "欧阳䶮𠮷"点阵：32px 共 460 B、16px 共 114 B |
| 8 个字（上限） | 最坏约 **1.5 KB** | |
| 姓名/房号/园区文字 | 224 B | **现在已经在 NVDS 里长期保存** |
| 版本号、校验、标记 | 约 16 B | Seq、整体 CRC、有效标记 |
| **一个居民合计** | **约 1.7 KB（最坏）** | 实测四字姓名约 0.8 KB |

### 2.2 固定显示字（固件自带，不清、不推送）

| 方案 | 大小 | 说明 |
|---|---|---|
| 现状 | 约 76.5 KB | 16/24/28/32/40 五个字号，每个都带同一套 185 个汉字（多为常见姓名用字） |
| 按字体规划精简后 | 约 22 KB | 每个字号只装它要显示的字（界面文字、房号、园区、英文） |

固定字在 GR **程序区**，跟固件一起升级，不占数据存储。

### 2.3 两种出厂清空方式对比

| | 只清姓名（推荐） | 清全部中文字库 |
|---|---|---|
| 要清的数据 | 约 1.7 KB（数据区） | 约 22~76 KB（程序区里的字库） |
| 能不能做 | 能，清数据区几个记录 | 实际上不可行：固定字是程序的一部分，单独擦会破坏固件签名校验；要整机重烧 |
| 清完后界面 | 正常，姓名显示"--"等推送 | 所有中文提示变方框，直到…没有办法补，因为固定字不走推送 |
| 结论 | **采用** | 不采用 |

## 三、长期保存存在哪里

GR 现在能长期保存数据的地方是 **NVDS**（SDK 的参数存储区，地址 0x2FE000，1 个扇区 4 KB + 1 个回收扇区）。它目前存着 IMEI 和居民文字信息，OTA 和有线烧录**都不动它**（实测烧录读回"NVDS 未变"），符合"用户数据不得被 OTA 清除"的要求。

| 方案 | 优点 | 风险/代价 |
|---|---|---|
| **A. 放 NVDS（推荐先评估）** | 现成、OTA 不动、已有读写代码 | 4 KB 和蓝牙绑定等共用，1.7 KB 占比不小；需要先**只读审计**现在 NVDS 实际用量；每个记录不宜过大，按字形分成多条存 |
| B. 单独划一个 Flash 扇区 | 空间独立 | 必须先做整片 Flash 布局审计并经你批准（AGENTS 红线：不得占用未知区域、不得移动链接地址）；OTA/Boot 必须确认不碰它 |

写入规则（两种方案都要）：
- **先收齐、校验通过，再写**；写新数据前旧数据保留，写完校验成功才切换"有效"标记，断电不会留下半份数据。
- 同一姓名重复下发（Seq 相同、内容相同）**不重复写**，减少擦写次数。
- 开机时读出、校验 CRC，通过才使用；失败就当没有（姓名显示"--"并向 CAT1 要）。

## 四、流程修正后的状态表

| 事件 | 姓名文字 | 姓名字形 | 固定字 | 临时广播字形 |
|---|---|---|---|---|
| 出厂（首次） | 空 | 空 | 有（固件自带） | 空 |
| 收到 `residentNameMsg` 并校验通过 | 写入 | **写入长期存储** | 不变 | 不变 |
| 重启 / 断电 / 断网 / 没收到新命令 | 保留 | **保留（不掉字）** | 不变 | 丢弃 |
| GR 有线烧录 / 整机 OTA | 保留 | 保留 | 随固件更新 | 丢弃 |
| 收到**清空姓名**命令 | 清 | 清 | 不变 | 不变 |
| 收到**恢复出厂设置** | 清 | 清 | 不变 | 清 |
| 收到临时广播 | 不变 | 不变 | 不变 | 只放内存，显示完/超时/重启即丢 |

现在的实现与此表的差别：姓名字形只在内存（要改成长期保存）；没有"清空"命令；没有恢复出厂设置的处理（工程里目前没有出厂设置功能，GR 和 CAT1 都没找到）；没有临时广播页。

## 五、英文名

- **字库**：16/24/28/32/40 每个字号都含 95 个 ASCII 字符（大小写字母、数字、空格和常用符号）。规划精简后仍保留。英文名**不需要推送字形**，生成工具也自动跳过英文字符。
- **要调整的限制**：
  - 现在"姓名最多 8 个字"按字符数算，英文名（如 `Elizabeth Smith`，15 个字符）会被工具和终端拒绝。应改为：**需要推送字形的汉字 ≤ 8 个，姓名总长 ≤ 63 字节**。
  - **显示宽度**：主页姓名 32px，英文字母平均约 16 像素宽，200 像素宽的屏一行约放 11~12 个字母。超长英文名需要定规则：自动换成 24px/16px 显示、两行显示，或截断。需要你定。
- 中英混合（如 `李 Anna`）：汉字推送、英文用自带字，可以混排。

## 六、临时广播页

- 平台下发一条带内容的广播（字段需要和平台定，例如 `broadcastMsg`：文字、显示时长、需要的字形）。
- 字形单独放一块**内存缓存**，和姓名的缓存、长期存储完全分开；显示时长到、被新广播替换、或重启后丢弃。
- 字号建议 24px（标题）+ 16px（正文）；内存按 40 个汉字估算约 3~4 KB。
- 优先级：报警/通话页面高于广播页；广播页不影响姓名。
- 这是新页面，需要做界面设计（GUI Guider 或代码），并确认文字长度上限、是否要声音提醒。

## 七、需要改的地方（工作量估计）

| 部分 | 改动 | 估计 |
|---|---|---|
| GR | 姓名字形长期保存（写、读、校验、切换）；清空命令；出厂清空入口；临时广播缓存和页面 | 2~3 天（不含广播页界面设计） |
| CAT1 | 转发"清空姓名"和"临时广播"；英文名长度规则 | 0.5~1 天 |

| 平台 | 清空命令、广播消息、出厂设置的下发 | 平台侧 |
| 验证 | 断电/重启/OTA 后不掉字；清空、出厂后确实清掉；广播重启即丢；NVDS 审计 | 1 天 + 实板 |

## 八、需要你决定的

1. **出厂只清姓名、固定字随固件不清**，是否同意？
2. 长期保存先按**方案 A（NVDS）**做只读审计，看实际剩余空间再定，是否同意？
3. "恢复出厂设置"从哪里触发：平台命令、按键组合，还是两者都要？清空范围除了姓名，还要清什么（IMEI 以外的绑定信息、通讯录等）？
