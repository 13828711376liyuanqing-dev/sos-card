YP001 整机 OTA 打包工具  YpOtaPack.exe  v1.1 使用说明
=======================================================

【2026-11-04 起】
  - CAT1 可用空间必须 ≥ GR 签名镜像 + 32768（16 KiB 保留 + 16 KiB OTA 过程增长余量），1.5.10 约 405736；不够就报错。
  - GR 签名镜像红线 393216，CAT1 包 .sota 红线 262144：超过就报错。CAT1 已用超过常驻预算 98304 会提醒。
  - 可用空间从 GR 调试串口读（cat_at OTA_FS），台架现在是 COM30，不再固定 COM26。
  - 红线数字在工具包根目录的 budget.json（所有工具和一键工具共用，只改这一个文件，并写明日期和原因）；没有这个文件时用内置的 2026-11-04 默认值。说明见 doc/2026-11-04_OTA空间红线_GR与CAT1大小管控.md。

一、这个工具做什么
  把已经签名的 GR5526 固件和 CAT1 脚本包，检查后打成可以上传 OTA 平台的整机升级包：
      YP001_<源版本>---<目标版本>_FIRST.zip       例如 YP001_1.5.2---1.5.3_FIRST.zip
  还负责：从 Air780EGH 源码生成 CAT1 包（含评审记录 review.json）、生成签名授权文件、验证已有的升级包、检查依赖的 Luatools 版本。
  运行环境：Windows 10/11，不用安装任何软件。整个文件夹要放在一起（YpOtaPack.exe、luatools 文件夹、contracts 文件夹）。
  私钥不在工具里：使用时由你选择私钥文件，工具只在临时目录放一份，用完覆写删除。

二、一次完整打包的顺序（以设备 1.5.2 → 升级到 1.5.3 为例）
  ① GR 固件：用“2_GR5526固件检查签名”工具得到 GR5526_1.5.3_b7_signed.bin。
  ② 把 Air780EGH\main.lua 改成目标版本：VERSION="001.005.003"、PRODUCT_VERSION="1.5.3"、FW_RELEASE_BUILD=7，
     OTA_TRIAL_SOURCE='1.5.2'、OTA_TRIAL_TARGET='1.5.3'，OTA_TRIAL_MD5 保持全零。
  ③ 本工具：选私钥文件、工作文件夹，点“① 生成CAT1包”。
  ④ 勾选两个确认项，填源版本，点“② 生成授权文件”。
  ⑤ 填 CAT1 可用空间，点“③ 检查并打包” → 得到升级包 zip，记下报告里的“平台整包 MD5”。
  ⑥ 上传平台，用 MD5 核对；把这个 MD5 冻结进给设备刷的“接收端”（见“1_CAT1刷机目录生成”的说明）。

三、窗口里每一项怎么选
  ┌ 私钥文件 (.key)
  │  怎么选：点“选择…”，选私钥文件本身（不用选公钥，工具从私钥里自动导出公钥）。
  │  例子：  D:\keys\OTA_TEST_PRIVATE.key
  │  作用：  “② 生成授权文件”“③ 检查并打包”用私钥签名（授权文件和整机包清单都由它签）；公钥用来验证 GR 镜像、授权文件和生成后的升级包，
  │          它的指纹写进升级包。设备只信任它预置的那把公钥，选错了密钥，设备会拒绝这个包。
  │          “④ 验证压缩包”只用从私钥导出的公钥部分。选到不是私钥的文件会提示“私钥文件无效”。
  │
  ├ 工作文件夹（生成的文件都放这里）
  │  怎么选：选一个文件夹（每次升级用一个新的最好）。
  │  例子：  D:\out\ota_1.5.3
  │  作用：  所有步骤的生成物都放在这里，后面的步骤自动到这里找，不用再一个个选：
  │            ① 生成 CAT1_…sota、同名 .sota.json、review.json
  │            ② 生成 ota_authorization.json
  │            ③ 生成升级包 YP001_1.5.2---1.5.3_FIRST.zip
  │          这里面同时只能有一个 .sota（有两个会报错让你清理），避免打包时用错了文件。
  │
  ├ GR 签名镜像 (.bin 或 .hex)
  │  例子：  D:\out\gr_1.5.3\GR5526_1.5.3_b7_signed.bin（“2_GR5526固件检查签名”的输出）
  │  作用：  整机包里的 GR 部分；目标版本由这个固件里的版本标记决定（这里是 1.5.3）。检查：签名和合同有效、不超过 442368 字节槽。
  │          “② 生成授权文件”“③ 检查并打包”都用它。
  │  .hex：已签名的 HEX（如 GR5526_1.5.3_b7_signed.hex）也可以选，工具先按地址还原成和 .bin 完全相同的内容再检查打包，结果一样；
  │          未签名的编译产物（YP001_GR5526.hex）不行，要先用“2_GR5526固件检查签名”签名。
  │
  ├ CAT1 源码目录
  │  例子：  D:\CODEX\sos-card\Air780EGH
  │  作用：  只用于“① 生成CAT1包”。main.lua 的 PRODUCT_VERSION 必须等于 OTA_TRIAL_TARGET（先改成目标版本），否则拒绝。
  │          工具会算出所有源文件的指纹写进 review.json，把 review 的 sha256 嵌入 main.lua，再编译、生成并读回校验 CAT1 包。
  │
  ├ 源版本（设备当前版本，如 1.5.2）
  │  例子：  1.5.2
  │  作用：  只用于“② 生成授权文件”：授权的升级范围是 “源版本 → 目标版本”，起点必须低于目标版本。
  │          “③ 打包”以授权文件里的范围为准，文件名里的版本也来自这里。
  │
  ├ 评审依据说明（可选）
  │  例子：  第二轮 1.5.1→1.5.2 实板通过；GR Boot 已实板验证
  │  作用：  一句话写进 review.json（① 时）和授权文件（② 时），作为评审留痕。可以留空，但建议写。
  │
  ├ CAT1 可用空间（字节）——只用于“③ 检查并打包”
  │  怎么读：板子接电脑，用串口 COM26（115200）发一次 cat_at OTA_FS（只读查询），读完直接填读到的值；也可以让开发工程师读了告诉你。
  │          不要估算，不要填门槛值（459656 = GR 槽 442368 + 签名预算 904 + 预留 16384）或随便填大：填门槛值检查一定通过，等于没检查。
  │  怎么填：用设备的真实读数，GR 命令行发 cat_at OTA_FS，读到 total（总块数）、used（已用块数）、block（块大小），
  │          可用字节 = (total − used) × block。例子：total=128 used=15 block=4096 → (128−15)×4096 = 462848。
  │  作用：  CAT1 要把整个 GR 镜像先存下来再送给 GR，需要“GR 镜像大小 + 16384 字节保留”的空闲空间；CAT1 包本身也要“包大小 + 16384”。
  │          这一项不够，工具就拒绝打包，避免设备上“空间不足、升级卡住”（10 月 29 日第二轮真实发生过：用清理前的 450560 字节
  │          就会被拒绝，当时手填了 495616 才没被发现）。余量不足 4 KiB 会给警告。
  │
  └ 已完成激活评审 / GR Boot 已实板验证（两个复选框）——只用于“② 生成授权文件”
     作用：  两项都必须由人确认勾上，否则拒绝生成授权文件。它们表示：已经评审过这次的激活流程；GR 的 Boot 切换/回滚已经在真实设备上
             验证过。勾选意味着你对这两件事负责，工具不能代替你判断。

  不用选的东西（工具自己处理）：布局合同/数据合同（用工具文件夹里的 contracts）；压缩包名前缀和后缀（固定 YP001 和 FIRST）；
  Luatools 的位置（只有点“⑤ 检查依赖版本”时才会问）；CAT1 包、review.json、授权文件（自动从工作文件夹里找）。

四、五个按钮
  ① 生成CAT1包    用：密钥无需；CAT1 源码目录、工作文件夹、评审依据说明。生成：CAT1 .sota 及 .sota.json、review.json。
                  工作文件夹里已有上次的生成物时，会问“要删除它们并重新生成吗？”（旧的授权文件也会失效）。
  ② 生成授权文件  用：私钥文件、GR 签名镜像、工作文件夹里的 .sota 和 review.json、源版本、两个确认框。生成：ota_authorization.json。
                  已有授权文件时会问“要用这次的结果替换它吗？”。
  ③ 检查并打包    用：私钥文件、GR 签名镜像、工作文件夹里的 .sota / review.json / 授权文件、CAT1 可用空间。生成：升级包 zip，
                  并列出包内每个文件的大小和 sha256，以及整包 MD5 / SHA-256（上传平台后用 MD5 核对）。
                  升级包永远不会被覆盖：同名包已存在时会报错，请先把旧包移走或换工作文件夹。
  ④ 验证压缩包    弹出窗口选一个 .zip（默认在工作文件夹里），用私钥导出的公钥验证；工作文件夹里有授权文件时一并使用。
                  不写文件，只检查签名、清单、组件摘要、版本和大小。
  ⑤ 检查依赖版本  显示本工具依赖的 Luatools 版本和自带文件的校验情况；然后弹出“选择文件夹”窗口：选已安装的 Luatools（例如 D:\Installers）
                  就和本机对比并列出需要升级的文件；点“取消”则只检查工具包自带的文件。

五、报告怎么看
  OK = 通过；WARN = 提醒；ERROR = 必须处理（不会生成升级包）。常见 ERROR 和含义：
    “授权必须明确确认…”                       没勾上两个确认框。
    “授权文件签名无效：内容被修改或不是这把密钥签的”   授权文件被改过，或用了别的公钥。重新生成授权文件。
    “授权文件里的 gr_payload_sha256 与实际输入文件不符”  授权是针对另一个 GR 镜像签的，换了镜像要重新授权。
    “GR 固件版本 … 与授权的目标版本不符”      选错了 GR 镜像。
    “CAT1 包里的 main.lua 没有嵌入这份 review.json 的 sha256”   CAT1 包不是用这份 review.json 生成的；重新点“① 生成CAT1包”。
    “5526暂存包+签名预算+保留空间超过CAT1可用文件区”   CAT1 可用空间不够，先清理设备（cat_at OTA_PRUNE 等）再读 OTA_FS。
    “工作文件夹里没有 CAT1 包” / “有 N 个 .sota”   先点 ①；或只保留这次要用的那一个 .sota。
    “同名升级包已存在，拒绝覆盖”               工作文件夹里已有这个包。
    “压缩包超过设备可处理的 2 MiB 上限”        包太大，设备处理不了。
    “目标版本必须高于源版本” / “main.lua 的 PRODUCT_VERSION 必须等于 OTA_TRIAL_TARGET”   版本没改对。

六、命令行（窗口里没有的选项只在这里）
  YpOtaPack.exe cat1   --source <Air780EGH源码目录> --out <目录> [--basis <说明>] [--host-check <文本>]... [--not-verified <文本>]... [--force]
  YpOtaPack.exe auth   --gr <签名bin> --cat <sota> --review <review.json> --source <源版本> --out <授权文件.json>
                       --private <私钥> [--public <公钥>] --reviewed --boot-verified [--basis <说明>] [--layout <json>] [--data <json>] [--force]
  YpOtaPack.exe pack   --gr <签名bin> --cat <sota> --review <review.json> --auth <授权文件> --free <字节> --out <目录>
                       --private <私钥> [--public <公钥>] [--prefix YP001] [--suffix FIRST] [--layout <json>] [--data <json>]
      --prefix/--suffix 改压缩包名的前缀和后缀（只能字母、数字、下划线和点，各不超过 48 个字符，不能含 ---）
  YpOtaPack.exe verify --zip <压缩包> --public <公钥> [--auth <授权文件>]
  YpOtaPack.exe --deps [--luatools <已安装的Luatools目录>]     检查依赖版本
  YpOtaPack.exe --version
  例子：YpOtaPack.exe pack --gr D:\out\gr\GR5526_1.5.3_b7_signed.bin --cat D:\out\cat1\CAT1_xxx.sota --review D:\out\cat1\review.json
        --auth D:\out\ota_authorization.json --free 462848 --out D:\out\pkg --private D:\keys\OTA_TEST_PRIVATE.key
  返回值：0 通过；1 有错误；2 参数错误。

七、检查项汇总（任何 ERROR 都不会生成升级包）
  文件与大小：GR 镜像签名/合同/槽大小；CAT1 包读回解压、脚本 ≤ 524288 字节；review.json ≤ 64 KiB 且内容合规；CAT1 空间；压缩包 ≤ 2 MiB。
  授权文件：签名公钥与私钥导出的公钥一致、签名有效；升级范围、GR 正文/CAT1 包/review.json 的 sha256 都与实际文件一致；两端版本与授权目标一致。
  CAT1 包来源：必须是本工具“① 生成CAT1包”的输出，不要在 Luatools 里另外导出，也不要用别人给的 .sota。原因：
     打包要核对同名的 .sota.json（生成记录，含每个文件的指纹），Luatools 导出的 .sota 没有这份记录，会被拒绝；
     本工具生成时把 review.json 的 sha256 嵌进了包里的 main.lua，打包据此确认“这个包就是按这份评审生成的”；
     授权文件绑定的是这个 .sota 的 sha256，换成别的来源的包授权就对不上。
     生成时工具内部调用自带的那份 Luatools 的 soc_tools.exe 制作升级包，所以电脑上不需要装或打开 Luatools。
     区别：.sota 用于 OTA 在线升级；刷机用的 USB_IMPORT 由“1_CAT1刷机目录生成”工具生成，两者用途不同。
  压缩包名：前缀、后缀字符和长度、不含 ---、目标高于源、不覆盖已有文件。
  打包后：读回包内每个文件的大小和 sha256，重新验证签名、清单、组件摘要。

八、依赖的 Luatools 版本
  窗口顶部灰色一行和每份报告的第一行写明：工具版本、Luatools 版本（v3.4.14，构建 2026.10.16）、脚本资源版本（v2026.10.13.20）、
  底包（V2052_Air780EGH_113）。本工具依赖 luatools 文件夹里的 8 个文件（luac、soc_tools、7z.exe、7z.dll 和 4 个厂商库源码）
  以及源码目录里 soc 文件夹中的底包。
  Luatools 升级后（它会自动更新脚本资源）：点“⑤ 检查依赖版本”，在弹出的窗口里选已安装的 Luatools 目录。
  结果里绿色的“提示”和“结论：不影响使用，不用升级”表示没有影响，什么都不用做；红色表示必须处理（只有工具包自带文件缺失或被改动才会出现，请重新拿完整的工具包，不要自己替换文件）。
  只有你决定让设备改用新的厂商库时才需要升级：由工具维护人用新库重新生成、实板验证后发新的工具包，在那之前继续使用现有的即可。

九、注意
  - 现在用的是本地测试密钥（OTA_TEST_*），不是产品发布密钥；正式密钥和算法需要与终端信任根一起确认。
  - 授权文件和升级包用同一把密钥签名，作用是把“评审确认”绑定到具体文件和版本范围并留痕；它不能代替人对评审内容的确认。
  - 工具只能打包“受控首次试验”类型的升级包（installation_accepted 与 raw_kv_accepted 始终为 false）。
