固件版本与空间工具  YpVersionTool.exe  v1.0 使用说明
=====================================================

【2026-11-04 起】
  - 读设备空间按红线判断：可用 ≥ GR 签名镜像 + 32768（以前多算了一次 904）；没选 GR 固件时按红线镜像 393216 判断。
  - 同时报告 OTA 状态记录（yp001_ota_state_0/1）大小：每次整机升级约 +170 字节、存两份，超过 4096 提醒（多次升级在累积，
    OTA_PRUNE 清不掉这部分）；已用超过常驻预算 98304 提醒。
  - 检查两个固件的空间时也按 OTA 红线：GR 签名镜像 393216、CAT1 脚本区 507904。
  - 串口默认选上次读成功的口（记在 last_port.txt）。
  - 红线数字在工具包根目录的 budget.json（所有工具和一键工具共用，只改这一个文件，并写明日期和原因）；没有这个文件时用内置的 2026-11-04 默认值。说明见 doc/2026-11-04_OTA空间红线_GR与CAT1大小管控.md。

一、这个工具做什么
  1. 把两个固件（GR5526 和 Air780EGH/CAT1）的版本一起改成同一个版本和构建号；改完你手动编译，工具不编译、不烧录。
  2. 检查两个固件各自的大小有没有超限、还剩多少，并核对编译出来的 GR 固件里的版本是不是你改的那个。
  3. 通过串口读设备 CAT1 的可用空间（向设备发一次只读的 cat_at OTA_FS），直接得到要填进“3_整机OTA打包”的那个数。
  什么时候用：准备做新一版 OTA 之前——先改版本，编译，检查空间，再去签名和打包。
  运行环境：Windows 10/11，不用安装任何软件。
  检查 CAT1 脚本大小时，要和“1_CAT1刷机目录生成”文件夹放在一起（工具包里本来就是），工具会调用其中的 Cat1UsbImport.exe（只检查，不写文件）。

二、一、改版本（窗口第一部分）
  ┌ GR 版本头文件 (yp001_fw_version.h)
  │  例子：  D:\CODEX\sos-card\ble_app_uart_c\Src\config\yp001_fw_version.h
  │  作用：  GR 固件的版本身份在这里定义（版本、产品版本、构建号），编译进固件里的 YP001_FW|GR5526|…|END 标记。
  │
  ├ CAT1 main.lua
  │  例子：  D:\CODEX\sos-card\Air780EGH\main.lua
  │  作用：  CAT1 的版本身份：VERSION、PRODUCT_VERSION、FW_RELEASE_BUILD。工具只改这三行（和一行时间标记），别的内容不动。
  │
  ├ 新版本
  │  例子：  1.5.3
  │  作用：  两个固件同时改成这个版本（GR 里写成 001.005.003 和 1.5.3，CAT1 也一样）。不允许版本倒退。
  │
  └ 构建号（留空 = 自动）
     怎么选：一般留空。版本升高时自动在当前构建号上加 1（例如 1.5.2/build 6 → 1.5.3/build 7）；版本不变时保持原构建号。
     例子：  1.5.2/build 6 改成 1.5.4，留空 → build 7；填 9 → build 9（必须大于当前的 6）。
     作用：  构建号是 GR 固件身份的一部分，设备和签名都用它，所以新版本必须比旧的大，同一版本不允许改构建号。

  按钮：
    读取当前版本   只看，不改。显示 GR 和 CAT1 现在的版本和构建号，两边不一致时会提醒。
    修改两个固件的版本   弹窗确认后才改。改之前把两个文件备份到项目根目录 logs\firmware_versions\set_时间\，
                         并同步项目根目录的 firmware_version.json（如果有）。
  改完之后：
    ① 在 Keil 里重新编译 GR（F7）——工具不会替你编译，也不会烧录。
    ② CAT1 的 OTA_TRIAL_SOURCE / OTA_TRIAL_TARGET 工具不改，请自己核对它们和这次要打的版本范围一致。
       （例如要打 1.5.2→1.5.3：OTA_TRIAL_SOURCE='1.5.2'，OTA_TRIAL_TARGET='1.5.3'。）

三、二、检查空间（窗口第二部分）
  ┌ GR 固件（编译出的 .hex / .bin）
  │  例子：  D:\CODEX\sos-card\ble_app_uart_c\Keil_6\Objects\YP001_GR5526.hex
  │  作用：  检查：应用大小 ≤ 441464 字节（GR 槽 442368 减 904 字节签名），显示余量和占比（≥95% 黄色提醒）；
  │          HEX 的地址必须从 0x00202000 起，不能含 Boot/SCA/NVDS；固件里要有且只有一个版本标记，
  │          并且和上面“GR 版本头文件”里的版本一致（改了版本却忘了重新编译，会在这里报“不一致”）。
  │          带签名尾部的 .bin（如 GR5526_1.5.3_b7_signed.bin）也可以选，大小按正文算。
  │
  └ CAT1 源码目录（含 main.lua）
     例子：  D:\CODEX\sos-card\Air780EGH
     作用：  检查 CAT1 脚本总量（LuaDB）≤ 524288 字节，显示余量；余量小于 2 KiB 黄色提醒。
             选了 main.lua 后这里会自动填上同一个目录。
  按钮：检查两个固件的空间。两项可以只选一项。
  报告颜色：绿色 OK；黄色 WARN（余量很小，下一版容易超）；红色 ERROR（超限或版本不符，必须处理）。

四、三、读设备 CAT1 可用空间（窗口第三部分）
  COM 口：下拉里列出这台电脑现在有的串口，选“GR 命令行口”（以前是 COM26，换电脑或换线后会变；不确定时拔掉再插上，看下拉里多出哪个）。
          点“刷新”重新列出。
  读取设备可用空间：向这个口发一次 cat_at OTA_FS（只读查询，不改设备），最多等 15 秒，读到后显示：
          OTA_FS total=128 used=15 block=4096
          CAT1 可用空间 = (128 − 15) × 4096 = 462848 字节   ← 把这个数填到“3_整机OTA打包”的“CAT1 可用空间”
  如果上面选了 GR 固件，会同时判断够不够，用的是设备自己的算法：需要 = 已签名镜像大小 + 904 字节签名预算 + 16384 字节预留。
      例子：已签名的 1.5.3（438472 字节）需要 438472 + 904 + 16384 = 455760；设备有 462848，余 7088 字节，够用；
            设备有 446464（OTA 状态文件占了 4 块以后的真实情况），差 9296 字节，不够。
      不够时报红色“不够，差 … 字节”：要清理设备上不需要的文件或减小固件，不能靠改数字解决。
  没选 GR 固件时，按最坏情况（GR 槽 442368 + 904 + 16384 = 459656）判断。
  清理 OTA 历史：不够时点这个按钮。弹窗确认后，向设备发两次 cat_at OTA_PRUNE（OTA 状态有两份副本，每次重写一份），
          先把 OTA 历史日志归档到 VUART 日志，再删掉历史键，然后自动重新读可用空间。它只清理 OTA 自己的历史，
          不动业务数据和固件。这是写设备文件的操作：GR 新固件试运行的 120 秒内不要做。
          例子：10-30 第三轮 OTA 卡在 COMPONENT_SPACE（可用 446464，差 9296），清理两次后可用 450560，OTA 才继续。
          注意：清理只释放“历史”；OTA 一发起，设备还会多占约 16 KB 的 OTA 状态文件，GR 镜像越大越容易不够，
          所以发起 OTA 之前最好先清理一次再读数。
  常见问题：
    “… 被别的程序占用”   串口助手、Keil、监控脚本占着这个口，关掉再读。
    “15 秒内没有收到 OTA_FS 回答”   检查 COM 口选对没有（GR 命令行口）、板子上电、CAT1 已启动（开机后要等一会儿）。
  注意：这个数每次刷机或 OTA 之后都会变，每次打包前重新读，不要抄旧的，也不要填门槛值 459656（那样检查必过，等于没检查）。

五、完整例子：准备 1.5.2 → 1.5.3 的 OTA
  1. 打开工具，GR 版本头文件和 main.lua 各选好；点“读取当前版本”，确认是 1.5.2 / build 6。
  2. 新版本填 1.5.3，构建号留空，点“修改两个固件的版本”→ 确认 → 1.5.3 / build 7。
  3. 到 Keil 编译 GR（F7）。
  4. GR 固件选新编译出的 hex，CAT1 源码目录选 Air780EGH，点“检查两个固件的空间”：大小、余量、版本标记一致都应通过。
  5. COM 口选对，点“读取设备可用空间”，记下读到的数。
  6. 去“2_GR5526固件检查签名”签名，再去“3_整机OTA打包”打包，可用空间填第 5 步读到的数。

六、命令行
  YpVersionTool.exe show  --header <yp001_fw_version.h> --lua <main.lua>
  YpVersionTool.exe set   --header <yp001_fw_version.h> --lua <main.lua> --version 1.5.3 [--build 7]
  YpVersionTool.exe check [--gr <固件.hex|bin>] [--cat1 <CAT1源码目录>] [--header <yp001_fw_version.h>]
  YpVersionTool.exe fs    --port COM26 [--gr <固件.hex|bin>]
  YpVersionTool.exe prune --port COM26 --yes [--gr <固件.hex|bin>]    清理 OTA 历史（会写设备文件，必须带 --yes）
  YpVersionTool.exe --ports      列出串口
  YpVersionTool.exe --version
  返回值：0 通过；1 有错误；2 参数错误。
