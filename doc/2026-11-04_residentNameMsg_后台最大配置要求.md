# residentNameMsg 文件：后台最大配置要求

SAM | 2026-11-04 | 读者：后台开发 | 超出任何一条，设备整份拒收，屏幕保持原来的内容

## 一、文字字段

| 字段 | 最大要求 | 说明 |
|---|---|---|
| `Name` 姓名 | **最多 5 个字**，且 ≤ 63 字节 | 不能为空。设备协议能收 8 个字，但屏幕按 5 个字设计，后台按 5 个字限制 |
| `Room` 房号 | ≤ 63 字节；**只能用数字、英文字母、`# - .` 等英文符号和"号楼栋单元层室"** | 用设备自带的字库显示，不推字形。写了别的汉字，屏幕显示 `--` |
| `Campus` 园区 | **最多 11 个字**（非英文字符，"·"也算 1 个），且 ≤ 95 字节 | 一行 180 像素，16px 字最多放 11 个 |
| `Seq` | 生成文件时的当前时间（Unix 秒，整数） | 必须比上一次下发的大，否则当作旧消息拒收 |
| `MsgType` | 固定 `residentNameMsg` | — |

## 二、字形 `Glyphs`

| 项目 | 最大要求 |
|---|---|
| 推哪些字 | 姓名每个字推 **32px 和 16px 两个字形**；园区每个字推 **16px 一个字形**（相同的字只推一次）；房号不推 |
| 字形个数 | **≤ 28 个**（5 字姓名 × 2 + 11 字园区 = 21 个，按要求填写不会超） |
| 字号 `S` | 只能是 `16` 或 `32` |
| 点阵宽高 `W` / `H` | 1–40 像素 |
| 单个点阵 | ≤ 200 字节（`D` 的 base64 ≤ 268 字符） |
| 校验 `C` | CRC-16（4 位十六进制），设备会重算，不对就拒收 |

## 三、整体大小

| 项目 | 上限 |
|---|---|
| 设备存储量 | 20 + 每个字形 16 + 全部点阵字节 ≤ **4000 字节**（5 字姓名 + 11 字园区实测 1378，放得下） |
| JSON 文件大小 | ≤ **8192 字节**（同样 5 + 11 字的文件约 3 KB） |

## 四、一句话

**姓名 ≤ 5 个字，园区 ≤ 11 个字，房号只用数字、字母和"号楼栋单元层室"，Seq 填生成时的当前时间**。按这四条生成，其他上限都不会超。
