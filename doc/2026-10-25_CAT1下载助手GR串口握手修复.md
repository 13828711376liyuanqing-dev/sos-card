# CAT1 下载助手 GR 串口握手修复

SAM | 2026-10-25 15:57 +08:00

## 现象与定位

截图中助手选中 COM26，点击首次上电后提示“未取得 GR CLI 回显……未发送电源命令”。根据代码路径，`FirstPowerOn()` 首先调用 `ConnectSerial()`；GR CLI 身份探测未通过会在 `cat1_power on` 和 `cat1_power key` 之前停止。因此本次失败发生在 GR UART 握手阶段，CAT1 电源命令没有发出，不能据此判定 CAT1 电源硬件故障。

旧 `ConnectSerial()` 发送 `help\r\n` 后固定等待 350 ms，只调用一次 `ReadExisting()`；有效 GR 回显若晚到就会被误判为无响应。`help` 在固件 CLI 中会输出 `Available commands:`，现有识别规则能识别该响应，因此此次修复针对读取时序，不改 CLI 协议或放宽设备身份确认。

## 修改内容

- `tools/cat1_download_assistant/MainForm.cs` / `ConnectSerial()`：改为最多约 2 秒，每 50 ms 读取并累积串口数据；GR CLI 身份检查成功后，才进入后续流程。
- `tools/cat1_download_assistant/DownloadSession.cs` / `CollectGrCliProbe()`：新增可测的有界读取累积逻辑。
- `tools/cat1_download_assistant/tests/DesktopTests.cs`：增加延迟数次读取后才收到 `Available commands:` 的回归断言。
- `tools/cat1_download_assistant/README.md`：记录已知握手问题、修复范围和实机验证边界。
- 新构建：`tools/cat1_download_assistant/bin/CAT1DownloadAssistant_20261025_1558.exe`；`bin/latest.txt` 已指向它。旧 EXE 保留，没有覆盖。

## 现场验证与下一步

用新 EXE（或双击启动 BAT，让其读取 `bin/latest.txt`）选择实际接 GR UART0 的 COM 口、115200/8N1，先点“仅连接 GR（不动电源）”。日志应出现 `Available commands:` 或 GR CLI 标识。确认握手正常后，再按现有首次上电流程操作；工具仍会先探测 CAT1，并保留 GR 身份校验，不会在无回显时盲目发电源命令。

如果新版本仍无 GR 回显，剩余阻塞是 COM/UART 的现场链路：确认 COM26 当前确为 GR UART0 且未被其他程序占用，并检查 USB-UART TX、RX、GND 接线。此时仍不应绕过身份检查强制上电。CAT1 USB 枚举、BOOT↔EXT 下载模式和 Luatools 烧写结果需要分阶段另行确认。
