# 姓名字形生成器 开发包

SAM | 2026-11-03 | 读者：接手二次开发的工程师（后台/平台、工具开发）

## 这是什么

YP001 三代报警定位卡的屏幕（200×200 黑白电子纸）只自带几百个常用字。居民姓名由平台把**每个字的点阵**推给终端显示。这个包负责把"姓名"变成终端能用的点阵文件（`residentNameMsg` JSON 文件，只用 JSON），并提供二次开发需要的源码、格式说明、参考代码和自检。

```
后台工具生成 JSON → 平台存储/MQTT → 终端 CAT1（Air780EGH）下载校验 → GR5526 显示
```

## 终端侧行为（当前固件，2026-11-03）

- **长期保存**：GR 收齐校验后把字形存进专用 Flash 两页 A/B（0x2FB000 / 0x2FC000，每页 4 KB，带 CRC；2026-11-04 起，原来是 NVDS 一条约 1 KB），新记录先写另一页、读回核对后才擦旧页，重启、断电、OTA 都不掉字；存储损坏时不用，自动向 CAT1 要。
- **只有两种情况清空**：平台"清空姓名"（CAT1 转发 `name_clear`），或出厂清空（生产工序 GR 串口 `name_store clear`，有线烧录工具最后一步自动做并核对 `name_store status` 为空）。出厂本地不留姓名、房号、园区。
- **下载流程**：CAT1 收到地址 → 保电 → 先清日志 → 下载 JSON → MD5 校验 → 转 GR → 回执 → 释放保电。只用 JSON，不接受 zip。
- 详见 `device_ref/` 和 `docs/`。

## 运行环境

| 用途 | 需要 |
|---|---|
| 只用/只改后台网页工具 | Windows + Chrome 或 Edge。无需安装任何东西 |
| Python 台架工具、自检 | Python 3.10+，`pip install -r requirements.txt`（Pillow、pyserial） |
| 与终端字库逐字节一致的渲染、T0 自检、网页 CORE 对比 | Node.js 16+（`fontconv/` 已带好 `lv_font_conv`，不需要再 npm 安装） |
| 推送到板子 | GR 调试串口（默认 COM26，115200）和已烧录姓名下发功能的 GR 固件 |

没有 Node 时，Python 工具退回 Pillow 渲染（形状近似，不保证与终端字库逐字节一致），自检会跳过相关项。

## 两套工具的关系

- **后台网页版**：浏览器渲染字体（黑体，缺字自动用 SimSun-ExtB 等扩展字体并加粗），给后台人工操作。可能与终端自带字差约 1 像素，不影响显示（同一姓名的字全部用推送字形）。
- **Python 版**：用 `lv_font_conv` 渲染，与终端字库**逐字节一致**；还能经串口直接推给板子测试。
- 两者的**打包、CRC、消息格式完全相同**，`selftest.py` 会对比。

## 二次开发常见场景

| 想做什么 | 改哪里 | 注意 |
|---|---|---|
| 把生成做成后台服务 | 搬 HTML 里 CORE 段到 Node，或直接用 `glyphlib.py`（`name_glyphs` → `platform_msg`） | 服务器上要有黑体等字体文件；建议用 `lv_font_conv` 渲染 |
| 换字体 | 网页"加载字体文件"；Python `G.DEFAULT_TTF` 或 `name_glyphs(..., ttf=)` | 确认字体授权允许嵌入/分发点阵 |
| 改界面/交互 | HTML 里 CORE 段以外的部分 | 不影响格式 |
| 改消息字段或点阵格式 | `docs/字段与格式说明.md` → HTML CORE → `glyphlib.py` → `device_ref` 对应的终端代码 | **终端固件必须同步修改并重新烧录**，否则终端拒收；改完跑 `selftest.py` |
| 增加字号（如 28px 房号） | 生成侧加 `S` 取值；终端侧要加动态字体 | 当前终端只接受 16、32 |

## 必须遵守的约束（终端会检查，违反则整批拒收）

- 字号 `S` 只能 16 或 32；宽高 1~40；单字点阵 ≤ 200 字节；**字形最多 28 个**（姓名每字 32+16px，园区每字 16px）。
- 姓名：**主页最多显示 5 个字**（汉字等非英文字符，英文不计个数），第 5 个之后自动截掉，只推这 5 个字的字形；UTF-8 ≤ 63 字节（2026-11-03 用户决定）。
- **姓名、房号、园区全部由后台下发，出厂本地不留，只留存放空间**（2026-11-04 用户确认）：姓名、园区里的每个非英文字都推字形，**不管设备自带字库有没有**；房号只用数字等，继续用设备自带字库，只推文字。英文名加空园区时字形是 0 个。
- **整套字形的存储大小 ≤ 4000 字节**（20 B 头 + 每个字形 16 B + 点阵；终端存在 GR 专用 Flash 两页 A/B，4 KB，2026-11-04）；5 字姓名 + 11 字园区实测约 1.4 KB，余量充足；超了工具会报错。
- 园区：非英文字符 ≤ 11 个（16px 一行 180 像素），园区随站点变化（燕园、鹏园…）所以也推字形。
- 显示：主页姓名 32px 标签一行 5 个汉字，超过截掉（已定，不缩字号、不换行）。
- 点阵：1 位/像素，**每行补齐到整字节**，高位在前（不是连续位流）。
- CRC-16/CCITT-FALSE 覆盖 10 字节头 + 点阵（细节见 `docs/字段与格式说明.md`）。
- 同一终端 `Seq` 必须递增。
- 只用 JSON 文件（UTF-8）；终端不再接受 zip（2026-11-03 用户决定）。

## 验证

```
python selftest.py          # 已知 CRC 向量、示例文件、打包互逆、串口行长度、网页与 Python 一致
python selftest.py --t0     # 再加：重新生成终端字库里的全部字并逐字节对比（约 20 秒）
```

全部 `PASS` 再交付。改了格式还要在实板上验证：`python glyph_maker.py send --name <姓名> --port COM26`，看屏幕。
