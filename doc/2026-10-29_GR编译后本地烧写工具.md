## 子命令

| 命令 | 作用 | 写设备 |
|---|---|---|
| `check` | 编译日志 0 错 0 警、AXF 晚于全部 .o、HEX 不早于 AXF、无过期目标；读 AXF 内版本 `YP001_FW|GR5526|x|build`；台架宏；相对上次交付变化的源码；是否支持 J-Link 直烧 | 否 |
| `sign --format hex\|bin\|both` | 任何版本：测试密钥签名（`GrBaselineSign_current.exe`），输出 `firmware_releases/gr_signed_<版本>_b<build>_<时间>/`，HEX 起始 0x00202000。用于 OTA 打包，**不是直烧镜像** | 否 |
| `prepare --format …` | 仅 1.0.2 build 3 台架基线：J-Link 只读快照两次（默认间隔 60 s，须一致、不停核）→ Boot 日志须为干净 PREPARED → 列出改动文件让你确认 → 调用技能 `prepare_delivery.py` 签名并配对 → 导出 `FLASH/APP_SIGNED_*.hex/bin` 与 `FLASH/BOOT_PAIRED.hex/bin` | 否 |
| `flash <输出目录>` | 输入 `FLASH` 确认 → 再拍快照须与准备时一致 → Keil 只下载工程依次写 APP、Boot（日志须 `Verify OK`）→ 一次 SYSRESETREQ → 读回验收（技能 `check_readback.py`）→ COM26 读 GR 版本与业务状态 | **是** |
| `auto --format …` | prepare + flash | 是 |

不自动给 CAT1 开机：GR 复位后若 `link=0`，按技能红线顺序处理（需授权的 `start_cat1_once.py` 不由本工具调用）。

## 为什么非 1.0.2 不能直烧

Boot 基线描述符中 A 版本号写死 1000002（`pair_gr_adc_resync_build.py:103`、`prepare_delivery.py:58`），签名断言也固定 1.0.2/build 3（`pair_gr_adc_resync_build.py:96`），这是唯一实板验证过的直烧配对。其他版本（如当前 1.5.1）只经 OTA 交付，工具会明确拒绝直烧并提示用 `sign`。
