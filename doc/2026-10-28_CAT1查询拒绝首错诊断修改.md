SAM | 2026-10-28 10:20 +08:00 | 已修改 CAT1 主源码并完成主机验证，未向设备下载或执行 OTA。

## 修改及原因

- `Air780EGH/ota_platform.lua` 的 `send_gr`：在发送器不存在或 JSON 编码失败时输出固定 `OTA_DIAG` 原因；保留原失败返回，不输出消息内容。日志对象不存在时仍返回失败。
- `Air780EGH/uart_app.lua` 的 `uart_async_push`：将控制消息的窗口锁存、DFU 占用和队列满分别记录为 `LOCKED`、`DFU`、`QUEUE`；保留 DFU 原 `nil` 和其他原有返回。共享受保护 JSON 解码；私有无元表数组直接追加替代 `table.insert`，保留队列顺序。
- `Air780EGH/ota_uart_window.lua`：首次锁存输出原始 UART 错误，日志异常不阻断故障事件；缓存初始化传入的事件回调以节省空间。该优化依赖现有构造调用不替换传入的 `io.event`。
- `Air780EGH/tts.lua`：两个纯转发接口改为对应 Lua 函数引用以节省空间。代表性参数主机差分一致，未验证实板音频。
- 之前已有但未部署的 `ota_runtime.lua` 查询准入补丁包含在维护预览中；它只检查预检时的状态，不能覆盖预检后新故障或 JSON 编码失败。
