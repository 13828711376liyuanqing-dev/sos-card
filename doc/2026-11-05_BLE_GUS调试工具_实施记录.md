# BLE GUS 调试工具实施计划

SAM | 2026-11-05 +08:00 | 按用户确认复用现有 BLE 工具，先验证 GUS。

1. 复用 factory_final 的 BleLink，独立增加串口式收发窗口，保留原厂测工具。
2. 提供 12 秒扫描、人工选设备、连接/断开、FT INFO 查询、手动 ASCII 命令及日志保存。
3. 单请求执行，8 秒回应超时，禁止自动重发，断线清理会话。
4. 编译验证、已有协议测试、窗口渲染及实际扫描分别记录，实板收发由用户首测。

此版本使用 Windows 系统蓝牙，COM31 Nordic USB CDC 适配尚未实现。完整 CLI、持续运行日志、OTA 和老化任务不作为此版验证范围。

## 实施结果及接口纠正

SAM | 2026-11-05 +08:00 | 用户明确要求使用 COM31 Nordic Dongle，最终交付改用 Nordic 串行 connectivity 驱动。

最初制作了基于 Windows GATT 的界面，该接口与用户要求不符，已替换为 COM31 专用工具。主入口为 `tools/ble_console/nordic/YP001_COM31_BLE.exe`。Python GUI 启动配套 Electron Node worker，通过 Nordic pc-ble-driver-js 2.8.2 控制 COM31，未调用 Windows 蓝牙。

功能包括打开 COM31、8 秒扫描、人工选择地址、连接 GUS、启用通知、INFO 序号匹配、手动 ASCII 分片发送、文本及 HEX 接收和日志保存。副作用命令不自动重发。源码分为 `com31_console.py`、`worker.js`、`protocol.js` 和 `Launcher.cs`。

串行控制驱动初始化及关闭会管理 Dongle 的 BLE 栈，未对 GR5526 执行复位/烧录。本轮未给 Dongle 烧录新固件。工具当前依赖本机 Python 3.12 的已安装路径及完整 Nordic runtime 目录，跨电脑便携性未验证。现场实测证据仅支持 Dongle 握手和扫描。

补充验证边界：窗口控件自检通过，但尝试将 GUI 自动打开至用户桌面的 Computer Use 调用超时，尚未完成可见窗口视觉核对。用户可手动双击入口。自动审批拒绝了开发下载/解包临时文件的批量清理，理由为可能影响 Nordic runtime，未执行该删除，相关组件全部保留。该拒绝不影响已验证的握手、扫描及工具文件生成。
