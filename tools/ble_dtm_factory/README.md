# YP001 蓝牙暗室 DTM 双方案交付

本目录只存放 GR5526 蓝牙射频测试产物；**不修改** `ble_app_uart_c`、交付副本、现有 CAT1 上位机或 `Air780EGH`。两方案各有独立固件：方案 1 保留原版，方案 2 的 2026-10-12 CAT1 自动开机版在启动时请求 CAT1 供电并脉冲操作 PWRKEY，供 CAT1 自身 USB 下载/调试使用；各自目录单独存放所需文件，可独立交给天线厂。

| 方案 | 控制 DUT 的设备 | 使用入口 |
|---|---|---|
| 1 仪器直控 | 支持 HCI H4/UART 的暗室蓝牙测试仪 | `方案1_仪器直控/使用说明.md` |
| 2 电脑手动 | 本包 Windows 工具控制 DUT，暗室仪器仅负责 RF 收发和测量 | `方案2_电脑手动控制/使用说明.md` |

**状态**：固件已在本机以 GNU Arm GCC 编译生成 BIN/HEX，PC 工具已编译并通过 HCI 报文主机测试；尚未烧入 YP001 实板，也未接暗室仪器验收。首次交付构建日志在 `../../SDK/projects/ble/dtm/yp001_ble_dtm/build_gcc.log`，退出码 0、0 错误、889 条链接警告（主要是旧 SDK ROM 绝对符号与 GCC 15 的兼容提示）；不能把“已生成”写成“实板可用”。

2026-10-12 方案 2 再更新：从独立 DTM 工程以 `CAT1_POWER_ON_BOOT=1 BUILD=out_cat1_boot` 重编，日志为 `../../SDK/projects/ble/dtm/yp001_ble_dtm/GCC/build_cat1_boot_20261012.log`。方案 1 仍使用原版固件；方案 2 在初始化蓝牙 HCI 前将 GPIO6 置高，并经 AON_GPIO0/Q4 对 CAT1 第 7 脚 PWRKEY 执行 200 ms 供电等待、1600 ms 按下、随后释放；不初始化 CAT1 UART4 或发送 AT。实板 CAT1 电压、PWRKEY 波形和 USB 枚举仍待验证。

交给工厂请用 `YP001_蓝牙天线暗室测试_方案2_CAT1自动开机_待样机验证_20261012.zip`；`CAT1上电_20261012.zip` 仅供电而不按 PWRKEY，`20261010.zip` 未加 CAT1 供电，均为历史包。方案 2 文件夹内 `使用说明.md` 和 `使用说明.pdf` 与新版镜像配套。

两方案都要求先保存被测板当前产品固件的**确切可恢复镜像**。测试镜像与产品应用占用同一应用地址 `0x00202000`，烧入测试镜像会暂时替代板上产品程序；测试后必须恢复并核验原产品版本。若无法取得确切恢复镜像，请使用专用工程样机，不要在正在交付的产品板上试烧。软件仓库中的产品工程和现有 HEX 没有被本任务改动。

2026-10-10 复核：当前用户只有产品板、没有确切恢复镜像，且拟同时连接电池和 USB/5V。**方案 2 目前仅为工厂评估包，不可直接在该接法和该板上烧写/测试。**DTM 固件未执行产品固件的 ETA69631 禁充流程；GR5526 烧写还需验证 SCA/启动信息处理。详见方案 2 使用说明。

原厂依据：[汇顶 GR5xx DTM 测试指南 V3.6](https://docs.goodix.com/zh/online/detail/dtm_test_bl/V3.6/defcb7e6094041b8c84bfeaa3ad350ed)。

## 开发与验证证据

- 源码：`../../SDK/projects/ble/dtm/yp001_ble_dtm/`（从 SDK DTM 示例复制到独立工程，只调整 HCI UART0 映射与构建兼容）。
- DTM HCI：UART0，GPIO28 TX / GPIO29 RX，115200 8N1，无流控。此为源码和既有板级映射核对，仍需实板确认测试镜像确实应答。
- PC 工具源码：`pc_tool/`；测试程序：`pc_tool/ProtocolTests.exe`。
- `方案1` 与 `方案2` 的固件应分别用各自 `SHA256SUMS.txt` 校验；方案 2 新版的 HEX/BIN 与方案 1 不再相同。
- 方案 2 新版 HEX/BIN 有效地址为 `0x00202000–0x0021D7D7`；HEX 数据与 BIN 对应字节一致，BIN 在 HEX 未覆盖的 6408 字节间隙填充 `0x00`。`0x0027E000` 在当前配置中只是已注释的 NVDS 示例地址，不能据此推断实际 NVDS 或烧写器擦除范围。
