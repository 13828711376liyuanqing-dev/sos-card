## YP001 连接与通信要求

- U13：VCC_SYS 经 R54 到 IN4；GPIO7/LDO_EN3 经 R14 到 EN3，R18 下拉；OUT1 经 R32 到 VDD_3V3，再到 U1104 VDD7。
- U1104 VDDIO3 接 VDD_1V8；SCL12 经 R53 接 GPIO2，SDA2 经 R52 接 GPIO3；R75/R77 4.7k 上拉到 1.8V。
- INT1 第 5 脚经 GS_INT1 接 AON_GPIO7，R1103 上拉到 1.8V。
- 当前配置：I²C0 MUX0、100kHz、7 位地址。Rev0.3 第 11 页规定 I²C 上限 400kHz。
- FAE 最新说明：SA0 低时 7 位地址 **0x26**，线上写地址字节 **0x4C**、读地址字节 **0x4D**；SDK API 传入 0x26。SA0 高时为 0x27，对应线上 0x4E/0x4F。旧 Rev0.3 第 12 页仅列 0x27，作为版本差异保留。
- Rev0.3 第 20 页：只读寄存器 **0x01**，预期 **0x13**。
- 本板逻辑分析仪预期：START → 4C/ACK → 01/ACK → repeated START → 4D/ACK → 13/NACK → STOP。主机末字节 NACK 是正常结束。
- Rev0.3 第 10 页列出 VDD/VDDIO 上电时间参数 100ms 和关断启动时间 3ms；不要仅凭这一表推导任意双电源先后顺序。实际供电时序与版本限制仍需确认。

## 当前证据

1. `logs/charger_reset_20261010_085643.log` 历史启动记录：I²C/DMA 初始化成功，读取 ID 返回 `ret=3, id=00`。SDK HAL 枚举中 3 为 HAL_TIMEOUT，且 `app_i2c_mem_read_sync` 原样返回 HAL 错误；00 是失败缓冲区内容，不能当作芯片真实 ID。
2. 本轮前置 COM26 115200 8N1 被动采集：`logs/gsensor_passive_20261010_101515.log`，收到电池、显示、充电日志，无 G-sensor 输出。该日志显示当时充电正在进行，不能因历史停充配置就假定当前停充。
3. 本轮 J-Link 只读检查：`logs/gsensor_readonly_jlink_20261010.log`；未发 halt/reset/Flash 命令。I²C0 TAR=0x27，ENABLE=0，STATUS=0x06，TX_ABORT_SRC=0。事务结束后的空错误值不证明通信成功。
4. GPIO0 DATA=0x1800、DATAOUT=0x680：输出锁存 GPIO7 为高，而 DATA 的 GPIO2/3 位为低。外设复用/输入通路可能影响 GPIO 读取，不能直接等同于引脚实测电压；必须用万用表/示波器进一步确认。
5. 固件先在 `gpio_init()` 拉低 GPIO7，随后 `BSP_init()` 的 `Pwr_Jkb(1,1,0)` 将其拉高，再启动传感器对象。不能只看前一个调用就结论为一直未供电。
