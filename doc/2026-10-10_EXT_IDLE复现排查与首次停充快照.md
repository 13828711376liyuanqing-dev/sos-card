## 本轮代码修改

仅增加诊断，保留现有保护条件、自动充电策略和100 mA/4.20 V配置。

| 文件/函数 | 修改前 | 修改后及原因 |
|---|---|---|
| `Src/user/charger/yp001_charger.c` / `remember_stop` | 状态缓存不断更新，历史故障可能被后续读清 | 在首次停止事件保存原因、开机毫秒时间及当时完整状态；后续停止重试不覆盖，方便追溯 |
| 同文件 / `yp001_charger_print_diagnostic` | 无停止记录查询 | 打印 ready/active/hold/stop_pending、last原因、snapshot有效性及当时输入/故障/配置；本函数只读RAM，不访问芯片 |
| 同文件 / prepare、start、poll、stop | 大部分错误只打印概括文字 | 在配置失败、启充检查失败、I²C读失败、输入丢失、运行保护、芯片终止等路径保存证据；停充详细打印安排在禁充回读成功之后 |
| 同文件 / successful start | 无记录生命周期 | 新的成功启充清除旧停止记录；查询和拔插过程中原记录保留，复位清除RAM。错误读取不伪造有效快照 |
| `Src/user/charger/yp001_charger.h` | 无诊断输出接口 | 增加只读RAM诊断打印接口声明 |
| `Src/user/charger/yp001_charger_cli.c` / `cmd_charger` | status只打印当前寄存器 | status先打印保存证据，再读当前状态；即使I²C随后失败仍能看到原记录 |

`REQUESTED_STOP`代表未先捕获专门原因的停止请求（包括手动/准备路径），不能单凭这个标签断言硬件故障。记录保留的是上次成功启充之后的**首次**停止；后续恢复尝试失败不覆盖旧记录。若显示 `snapshot=0`，只知道路径原因，没有完整寄存器快照，不解读旧结构内的值。

运行失败标签 `RUN_GUARD` 配合 `CHG SNAP` 定位：VIN/PG看输入，HIST/NOW看历史/当前故障，THERM看热限制，POWER/TIMER/PRETERM/FINE及IIN/ICHG/VREG看配置。详细字段含义沿用ETA69631 Rev1.9；本轮未绕过任何保护或启用自动故障重试。
