# SVN2 Air780EGH 与当前正式 Air780EGH 的 SIP/上网实现对比

> 分析时间：2026-10-15（北京时间）  
> 分析人：SAM  
> 范围：只读比较 `D:\SVN2\Air780EGH` 与正式工程 `D:\CODEX\sos-card\Air780EGH`。本报告不把 SVN2 代码、底包或账号配置作为正式工程输入。

## 1. 结论先行

1. **SVN2 确实包含较完整的 SIP、4G 网络、MQTT、SIM 热插拔和网络看门狗模块**，可作为设计参考。
2. **SVN2 目录没有找到带时间、串口、SIM、注册/IP、MQTT 或 SIP 通话结果的独立原始测试记录**。因此不能据此认定“上网已实际验收”或“SIP 实际通话已通过”。源码中的“原始版本已验证可正常通信”等注释只能算开发备注。
3. **当前正式源码比 SVN2 多了网络代次（generation）和 IP/SIM 状态门控**，能够让旧的 MQTT/SIP 回调在 SIM 拔出、IP 丢失后失效，降低旧会话恢复业务的风险。
4. SVN2 可以借鉴的主要是模块组织、事件命名和业务接口；其账号、服务器、底包和具体配置不能直接复制。报告不展开任何密码或 Token。
5. 当前正式工程已有串口和部分 MQTT 环境日志，但现有证据仍不足以证明真实 SIM 注册、稳定 IP、MQTT 长连或 SIP 真实通话全部通过；这些必须在目标 SIM、目标网络和实板上分层验收。

## 3. SIP 实现对比

### 3.1 共用的业务骨架

两边均采用 `exsip` 回调驱动的状态机，主要业务事件为：

- `SIP_INIT`：初始化 SIP 和音频；
- `SIP_DEINIT`：停止 SIP；
- `SIP_DIAL=<号码>`：呼出；
- `SIP_ACCEPT`：接听；
- `SIP_HANGUP`：挂断；
- `SIP_STATUS`：查询状态；
- `SIP_CALL=<号码>`：复合初始化+拨号。

因此，GR5526 侧若依赖这些文本事件，接口形态总体可以保持，不需要因为参考目录存在就重写业务协议。

### 3.2 当前正式版本的改进

当前正式 `sip.lua` 相对 SVN2 增加或保留了以下保护：

- 引入 `netdrv_device`，等待 **SIM 就绪和 IP 就绪**，而 SVN2 主要只等待 `socket.adapter(socket.dft())`；
- 订阅 `SIM_LOST` 和 `IP_LOSE`，网络断开时可以停止或终止当前 SIP 会话；
- 保存网络 `generation`，回调返回时重新核对 generation 和 IP 状态，旧网络会话的迟到事件不能恢复新业务；
- 排队拨号在网络代次变化或 IP 丢失后会转为错误，避免在旧链路上误拨；
- `stop()` 时释放音频设备，减少 SIP 反复启停后的音频资源占用；
- 去除了 SVN2 中初始化时的 TTS 提示音，并延后/关闭来电 TTS，降低 TTS 与通话音频资源冲突。

这些改动更适合当前 GR5526+Air780EGH 的掉卡、断网和重复启动场景，不能为了“对齐 SVN2”而回退。

### 3.3 参考目录中的差异

SVN2 有通话 BUSY 周期上报、来电播报和 SIP 初始化提示音等业务表现。它们能作为需求讨论参考，但是否保留要由当前产品语音资源、GR 事件协议和音频硬件验证决定。尤其不能直接复制 SVN2 的 SIP 服务器、用户名、密码或测试地址。

## 4. 上网、SIM 与 MQTT 对比

### 4.1 SVN2 网络流程

SVN2 的基本流程是：

1. 通过 `mobile` 监听 SIM 状态和驻网状态；
2. 通过 `IP_READY` 等事件判断数据链路；
3. MQTT 主任务等待 `socket.adapter(socket.dft())`；
4. 创建 TLS MQTT 客户端，认证、连接、订阅；
5. 断开或错误后关闭客户端，延时后重连；
6. 网络看门狗依靠 MQTT 心跳或业务消息喂狗。

`sim_hotplug.lua` 中还提供了检测脚防抖：插卡时飞行模式切换、等待驻网；拔卡时进入飞行模式。

### 4.2 SVN2 的限制

- `sim_hotplug.lua` 在 SVN2 `main.lua` 中被注释掉：`--require "sim_hotplug"`。因此文件存在不等于运行时启用；
- 网络模块没有当前正式版本的完整 `status()`、`ready()`、`ip_ready()`、`generation()` 状态接口；
- 旧 MQTT/SIP 任务对 SIM_LOST/IP_LOSE 的会话清理和迟到回调隔离较弱；
- MQTT 主要依赖 `socket.adapter`，无法单独证明 SIM 已就绪、蜂窝 IP 属于当前会话；
- 看门狗能触发软件重启，但不能替代网络注册、IP、MQTT、SIP 各自的验收证据。

### 4.3 当前正式版本

当前正式 `netdrv_device.lua` 维护：

```lua
M.status()       -- SIM 状态
M.ready()        -- SIM 是否 RDY
M.ip_ready()     -- SIM RDY 且 IP_READY
M.generation()   -- 网络会话代次
```

并对以下事件做统一处理：

- `SIM_LOST`、`SIM_PIN`：清理网络可用状态并提升代次；
- `IP_READY`：只接受蜂窝适配器对应的 IP；
- `IP_LOSE`：清除 IP 并提升代次；
- 网络状态变化：统一发布给 MQTT、SIP 等业务模块。

当前正式 MQTT 仍需等待正式网络状态后连接，并已有 SIM 丢失时主动关闭旧 MQTT 会话的逻辑。该设计比 SVN2 更适合作为正式基础。

## 5. “实际测试过”证据核查

### 5.1 SVN2 目录能证明什么

可以证明：

- 代码文件存在；
- SIP、MQTT、网络看门狗、SIM 热插拔设计曾被写入该目录；
- 代码中有 `IP_READY`、MQTT conack/disconnect、SIP 注册/拨号等事件处理；
- `uart_app.lua` 中写有“原始版本已验证可正常通信”等开发注释。

不能证明：

- 目标 SIM 已成功注册；
- 已获得有效蜂窝 IP；
- MQTT 已在目标服务器完成认证、订阅和长时间心跳；
- SIP 已完成注册、呼出、接听、双向语音和挂断；
- SIM 拔插后业务可以稳定恢复；
- 该目录的源码和底包就是实际下载到当前板子的版本。

本次对 SVN2 递归检查只发现源码、`README.md` 和引脚配置文件，没有发现上述测试的原始串口日志、抓包、录音、服务器回执或验收表。

### 5.2 当前正式目录已有证据

当前正式目录存在历史串口和网络相关日志，例如：

- `logs/cat1_manual_key_boot_attempt_20261014.txt` 中有 MQTT 环境连接/订阅输出；
- `logs/cat1_after_manual_key_com26_20261014.txt` 中出现 `CSQ: 99`；
- `logs/cat1_sim_20261009/` 中有 `CSQ=99,99` 的 SIM/网络探测记录；
- `logs/cat1_redownload_20261010/` 中有 LTE 状态输出；
- UART/DL32 目录有串口帧级测试记录。

这些证据可支持“串口链路、部分 CAT1 事件和测试流程被观察过”，但目前仍不能单独升级为“SIM 注册、稳定 IP、MQTT 长连、SIP 真实通话均已验收”。特别是 `CSQ=99` 表示当前记录中信号值不可用，必须结合 `CPIN?`、`CEREG?`/模块状态、IP 地址和 MQTT/SIP 服务端结果继续判断。

## 6. 可借鉴内容与禁止直接合并内容

### 可借鉴

- SIP 命令和事件命名的整体结构；
- `exsip` 回调到业务状态机的组织方式；
- `SIM_DET_CHANGE` 的中断只记录、任务中执行耗时切换的思路；
- MQTT 连接、订阅、断开、重连和看门狗的分层结构；
- 低频统计输出，避免高频日志影响 GR5526/CAT1 通信。

### 不应直接合并

- SVN2 的 SIP/MQTT 账号、密码、服务器地址和测试凭据；
- SVN2 的 `.soc` 底包或任何历史发布包；
- SVN2 未启用的 `sim_hotplug.lua`；
- 只基于 `socket.adapter` 的旧 SIP/MQTT 等待逻辑；
- 任何没有对应正式硬件引脚、原理图和官方 Air780EGH API 依据的 GPIO/检测脚配置。

## 7. 建议的现场验证顺序

按证据层级逐步执行，不把前一步结果替代后一步：

1. **模块与 SIM**：记录 Air780EGH 固件版本、`CPIN?`、ICCID/IMSI（脱敏）、`CSQ`、`CEREG?`/驻网状态。
2. **数据链路**：记录 `IP_READY`、适配器、IP 地址、DNS 和一次 TCP/HTTPS 可达性。
3. **MQTT**：记录 TLS 建连、认证、订阅、发布回执、心跳保持至少一个稳定周期，以及断网后重连。
4. **SIM 热插拔**：记录检测脚电平、`SIM_LOST`、IP_LOSE、MQTT 关闭，重新插卡后的重新驻网和重新订阅。
5. **SIP**：在 IP_READY 后记录 SIP 注册成功、呼出/来电、接听、双向音频、挂断、SIP_DEINIT，再做断网/掉卡恢复。
6. **GR 联调**：确认 GR 只根据明确的 `NET_ENV`、`MQTT_ENV`、`SIP_ENV` 事件推进状态，不把 UART 收到 TX 或单个 BUSY 日志当作网络/通话成功。

## 8. 最终判断

目前不能说 SVN2 的“上网和 SIP 已实际测试通过”；更准确的表述是：**SVN2 提供了一套较完整的参考实现，但缺少可审计实测证据。当前正式 Air780EGH 已在网络状态隔离、SIM/IP 丢失恢复和 SIP 音频资源释放方面改进，应该继续以正式目录为唯一开发输入，并按上面的分层现场流程补齐真实网络和通话验收。**

本轮未修改任何固件源码、底包、工程配置或设备状态。
