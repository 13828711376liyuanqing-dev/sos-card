# YP001 姓名生僻字动态字库方案可行性评估

- 日期：2026-10-19（北京时间）
- 范围：后台经 Air780EGH CAT1 将居民姓名及缺失字形传给 GR5526，并在 LVGL/DEPG0150 上显示。
- 结论：**技术上可实现，整体难度中等偏高；建议采用按需补充、设备端缓存的字形方案。**当前结论是方案评估，不表示协议、固件、后台或实板功能已完成。

## 1. 需求理解

设备保留常用中文字体，姓名中未包含在本地字体里的偏僻字由后台提供字形。CAT1 负责蜂窝网络下载与串口转发，GR5526 负责协议校验、持久化和 LVGL 显示。字形应缓存于设备，正常显示不依赖每次实时联网。

## 2. 项目现状与依据

| 项目 | 当前依据 | 对本方案的影响 |
|---|---|---|
| 显示硬件 | YP001 使用 200×200 黑白 DEPG0150 电子纸 | 字体和布局按黑白像素显示评估；字形补丁可使用 1 bit/像素 |
| GUI | 当前工程使用 LVGL 8.3.1 | 可通过字形描述/位图回调接入动态字形，需兼容当前 LVGL 配置及绘制路径 |
| 本地字体 | 工程内有 16/24/28/32/40 px 中文字体源，字体文件头列出有限的字符范围 | 已有常用字基础，但并非完整汉字库；不能假设任意姓名都能显示 |
| 缺字处理 | `epaper_ui.c` 的 `safe_text()` 检查字形，不支持时返回 `"--"` | 当前有缺字保护；动态字形尚未接入 |
| 客户要求 | 软件要求 F-021：平台下发居民姓名/房号并显示 | 具体线上字段未定义，见冲突 C-06；不应自行创造正式消息字段 |
| CAT1链路 | CAT1 与 GR5526 通过 UART4 通信；CAT1 是网络侧，GR5526 是应用主控 | 需要定义 CAT1 下载结果到 GR 的可靠分包/确认接口 |
| 数据保护 | 居民资料属于 OTA 保护数据 | 字形缓存和姓名均不得被 OTA、回退或恢复流程覆盖、清空或丢失 |

## 3. 推荐架构

1. **姓名下发：**后台下发姓名及版本/编码信息。设备以本地字体逐字检查覆盖情况。
2. **缺字请求/补充：**对本地缺失字符请求对应字号的字形数据。由后台生成或从后台字形服务取得；每个字形包含 Unicode 码点、宽高、行跨度、位深、数据长度、版本和完整性校验。
3. **CAT1传输：**CAT1 将字形数据按有界大小分包转发给 GR5526；每包带事务标识、序号和校验，支持确认、超时重传和失败结束。
4. **GR暂存与验证：**GR 将新数据写入独立暂存区，验证字符、尺寸、长度、总量、版本及校验值。完整验证成功后才提交为活动缓存，避免断电留下半份数据。
5. **LVGL查找：**动态字体适配层优先查本地字体，未命中时查已提交的动态字形缓存；仍未命中时显示约定的备用文本/替代符号，不得显示旧姓名或虚报成功。
6. **显示刷新：**姓名数据或字形版本改变后更新标签并请求电子纸刷新。刷新必须遵循现有显示调度，不能长时间阻塞报警、按键和通话事件处理。

```text
后台字形服务 -> Air780EGH CAT1 -> UART4分包 -> GR5526校验/暂存/提交
                                                   |
                                                   v
                                   LVGL：本地常用字 -> 动态字形缓存
                                                   |
                                                   v
                                          DEPG0150电子纸
```

## 4. 容量与实现难度

按 1 bit/像素、无压缩估算：

| 字形尺寸 | 单行字节数 | 单字位图约占用 |
|---|---:|---:|
| 24×24 | 3 字节 | 72 字节 |
| 32×32 | 4 字节 | 128 字节 |
| 40×40 | 5 字节 | 200 字节 |

以上只计位图，不含索引、版本、校验及存储对齐开销。只缓存姓名中少量缺字时通常是可控规模。正式容量不能仅凭该估算确定：需核对 GR5526 可用非易失存储、现有 NVDS/LFS 使用和保留区，并遵守用户数据保护要求；不得自行移动链接地址或占用未知区域。

| 子项 | 难度 | 主要工作 |
|---|---|---|
| 字形格式与后台输出 | 中高 | 字体授权/来源、字号、码点、点阵方向、行对齐、版本和服务接口 |
| CAT1到GR传输 | 中 | 分包、背压、确认、重试、超时、复位恢复及并发串口业务协调 |
| GR持久化与原子切换 | 高 | 预留空间审计、耐久性、掉电保护、坏块/写失败处理、版本回退 |
| LVGL动态字体适配 | 中高 | 适配字形查找接口、字宽/偏移度量、多字体混排与内存生命周期 |
| 电子纸与业务调度 | 中高 | 刷新耗时、姓名变更时机、报警优先级及真实屏幕可读性验证 |
| 端到端联调 | 中高 | 后台、CAT1、GR、LVGL、跨重启缓存和故障注入共同验证 |

## 5. 关键风险与控制

- **后台能力是前置条件：**客户/平台需确认能按 Unicode 字符及指定字号生成并提供字形数据。若只能下发文字而无字体服务，偏僻字仍无法显示。
- **协议未冻结：**F-021 的姓名/房号字段在 C-06 中标记未定义。先冻结字段、字符编码、缺字查询和应答语义；不得把内部测试包当正式线上协议。
- **字体许可：**确认后台生成所用字体及其嵌入/转换/下发授权，留存字体来源和许可条件。
- **输入安全：**限制码点范围、字形尺寸、单字/总字节数、版本和写入次数；拒绝越界、重复冲突或校验错误数据。
- **掉电和写入安全：**下载期间继续显示旧的有效姓名/字形；仅在整批验证完成后原子切换。不得因字库更新格式化或覆盖其他用户数据。
- **数据一致性：**姓名和字形应绑定版本/校验关系；防止新姓名搭配旧字形或旧缓存被错误当作新版本。
- **空间与寿命：**核实存储余量、擦写粒度和寿命；设计缓存上限及可控替换策略，不能任意清除仍被当前姓名引用的字形。
- **显示和调度：**电子纸是黑白显示，需确认偏旁细节在最终字号下清晰；屏幕刷新不得影响报警及时性。
- **隐私：**居民姓名及其缓存按用户数据保护。日志不得输出不必要的完整姓名或后台鉴权信息。

## 6. 建议实施阶段

1. **需求冻结：**客户确认姓名字段、编码（建议 Unicode/UTF-8）、字号、最大姓名长度、单次最多缺字数、后台字形接口、失败显示规则和隐私要求。
2. **存储审计：**分别检查主工程及交付副本的实际 Flash/NVDS/LFS 使用和链接布局，给出可用容量依据；未经确认不更改布局。
3. **格式原型：**先用一个常用字和一个代表性偏僻字生成定尺寸 1-bit 字形，在主机侧核对码点、点阵方向、stride、宽度和基线。
4. **设备最小闭环：**通过测试桩传入单个字形，GR 校验并保存，重启后 LVGL 显示；保留本地字体优先查找和失败回退。
5. **传输与恢复：**加入 CAT1 UART 分包、确认/重试、超时、断链和断电中断恢复；验证旧缓存不被半包覆盖。
6. **后台联调和验收：**接入正式服务，覆盖常用字/缺字/混排/多字/超长输入/坏包/重复包/存储满/断电/跨重启，并在实际电子纸上检查清晰度和刷新时间。

## 7. 验收条件

- 已冻结的后台字段和字形协议与平台联调一致；后台能够返回请求字符的合法字形。
- 常用字继续由本地字体显示；缺字能下载、校验、保存，并在姓名中正确混排显示。
- 首次下载完成后断网重启，已缓存姓名和字形仍可显示。
- 断链、超时、坏包、写入失败、存储满或掉电不会破坏之前有效的姓名/字形；失败状态有可识别的回退显示。
- 已缓存字形版本与姓名版本一致；替换/清理策略不会删掉当前有效姓名所需字符。
- 报警、按键和通话事件在字形下载及电子纸刷新期间仍能按产品要求处理。
- 主工程与交付副本分别完成构建和协议/屏幕验收；实板显示、跨重启和故障恢复各自留有证据。

## 8. 当前结论及待客户确认项

方案可行，建议采用“**常用字固化在本地 + 后台按需下发缺字点阵 + GR5526 校验并缓存**”。当前无法承诺具体存储上限或工期，因为尚未冻结后台字形服务、姓名协议字段和最终字号/容量预算。进入实现前需确认：

1. 后台是否支持提供指定 Unicode 字符的字形点阵，还是需要新增字形生成服务？
2. 姓名字号、最大长度、最大缺字数以及只要求显示姓名还是也需要房号？
3. 缺字下载失败时，客户接受显示替代符号、拼音/问号，还是保留姓名并提示缺字？
4. 字形缓存是否需要跨绑定/解绑保留，及其清理授权规则是什么？
