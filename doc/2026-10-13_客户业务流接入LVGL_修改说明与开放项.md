# 客户业务流接入 LVGL：修改说明与开放项

日期：2026-10-13，北京时间。修改人：SAM。

后续按用户要求逐项修复：CAT1快速重启的电量补同步、接听/挂断ERROR反馈。最新改动及验证见 [业务逐项修复记录](2026-10-13_业务逐项修复记录.md)；下文原始日志/产物哈希保留为前一轮历史记录。

## 结论与边界

本轮将真实按键、电池、CAT1 串口状态与六页 LVGL 接通，并增加 CAT1 报警/通话/消息持久化服务。**尚未完成客户 F-001～F-033 全部功能，不是可直接量产的完整业务固件。** 以下逐项列出实现、接口与未实现内容；源码、主机测试、编译和实板验收分别记录。

主工程是 `ble_app_uart_c/Keil_6/YP001_GR5526.uvprojx`，交付副本是 `SVN交付_YP001_GR5526_20261001/ble_app_uart_c/Keil_6/YP001_GR5526.uvprojx`，目标均为 `YP001_GR5526_AC6`。CAT1 仅使用 `Air780EGH`，未读取或合并旧 `cat_1` 项目。

## 实际运行链与修改

| 文件/函数 | 修改前 | 修改后/原因 |
|---|---|---|
| `Src/user/business/yp001_business.{c,h}` | 没有统一的产品显示状态 | GR 保存报警、通话、网络、信号、电池、NTP 时间、居民资料有效性；区分未知、受理、拨号、接通、结束及平台确认 |

| `Src/platform/bsp.c` / battery_display_poll | 六页除电池外主要是模板；无变化也周期刷屏 | 实际ADC/充电状态进入业务模型；状态或页面变化才刷屏，失败保留重试；传感器采样保持独立节拍，不把无数据当静止 |

| `Src/external/lvgl_8.3.1/lv_conf.h`、两份Keil源清单 | QR功能关闭，图像为固定样例 | 开启LVGL QR编码器，仅有效15位IMEI生成二维码；沿原116×116区域保留白边；增加qrcodegen与business源文件，不改链接/下载配置 |
| `Air780EGH/business_core.lua` | 没有客户业务持久状态机 | 持久报警身份、单次拨号资格、应用确认/超时重报、上线消息、电话绑定与低电候选消息；不确定能力明确拒绝 |
| `Air780EGH/business_store.lua` | 没有独立业务记录 | 两个独立文件、代次、CRC、写入读回核验；损坏时拒绝继续，不格式化，不用旧快照覆盖最新合法数据 |
| `Air780EGH/business_runtime.lua` | 实际模块事件未供GR显示 | 接真实IMEI、CSQ、SIM/IP/MQTT、NTP、SIP事件；hello重新同步状态，恢复丢失的挂断事件；拨号错误不能被显示为拨号中 |
| `Air780EGH/main.lua`、`uart_app.lua`、MQTT相关模块 | 业务与旧演示转发并存 | 注册内部业务服务；保留OTA路径；只有正确下行订阅确认才就绪；处理未知下行转发边界，避免CRLF伪造内部串口帧；日志不输出业务凭据/完整payload |

内部串口 `BUS_CMD`/`BUS_EVT` 仅是两端代码接口，不新增任何客户平台 MsgType。`hello` 的持久状态不明时不能回“报警已取消”。发送成功、Broker PUBACK、平台应用确认分别处理。

## 本地验收入口

- `business status`：读取实际业务状态与失败原因。
- `business cancel`：明确的本地调试取消入口，等待CAT持久确认；不是新增客户按键手势，也不是平台取消协议。
- `business time on` / `business time off`：本轮RAM级显示开关。
- `epd_page screen` 等保留页面选择入口，但报警/通话/低电等真实状态具有优先级；进入页面不会制造通话或报警事件。

界面部分状态暂用可验证字库中的英文/数字及代码提示，避免缺字伪显示。二维码主机编码和像素测试不等于实际墨水屏扫码成功。
