# 整机基线与 OTA 升级：工具使用说明（流水线）

SAM | 2026-11-10 | 读者：做固件的同事、测试人员 | 工具：`YP001_工具包`（2026.11.10-2）

例子：先把 **1.5.24** 烧到板子上做基线，再做 **1.5.25** 的 OTA 升级包推送。

> **前提（很重要）**：板子上的固件必须带有 2026-11-10 起的"出厂即可接收 OTA"代码（CAT1 的 `ota_trial.lua`、`ota_manager.lua` 等已按新规则改过）。更早的固件里写死了升级范围，烧到板子上也收不了 OTA（会报 `REJECTED HTTP_NATIVE_CONTRACT`）。
> **验收状态**：代码和工具已改完，主机测试通过；**"同一块板连续两次 OTA"的真机验收还没做**，做完之前请把这份流程当作待验证。

## 开始之前（一次性准备）

| 要有 | 说明 |
|---|---|
| 工具包 | `YP001_工具包`，整个文件夹放在一起用 |
| 工程目录 | 本说明里写的 `D:\CODEX\sos-card` 是我们的工程目录；**要用带"出厂即可接收 OTA"新代码的那份工程**，不要选还没合并的旧工程（比如同事的 `D:\123\YP01`，里面还是旧 OTA 代码） |
| Keil | 打开 GR 工程，**只用 F7 增量编译，不要 Rebuild**；编完不要再打开 Keil |
| J-Link | 装在默认位置，接好板子的 SWD |
| Luatools | 刷 CAT1 用 |
| 私钥 | 签名用的私钥文件（`.key`），向项目负责人要，**不要外传** |
| 串口 | GR 命令口，号码会变，**以设备管理器为准**；CAT1 的三个口留给 Luatools，别的软件不要占 |

---

## 第一部分：搭建板子基线（把 1.5.24 烧到板子上）

### 第 1 步　4 号工具：把版本改成 1.5.24
打开 `4_固件版本与空间\YpVersionTool.exe`。
- GR 版本头文件：点"选择…"，选 `D:\CODEX\sos-card\ble_app_uart_c\Src\config\yp001_fw_version.h`（路径里的 `D:\CODEX\sos-card` 换成你自己的工程目录）
- CAT1 main.lua：点"选择…"，选 `D:\CODEX\sos-card\Air780EGH\main.lua`
- 新版本：`1.5.24`；构建号：留空（自动）
- 点"修改两个固件的版本"

**输出**：两个文件的版本和构建号被改成同一个，改前的文件备份在 `logs\firmware_versions\`。**看到绿色"结果：通过"才算成功。**

### 第 2 步　Keil：编译 GR
按 **F7**。得到 `…\Objects\YP001_GR5526.hex`。

**检查**：回到 4 号工具，"检查空间"里选这个 hex 和 CAT1 源码目录，点"检查两个固件的空间"。要看到：固件里的版本标记是 **1.5.24**，GR 签名镜像没有超过红线 393216。

### 第 3 步　2 号工具：给 GR 签名
打开 `2_GR5526固件检查签名\Gr5526Tool.exe`。
- 固件文件：第 2 步的 `YP001_GR5526.hex`
- 期望版本：`1.5.24`
- 私钥文件：你的 `.key`
- 输出目录：新建一个文件夹
- 点"检查并签名"

**输出**：`GR5526_1.5.24_bNN_signed.bin`（给下一步烧录用）。

### 第 4 步　GR_JLink_Flash_Tool：烧 GR
打开 `GR_JLink_Flash_Tool\GrJLinkFlash.exe`（先关掉 Keil 调试和占用 GR 串口的软件）。
- 选第 3 步的 `signed.bin`
- 串口：选 GR 命令口
- 点"开始烧录"，等 1~2 分钟

**输出**：弹出"烧录完成，核对全部通过"。
**注意**：默认会清空板上的姓名、房号、园区（出厂清空），等后台重新下发；只有台架要保留姓名时才取消勾选。

### 第 5 步　1 号工具：生成 CAT1 刷机目录
打开 `1_CAT1刷机目录生成\Cat1UsbImport.exe`。
- 源码目录：`D:\CODEX\sos-card\Air780EGH`（要和第 1 步改过版本的是同一份）
- 输出位置：选一个空文件夹
- 点"检查并生成"

**输出**：输出位置下的 `USB_IMPORT` 文件夹。**看到绿色"结果：通过"。**

### 第 6 步　Luatools：烧 CAT1
- 先点"**删除全部**"，再添加 `USB_IMPORT` 文件夹，点烧录
- 平时保留 FS/KV；只有要清掉设备上的 OTA 状态时，才同时勾"清除KV分区"和"清除FS分区"（会丢绑定号码等，要后台重新下发）

### 第 7 步　确认板子是 1.5.24
GR 命令口发 `fw_version`，应显示 `001.005.024`；CAT1 在线。

**到这里：板子基线 = 1.5.24，不需要再刷任何东西。**

---

## 第二部分：做 1.5.25 的 OTA 升级包（板子不用动）

### 第 1 步　4 号工具：版本改成 1.5.25
和基线第 1 步一样，新版本填 `1.5.25`，构建号留空（自动加 1）。
**注意**：不允许版本倒退，构建号必须比 1.5.24 的大。

### 第 2 步　Keil：F7 编译 GR
得到新的 `YP001_GR5526.hex`。检查版本标记是 1.5.25。

### 第 3 步　2 号工具：给 GR 签名
期望版本 `1.5.25`，其余同基线第 3 步。**输出**：`GR5526_1.5.25_bNN_signed.bin`。

### 第 4 步　读设备版本和 CAT1 可用空间
板子上电、CAT1 已启动。在 4 号工具的"读设备 CAT1 可用空间"里选 GR 命令口（列表里已经去掉了 CAT1 的口）：
- 点"**读设备版本**"，**输出**：设备 GR 当前版本，**记下它，第 5 步的"源版本"就填它**（填错的包设备会拒绝）；
- 点"读取设备可用空间"，**输出**：一行"CAT1 可用空间 = … 字节"，**记下这个数**（不要估算、不要把门槛当实际值）。

### 第 5 步　3 号工具：生成 CAT1 包
打开 `3_整机OTA打包\YpOtaPack.exe`，先填这几项：
- 私钥文件：你的 `.key`
- 工作文件夹：新建一个文件夹（每次升级用新的，例如 `ota_1.5.25`）
- GR 签名镜像：第 3 步的 `signed.bin`
- CAT1 源码目录：`D:\CODEX\sos-card\Air780EGH`（版本是 1.5.25）
- 源版本：`1.5.24`（设备现在的版本）
- CAT1 可用空间：第 4 步记下的数

点"**① 生成CAT1包**"。**输出**：工作文件夹里出现 `CAT1_….sota` 和 `review.json`。

### 第 6 步　3 号工具：生成授权文件
- 勾上"已完成激活评审"和"GR Boot 已实板验证"两个确认框（**这是人的判断，工具不替你勾**）
- 点"**② 生成授权文件**"

**输出**：`ota_authorization.json`，范围 1.5.24 → 1.5.25。

### 第 7 步　3 号工具：检查并打包
点"**③ 检查并打包**"，再点"**④ 验证压缩包**"。
**输出**：`YP001_1.5.24---1.5.25_FIRST.zip`，报告里有 **整包 MD5**，**记下它**。验证要通过。

### 第 8 步　上传平台
把 zip 上传平台，用 MD5 核对，得到下载地址。

### 第 9 步　后台推送
在后台对这台设备推送 1.5.25（推送对象填设备 IMEI）。设备要在线、电量够。

### 第 10 步　等它升完
大约 15~20 分钟。**期间不要按键、不要碰板子、不要拔 USB。**
升完后 GR 命令口发 `fw_version`，应显示 `001.005.025`。

**到这里：板子从 1.5.24 升到 1.5.25，没有刷任何接收端。**

---

## 第三部分：再升 1.5.26
把第二部分里的 1.5.25 换成 1.5.26，**源版本换成 1.5.25**，重复第 1~10 步。板子不重刷。

## 要记住的规则

- 升级包只认它的**源版本**：设备在 1.5.24，就要用"1.5.24 → 1.5.25"的包；设备在 1.5.23，要另打一个"1.5.23 → 1.5.25"的包。
- 两个固件（GR 和 CAT1）的版本、构建号永远一起改，只用 4 号工具改，不要手改。
- 改过源码就要重新 F7，再签名、再打包；不能拿旧的 hex 去签。
- 私钥只在签名和打包时选择，不放在工具包里，不外传。

## 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 4 号工具提示"不允许版本倒退"或构建号不对 | 新版本比当前低，或构建号没比旧的大 | 版本和构建号都要更高 |
| 2 号工具"版本与期望不符" | 忘了重新 F7，或选了旧 hex | 重新 F7 再签名 |
| GR 签名镜像超过红线 393216 | GR 固件太大，整机 OTA 时 CAT1 放不下 | 先减小固件，再签名 |
| 3 号工具"CAT1 可用空间不够" | 设备上历史数据多 | 先读真实空间；不够时在 4 号工具里"清理 OTA 历史"（会写设备文件，要确认） |
| 3 号工具"VERSION 与 PRODUCT_VERSION 不符" | 版本没用 4 号工具改对 | 用 4 号工具重新改一次 |
| 设备回 `REJECTED HTTP_NATIVE_CONTRACT` | 板子上是**旧固件**（带写死的升级范围） | 按第一部分用新代码重新烧一次基线 |
| 推送后设备没反应 | CAT1 被 GR 空闲关电，或没在线 | 板子上电、等 CAT1 起来再推送 |
| 串口被占用 | 另一个软件占着 | 关掉它；CAT1 的三个口留给 Luatools |

## 这条流水线用到的工具

| 步骤 | 工具 | 干什么 |
|---|---|---|
| 改版本 | 4 号 YpVersionTool | 两个固件一起改版本和构建号 |
| 编译 | Keil F7 | 生成 GR 的 hex |
| 签名 | 2 号 Gr5526Tool | 检查并给 GR 签名 |
| 烧 GR | GR_JLink_Flash_Tool | 有线烧签名后的 GR（只在做基线时） |
| 烧 CAT1 | 1 号 Cat1UsbImport + Luatools | 生成 USB_IMPORT 再刷（只在做基线时） |
| 读空间 | 4 号 YpVersionTool | 读设备 CAT1 可用空间 |
| 打包 | 3 号 YpOtaPack | 生成 CAT1 包、授权、整机升级包 |
| 上传、推送 | 平台后台 | 上传 zip，对设备推送 |

## 推送前、推送后各一条命令（给我们自己人用，不装工具包也能用）

```
# 推送前：包名/范围、平台文件是否一致、设备版本是否等于包的源版本、空间够不够
python tools/ota/bench/ota_check.py pre --zip <包.zip> --url "<平台下载地址>"
# 推送时：一条命令开保电、信标日志和 owner 监控，只输出阶段变化和异常
python tools/ota/bench/ota_run_monitor.py --round logs/<本轮目录>
# 升完后：两端版本、OTA 状态、owner、Boot 一张表
python tools/ota/bench/ota_check.py post --target <目标版本>
```
都要求 GR 命令口没被别的程序占用（`ota_run_monitor.py` 自己会启动保电，推送前别再开一个）。
