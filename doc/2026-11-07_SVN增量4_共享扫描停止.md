# SVN增量4 共享扫描停止

SAM | 2026-11-07 +08:00 | 以7d30b25及用户确认的b21本地页面验收范围为基础。候选1.5.18/b22，针对性主机回归通过，等待原工程F7。

## 来源与范围

同事 `D:/SVN/ble_app_uart_c/Src/user/yp001_scan_sched.c` 在stop_scan恢复调用ble_scanner_stop。共同起点和三方清单复用此前已核验的归档及审查记录。

需求F-005/F-006/F-011涉及运动扫描、静止和功耗，F-001要求SOS优先。当前扫描器被周期定位、LocaSvr SOS/找人取位、手动CLI共用。SDK1.0.4的ble_scanner_start/stop直接调用GAP接口，停止请求返回成功后仍需BLE_GAPM_EVT_SCAN_STOP确认。

## 实际适配

| 文件或入口 | 改动 |
|---|---|
| yp001_scan_sched.c / stop_scan | 普通窗口结束发出真实SDK停止请求，逻辑窗口、延后请求和控制器停止确认分别记录 |
| yp001_scan_sched.c / start_scan | 控制器停止事件到达前等待，避免异步停止与下一轮启动相撞 |
| yp001_scan_sched.c / radio_hold、radio_restart_poll | 定位与手动扫描用独立占用位，延后的停止在占用释放后处理，停止途中接管则在真实停止事件后由前台恢复扫描 |
| cat1svr.c / LocaSvr_BeaconProcess | 进入SOS/找人取位前取得占用，每次退出释放，覆盖取消路径 |
| user_app.c / ble_scan及BLE事件 | 手动start先登记请求，再调用SDK；stop释放请求，真实扫描停止事件解除等待屏障 |
| yp001_scan_sched.h | 两类占用常量和两个接口声明 |

周期停止遇到报警、手机BLE连接或其他占用时让出扫描器。占用位跨周期调度器重新初始化保留，避免CAT1再次上电时抹掉其他使用方的占用。BLE回调只更新标记，恢复扫描的SDK调用由前台poll执行。

0x0F仍按SDK拒绝记录。手动start遇此返回时保留的是人工扫描请求，不能据此记为控制器已开始扫描。停止返回拒绝会记录失败并结束本次请求，避免每30ms重复提交。成功停止请求等待真实事件，失败或缺失的停止事件维持起扫屏障，需后续真实成功停止事件解除。

## 针对性验证

`python tools/business/test_scan_stop_shared.py --label red` 在原生产stop_scan上编译成功，因未调用真实停止接口的运行断言失败。`scan_stop/red` 保存生成编译单元和原始结果。

适配后专项提取生产start_scan、stop_scan、占用、停止回调、前台恢复函数及真实cmd_ble_scan，编译并调用实际C函数。最终 `--label final` 通过，覆盖正常禁用、重复停止、两种占用及同时占用、报警和手机连接保护、占用释放后的停止、失败事件保持等待、真实成功事件解除等待、停止中禁止起扫、停止途中接管后恢复、接管提前结束时取消恢复、SDK拒绝和无请求洪泛。

审查另发现手动start若在SDK返回之后才登记占用，停止回调可能在SDK调用期间到达，导致漏恢复。增加事件交错用例先得到 `manual_race_red` 运行失败，改为调用SDK之前取得占用后最终通过。

另跑现有 `python tools/business/test_sos_qp_states.py` 通过，覆盖队列准入、重复启动、取消和重新启动。其他已验证且未触及的单键、业务JSON及OTA专项复用原证据。

主机桩替代SDK和中断时序，支持逻辑及交错场景回归。控制器真实启停、SOS取位、手机连接、手动接管及整机功耗均待b22实板。原程序对扫描启动0x0F的处理和现有BLE_SCAN_TEST样本逻辑继续作为已有待审项，不能因此认证定位数据或功耗。
