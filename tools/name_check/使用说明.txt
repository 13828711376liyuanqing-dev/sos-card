姓名字库文件核对  NameCheck.exe  v1.0 使用说明
==============================================

SAM | 2026-11-04

一、这个工具做什么
  核对后台生成的姓名字库文件 residentNameMsg_<姓名>.json 能不能下发给设备，并生成一份"逐段说明"（Markdown），
  写清时间戳、每个字段、每个字形和结论，可以直接发给后台。

二、规则（2026-11-04 确认）
  - 姓名、房号、园区全部由后台下发，设备出厂本地不留，只留存放空间。
  - 时间戳是 Seq 字段 = 生成文件时的当前时间（Unix 秒）；设备只收比上次大的 Seq；早于 2026-01-01 直接判错。
  - 姓名最多显示 5 个字，每个非英文字要有 32px 和 16px 两个字形；园区最多 11 个字，每个非英文字要有 16px 字形；
    不管设备自带字库有没有都要推。
  - 房号只推文字，只能用数字、字母和"号楼栋单元层室"（设备自带 28px 字库）。
  - 每个字形：U 码点、S 字号 16/32、W/H 1..40、点阵长度 = ⌈W/8⌉×H（≤200）、C 是 CRC-16 校验码，设备会重算。
  - 设备存储 = 20 + 每个字形 16 + 点阵 ≤ 4000 字节；字形最多 28 个。

三、用法
  窗口：双击 NameCheck.exe → 选择文件 → 看结论；逐段说明保存在 JSON 同一文件夹，文件名后加 _核对.md。
        "设备上次的 Seq"可选：填了就检查新文件的 Seq 是否更大。
  命令行：NameCheck.exe <文件.json> [--seq-min <设备上次的 Seq>] [--md <说明.md>]
         返回 0 = 可以下发，1 = 不能下发，2 = 找不到文件。

四、和开发电脑上的检查的关系
  规则与 tools/glyph_maker/check_platform_json.py 相同；开发电脑上还会用设备同一套代码模拟收下
  （tools/name_push/run_platform_json.py），这个工具不需要。
