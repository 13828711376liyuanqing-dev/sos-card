本轮直接核对：

- `ble_app_uart_c/Src/user/ota/yp001_ota_port.c`：provisioned=false，load/store/package_ready/completed 等仍拒绝，gates 清零。
- `Air780EGH/ota_platform.lua`：resolve/validate/compare/safe/activate/health 等返回不可用，主题默认不接收。
- `Air780EGH/update.lua`：FOTA_CHECK 拒绝无平台任务/GR授权的请求，能力查询报告 install_enabled=false。
- `tools/ota/boot/yp001_ota_start.h`：checked 入口只选择、认证和检查向量，不执行反初始化或跳转。

所以当前没有可要求用户再次下载的完整 OTA 固件。历史编译/模拟测试不等于本轮实板验收。`libfota2.lua` 开头的 reboot 示例位于注释内，不能把文本命中当作现行自动重启调用链。

## 3. 实施顺序与先后依赖

### 第一批：立即可做，不依赖生产密钥

1. **A1 启动交接适配**：围绕 `yp_boot_select_checked` 增加可注入的交接控制流，检查成功才允许调用反初始化与 SDK 跳转适配；主机验证失败不调用跳转、调用次序、意外返回处理。先核对 SDK `sys_firmware_jump` 和板级外围要求，不能凭参考板代码猜测中断/看门狗交接。生产入口保持禁用。
2. **B1 持久记录故障模型**：先对独立协调双扇区候选后端建立撕裂写、掉电、序号/epoch、双副本损坏测试，再接真实存储。布局未批准时仅主机/隔离构建，不能写 NVDS 或把候选扇区默认为空闲。
3. **C1 厂商激活语义核查**：明确 V2052 的 init/run/file/finish/isDone 哪一步留下自动安装标记、掉电/复位会如何处理，以及取消/失败语义。以准确版本的厂商实现或说明为证，API 存在不能证明安全。无法证实就继续禁用激活。

以上可并行；A1、B1 的候选文件避免重叠。共享头文件或生产适配由主线程统一落地。

### 第二批：接上可信数据与业务条件

4. **D1 包与版本合同**：确认真实签名包、公钥指纹和发布版本映射。GR 当前候选约定 image.size 为正文长度、不含 904 字节尾部；严格解析容器，核对签名实际覆盖的身份/版本/布局字段。没有可信材料时允许拒绝路径测试，不允许假验签通过。
5. **B2 安全条件与串行授权**：真实读取充电、70%电量、稳定静止、报警/通话/用户活动及对端状态，未知即拒绝；GR 持久化授权之后才答复。第二组件不能后台预下载。恢复已提交事务与批准新安装分开处理。
6. **A2 恢复与试运行闭环**：完善交换期间看门狗及耗时核查、空日志的可信首次初始化、失败启动限次回退，再接健康确认。坏向量当前只会拒绝启动，不能写成同次调用自动完成回退。
7. **C2 受控激活与上报**：只有 C1/D1/B2 成立才接厂商激活；持久化实际版本/健康结果后才清对应任务。QoS1 断连补报，不等不存在的平台应用 ACK；保留失败 hash 的限次记录。

### 第三批：部署与验收

8. **E1 受控首次部署**：核对全部用户区、SCA/Boot 安装与恢复方式、原始镜像和精准扇区范围。当前普通主工程下载不等于部署独立 Boot；不能以整片擦除或接受 unsigned 原应用来绕过初始化。
9. **E2 两份生产构建**：确认交付副本无独立冲突后同步本轮变更，分别编译主工程和交付副本，记录新产物哈希/布局。保持 SDK 1.0.4、原 APP_INFO 和既有 Keil 配置。
10. **E3 实板逐项验收**：先 GR 真包完整升级/确认，再试运行失败回退；再独立验证 CAT1 N→N+1；最后验证两端排队、断网/断电及结果补报。每步前后核对用户数据，回退不恢复旧用户快照。

## 4. 统一验收矩阵

| 范围 | 必测项 | 证据层级 |
|---|---|---|
| Boot | 签名错、尾部不足、栈/向量非法、Flash 失败、试运行超次、跳转返回 | 主机故障测试 + 隔离 ARM 构建；真实跳转另验 |
| 持久协调 | 双端同时请求、旧 epoch、记录撕裂、结果落盘前后掉电、坏包重复推送 | 主机断点注入；跨设备重启另验 |
| 业务窗口 | 69/70%、充电未知/拔出、运动/SOS/来电插入、自然休眠恢复 | 自动测试 + 实板业务观测 |
| CAT1 FOTA | 未提交任意复位、真实 N→N+1、下载中断、安装失败、FS/KV 保持 | 精确版本厂商依据 + 实板证据 |
| 数据保护 | 升级期间新写入、回退后最新合法值、维修救援拒绝破坏用户区 | 地址审查 + 主机故障注入 + 实板前后核对 |
| 平台 | 实际版本、接收回执与完成结果区分、QoS1 补报、单组件映射 | 合同确认 + 平台联调 |

现板 SIM 热插拔硬件未完成，软件恢复测试继续保留；真实插拔验收留给下一版硬件，不反复要求现板拔卡。
