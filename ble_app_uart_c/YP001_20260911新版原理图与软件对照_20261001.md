# YP001 2026-09-11 新版原理图与当前软件对照

日期：2026-10-01。对象：`YP001_MB_SCH_A1_20260911.pdf`（3 页）及当前工作区 `ble_app_uart_c/Keil_6/YP001_GR5526.uvprojx`。以 `YP001_MB_SCH_A1_20260909(2).pdf` 为上一版对照。本文是图纸与源码的只读分析；没有修改固件、编译或重新下载。当前工作区已有 10 月 1 日的 LVGL 等改动，不能用 9 月 30 日交接包代替当前源码。

## 核心结论

新版图中可明确核实的电气增量位于**第 3 页 USB-C 插座**：CC1、CC2 各增加一只接地的 **5.1 kΩ 下拉**，分别为 R112、R113。旧图两只 CC 引脚悬空。此修改符合设备作为 USB-C 受电端的连接方式，可改善 C-to-C 线接入时 VBUS 是否被电源端开启的问题；是否已装到现有 PCB，还必须核对 BOM、PCB 版本或断电实测。它不要求改 GR5526 GPIO 映射。

新版图第 1 页的 MCU、充电、CAT1 电源开关、马达和按键，第 2 页的 Air780EGH、SIM、ES8311/功放，第 3 页的 EPD 与 G-sensor 经逐页视觉核对，**未发现需要立即重分配 MCU 管脚的变化**。PDF 版式和文字提取方式也改变了，故不能仅凭文本差异断言所有器件值完全相同；后续仍应由厂方提供正式 ECO/网表/BOM 差异清单。

|---|---|---|

| GR5526 / SWD（图 1） | SWD 仍占 GPIO0/1；`yp001_board_config.h` 保留这些脚外的 UART0 GPIO28/29。 | 与当前下载和日志管脚安排相容。J-Link VTref 不能替代主电源轨测量。 |
| DEPG0150（图 3） | GPIO10→R84→U1005 EN；GPIO24/25 为 BUSY/RESET，GPIO30/31/32/33 为 DATA/CLK/RS/CS。代码在 `yp001_board_config.h` 和 `epaper_depg0150.c` 中一致。 | 用户已确认先前 LOGO/“测试OK”实屏正常。当前源码又在 `BSP_start()` 增加 LVGL 主页全刷，宜单独量化启动时间并验证页面。图块标题“AMOLED”与实际 EPD 连接不一致，建议出图时更名。 |
| Air780EGH（图 1、2） | GPIO6 请求 4G 电源，AON_GPIO0 经 Q4 控 PWRKEY，AON_GPIO2/3 为 UART4。当前 `cat_diag` 可按命令初始化 UART4 收发 AT；`Cat1Svr` 业务 AO 在 `bsp.c` 的 `#if 0` 内。 | 管脚相容；旧实测 AT→OK，但 SIM/注册尚未通过。USB/VBUS 经旁路可能维持模块电源，GPIO6 低不能作为实际断电证据。 |
| ETA69631（图 1） | GPIO4/5 I2C4、AON_GPIO5 中断、GPIO20 NQON；代码有 `eta69631_init()`，只在充电测试入口调用。其初始化默认写入输入 2000 mA、充电 1000 mA、4.2 V 并使能充电。 | 这些值目前不等于量产许可值。新增 5.1 kΩ CC 下拉只声明受电端存在，不能单独证明 USB 电源可持续提供 2 A。 |
| G-sensor（图 3） | GPIO2/3 I2C0、GPIO7 控 U13 的 3.3 V EN、AON_GPIO7 中断。U1104 的 VDD 接开关后的 3.3 V，VDDIO 和 I2C/INT 上拉接 1.8 V。代码按 DA221、地址 `0x27`、ID `0x13` 判断。 | 旧实测读 ID 为 0。应先确认 U1104 实装型号和 U13 IN/EN/OUT，再核 I2C 地址/ID。VDD 关断而 VDDIO 与上拉仍在时，需依器件手册核对允许的上电顺序和漏电。 |

| ES8311 / 功放（图 2） | Codec 的 I2C/I2S、音频电源和 PA 使能在 Air780 一侧；GR5526 当前源码无直接驱动这条音频链的主控职责。 | 功放调试应同时检查 Air780 固件配置、VDD_PA、PA_EN、I2S 时钟和喇叭输出，不宜仅在 GR5526 侧添加寄存器配置。 |

## 优先建议

| 优先级 | 建议与依据 | 最小验证动作 |
|---|---|---|
| P0 硬件版本 | 把 R112/R113 两只 5.1 kΩ 纳入新版 BOM/装配检验，并在图纸标题栏填写明确版本和 ECO。现有文件名是 09-11，但标题栏 Version/Date 留空。 | 板子断电测 CC1、CC2 对地各约 5.1 kΩ；A-to-C 与 C-to-C 插入后记录 VBUS/`5V+`/`VCC_SYS`。对老板区分是否补装，避免把供电差异误判为固件问题。 |
| P0 软件稳定性 | `Keil_6/README_YP001_Keil_V6.md` 记录 `ble_scanner_start()` 在 YP001 触发 INVSTATE HardFault，因此启动扫描被关闭；但 `user_app.c` 的 `app_disconnected_handler()` 仍直接调用它。这个路径在断线后可再次触发同一故障。 | 在查清 HardFault 的调用上下文、堆栈和 SDK 状态前，统一门控所有扫描入口；连接/断线循环实测后再启用。主页应区分“BLE 栈初始化成功”和“扫描可用”。 |
| P1 供电/充电 | 根据电池容量、热设计、USB 输入能力设定 ETA69631 的输入/充电限流。当前 `eta69631_init()` 默认 2 A 输入、1 A 充电、4.2 V，且会使能充电。 | 先只读 IC ID/状态/故障；核电池规格与 USB 源能力后再按模式写入参数，测 VBUS、VCC_SYS、BAT 和温升。没有 USB-C 电流能力检测时，勿从 R112/R113 推导 2 A 可用。 |
| P1 传感器 | 当前 U1104 料号在图纸上不明确，而软件严格按 DA221 ID `0x13` 判断；旧日志读 ID 失败。 | 核 BOM/器件丝印，再按 U13 IN/EN/OUT→VDD/VDDIO→SCL/SDA 波形→地址/ID 的顺序查。核实 3.3 V VDD 与常在 1.8 V VDDIO 的时序条件。 |
| P1 开机体验 | `BSP_init()`先全刷 LOGO，`BSP_start()` 在 BLE init 后又全刷 LVGL 主页；两次 5000 字节写入与 BUSY 等待都在 QP 正式运行前。 | 在 UART0 分别记录供电→LOGO、LOGO→主页、主页→事件循环的耗时与失败原因；按产品需求决定保留双刷还是一次呈现最终画面。保持已实测成功的屏幕管脚和像素映射。 |
| P1 CAT1 业务 | 区分 GPIO6 的电源请求状态与 Air780 实际 VBAT/`RDY` 状态；旧 AT 日志曾显示 SIM 错误和未注册，`Cat1Svr` 当前未启动。 | 在有、无 USB 两种供电下测模块 VBAT 和 PWRKEY/RDY，插 SIM 后按 `CPIN→CSQ→CEREG` 顺序复测，再评估启用业务 AO 的缓冲、队列和超时。 |
| P2 音频/马达 | 按图 2 的 Air780→ES8311→U5 功放链和图 1 的 AW86233 独立制定验收表。 | 音频测 I2S 时钟/数据、PA 电源/使能及喇叭；马达测 I2C3 读 ID、RESET、INT 和实际振动。只凭源代码或图纸不报“功能正常”。 |

## 建议的改进顺序

1. 先确认新版 PCB/BOM 是否真的装了 R112/R113；测 C-to-C 与 A-to-C 供电。此项不需要改固件。
2. 修复 BLE 断线后的扫描调用与主页状态语义，保留当前 LCD 正常显示基线。
3. 完成 G-sensor 与充电 IC 的只读识别和供电测量，再决定配置参数。
4. 取得 SIM/网络、音频和马达的分模块实板证据；最后做整机开机、电池与 USB 切换、长时间运行及多机回归。
