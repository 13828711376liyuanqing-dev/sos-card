## 为什么不直接初始化

合宙公开Lua层components/fskv/luat_lib_fskv.c中，fskv.status在fskv_inited=0时直接返回无结果。默认初始化经sfd_onchip及sfd_lfs；当前底包map也显示使用luat_fskv_sfd.c.o、luat_sfd_lfs_init。

公开components/sfd/luat_sfd_lfs.c第95～105行逻辑为：

```text
lfs_mount()
  失败 → lfs_format()
          成功 → 再次lfs_mount()
```

这条自动格式化分支与“不改、不清、不丢用户现有数据”的要求存在直接冲突。因此不增加一句fskv.init后假称保护门已解决，也不将无法读出的KV当成0个键。

公开源码不是V2052二进制安全合同；来源与SHA256记录在logs/ota_usb_merge_20261024/kv_readonly_sources.json。当前所选根目录SOC容器SHA256为29a3f2dc4eb07badc1093bf8b48f04fa54b40a6d537d1c0814dcfadf53693eec，文件Air780EGH/soc/LuatOS-SoC_V2052_Air780EGH_113.soc。后续必须明确匹配底包，不只比较文件名或版本字符串。

## 需要的具体底包能力

以下是待实现接口要求，**不是现有V2052已经支持的API**。

提供只读挂载／读取现有KV的接口，具备：

1. 挂载失败只返回错误；空白、损坏、版本不兼容、分配失败、读错误均不得调用format/erase/prog。
2. 只读挂载完成后，可执行status/iter/next/get；不得自动创建键或修改元数据。set/del/clear必须拒绝，不得静默成功。
3. 未初始化、空库、损坏库、读失败必须明确区分。空白介质不是“已有空库”的证明；缺能力不能变成空清单。
4. 可以按现有KV几何读取完整区并返回有界数据供SHA256取证，作为只读挂载的替代；地址、长度、型号、读取范围必须由匹配底包提供并验证，不能随意猜CPU映射。
5. 不用未验证的寄存器读或安全禁用API替代Flash读取，不试发不明USB/AT指令。

厂商若已有等价接口，需要给准确API签名、返回语义、匹配的底包及指纹、失败不写数据的保证和验证样例；若没有，需要在底包层增加上述能力。单改当前Lua脚本无法实现缺失的原生只读挂载。

## 接口验收

| 输入／故障 | 必须结果 |
|---|---|
| 已有有效KV及真实键值 | 只读遍历和get成功；挂载前后原始区hash相同，prog/erase计数0 |
| 已有空KV | 明确返回已挂载空库，count=0；不创建元数据 |
| 未初始化／全空白区 | 明确返回未初始化；不得自动format，不冒充已验证空库 |
| 损坏superblock／目录 | 返回损坏错误；原始区保持不变 |
| 瞬态读取失败／断电重启 | 失败拒绝；无格式化和“修复”写入 |
| 内存不足／API不可用 | 返回能力或内存错误；无写入 |
| 写／删／清理请求 | 在只读模式明确拒绝；prog/erase计数0 |

当前应用已有根文件和初始化KV的双遍只读审计、摘要持久化与启动回执，不重写这些已通过主机测试的链路。原生只读端口有效后仅补接入口，再做真实KV读取及最终OTA前后保持取证。

## V2052 的 sfd 等价入口核对结论

SAM | 2026-10-24 +08:00 | 复用已保存的 EC7XX 源码取证，避免重复联网及实板测试；本节仅为静态核对。

- 适用对象继续锁定 Air780EGH V2052；准确 SOC 指纹沿用上文，不凭版本号放开安装。
- 已有文件 `logs/ota_usb_merge_20261024/mirror_project_luatos_src_luat_sfd_onchip_ec7xx.c` 显示：`sfd_onchip_init()` 直接返回0；`sfd_onchip_read()` 调用 `FLASH_readSafe(FLASH_FDB_REGION_START + offset)`，成功返回长度，失败返回-1。这份平台源码没有初始化格式化路径，但尚未证明与当前V2052二进制完全一致。
- 固定提交审阅文件 `logs/ota_wdt_fix_20261024/sfd_readonly_review/luat_lib_sfd.c` 中，`l_sfd_read()` 忽略底层返回值；调用 `luaL_buffinitsize` 后直接 `luaL_pushresult`，未调用 `luaL_addsize` 或 `luaL_pushresultsize` 提交读取长度。按标准Lua缓冲API，不能据此得到可信的指定长度读取及失败判定。不能把空返回当空KV，也不能据此生成data_ok。
- 平台读取函数自身没有区间检查，故即使修复包装，也必须使用匹配底包确认的FDB起点及长度，不能猜读范围。
- 结论：发现了原生只读实现线索，但现有公开Lua包装尚不满足取证合同；不调用fskv.init，不刷同一诊断版，不更改安装门。下一项仅核对V2052实际导出接口与实现差异，或取得具备长度、边界、错误语义的等价只读接口。
- 本轮未执行设备读写、编译、下载、安装；Boot、签名、网络解析等既有通过项未重测。
