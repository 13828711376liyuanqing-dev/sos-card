# OTA 升级包下载地址：后台响应头需要改的 2 处

SAM | 2026-11-04 | 读者：后台同事 | 地址：`ccrcapp.tkhealthcare.com/tkhos-file-cluster/fileOs/appDownload/file_….zip`（openresty）

## 结论

文件内容没问题：MD5 一致，和本地包逐字节相同，也支持 Range（206、`Content-Range` 精确）。但设备（Air780EGH）的 HTTP 解析会拒收这个地址的响应，**分段下载和顺序下载两条路都过不去**，原因是下面 2 处响应头。

## 需要改的

| # | 现在 | 要求 | 设备报错 |
|---|---|---|---|
| 1 | `Accept-Ranges: bytes` 出现 **2 次**；`Vary` 出现 **3 次**（`Origin` / `Access-Control-Request-Method` / `Access-Control-Request-Headers`） | 同名响应头只出现 **1 次**。`Accept-Ranges` 去掉重复的那个（多半是 openresty 和后面的服务各加了一次）；`Vary` 合成一行：`Vary: Origin, Access-Control-Request-Method, Access-Control-Request-Headers`，或者下载接口不返回 `Vary` | `HTTP_DUPLICATE_HEADER` |
| 2 | `Etag: file_pWMxsM7eT22ZibjNNs8rYg.zip`（**没有双引号**） | 按 HTTP 标准带双引号的强 ETag，例如 `ETag: "file_pWMxsM7eT22ZibjNNs8rYg.zip"`，或者用文件 MD5：`ETag: "920e255c7e5cfd6fa71a0688bda3cf44"`。同一个文件每次请求都要一样 | `HTTP_ETAG` |

## 保持不变（这些现在是对的）

- `Range: bytes=a-b` 返回 206，`Content-Range: bytes a-b/总长`，`Content-Length` 等于该段长度。
- 不带 Range 时返回 200 和 `Content-Length`，不要 chunked，不要 gzip（`Content-Encoding`）。
- 直链，不跳转（不要 301/302），用 http。
- 地址后面带 `?md5=<文件MD5>` 时照常返回文件（现在已经是这样）。

## 建议顺带改的（不影响这次）

- `Last-Modified` 现在每次请求都是当前时间，建议改成文件上传时间。

## 改完怎么验

改完告诉我，用同一个地址重跑 `python tools/ota/check_url.py <url.txt> --package <zip>`，`PASSED=true` 就可以发令。也可以自己用下面的命令看，同名头只出现一次、ETag 带引号就行：

```bash
curl -s -D - -o /dev/null -H "Range: bytes=0-15" "<地址>"
```
