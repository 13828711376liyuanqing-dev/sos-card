# 按键接听 / 挂断：修改记录与验证清单

SAM | 2026-11-06 | 读者：负责 GR 编译和实板验证的人、同事 | 状态：**代码已改、主机测试通过；GR 未编译、未上板**

## 一、用户要求（2026-11-06 口述）

> SOS 按了肯定会把报警消息发出去；发出去后平台就开始打电话；打电话过程中，不管按左边还是右边，按一下就挂断。现在是要左右一起按三秒才能挂断。 / 单击是接听，后面才是挂。

| 通话状态 | 单击左键或右键 |
|---|---|
| 来电（`INCOMING`） | **接听** |
| 拨号中（`DIALING`）、通话中（`CONNECTED`） | **挂断** |
| 空闲、已结束、失败、未知 | 不处理（仍然是普通点按，计入"连续按键查 IMEI"） |

不需要双键、不需要长按、不需要 3 秒。

## 二、改动

| 文件 | 改动 |
|---|---|
| `ble_app_uart_c/Src/user/business/yp001_key_call.h`（新） | 纯逻辑头文件：`yp_keycall_step()` 根据按键边沿和通话状态给出"接听/挂断/无"；`yp_keycall_swallow()` 让触发动作的那次按键不再被当成点按 |
| `ble_app_uart_c/Src/user/business/yp001_business.c` | `#include`、一个状态变量、`yp_business_init` 里初始化；`yp_business_keys` 在去抖之后调用 `yp_keycall_step`，动作交给**现成的** `yp_business_call_action()`；左右键松开分支里，被"吞掉"的那次按键不记入 IMEI 序列 |

没有新增任何串口命令：`yp_business_call_action()` 原来就存在（`accept`/`hangup` 经 `BUS_CMD` 发给 CAT1，CAT1 的 `business_core.lua` 转成 `SIP_ACCEPT` / `SIP_HANGUP`），只是此前**没有任何按键接到它**。改前备份：`D:\CODEX\_archive\before_key_call_20261106\yp001_business.c`。

细节：
- 一次按键手势只产生一次动作：第二个键在 500 ms 内按下，算同一手势，不再动作（避免 SOS 双键或双手同时按造成"接听后马上挂断"）。
- 长按（比如按住 2 秒）也只触发一次。
- 通话打出后单击与"报警中双键再按"不冲突：报警中双键再按仍然忽略（TC-SOS-03），挂断由单键完成。
- **挂断只挂电话，不改报警状态**（见第四节第 1 项）。

## 三、验证

主机（已通过）：
- `python tools/key_call/test_key_call.py`：编译**真实的** `yp001_business.c`，用按键序列和 `BUS_EVT` 通话状态模拟：来电单击左/右 = 接听一次；拨号中、通话中单击左/右 = 挂断一次；按住 2 秒只挂一次；双键同时只挂一次；接听后再单击 = 挂断；空闲/结束/失败/未知不动作；无通话时点按仍记入 IMEI 序列（`L`、`LRL`）；接听/挂断的那次按键不记入序列；无通话时 SOS 双键 3 秒仍然触发报警。
- 对照：用改之前的备份跑同一个测试，在第一条"来电单击应接听"失败，所以这个测试确实检验这次改动。
- 回归：`tools/name_push/test_name_push.py`、`test_cat1_resident.py` 全部通过（它们编译同一份业务代码）。

实板（**要你 Keil F7 编译后做**）：
1. 来电（平台打进来）：单击左键 → 接听；再来一次，单击右键 → 接听。
2. 接听后再单击左或右 → 挂断。
3. 按 SOS（双键 3 秒）→ 报警消息发出 → 电话拨出：拨号中单击左键 → 挂断；再来一次用右键。
4. 通话中单击左键、右键各一次 → 都挂断。
5. 报警进行中再按一次双键 3 秒 → 仍然忽略，不重拨（TC-SOS-03）。
6. 没有通话时连续按左右键 → 仍然显示 IMEI。
7. 挂断时语音提示（规格要求）：看 CAT1 一侧挂断时有没有播放；**这次没有改语音，如果没有提示要另做**。
