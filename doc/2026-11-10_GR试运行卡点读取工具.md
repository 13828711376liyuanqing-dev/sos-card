# GR 试运行卡点读取工具 YpTrialProbe v1.0

SAM | 2026-11-10 +08:00

## 1. 用途

同事机器（IMEI 864317088500841）OTA 1.5.29→1.5.30 时，GR 停在 Boot TRIAL（owner INSTALL_PENDING，目标 GR5526）。这个工具用 J-Link 只读 GR 内存，分清卡在哪一步：

| 步骤 | 读的变量（.map 定位） | 卡住时的判断 |
|---|---|---|
| A. 120 秒健康计时 | `health_started` / `health_since` / `result_check_*`、`health_check`（身份、Boot 状态）、`s`（告警、通话、链路、网络、now_ms）、`ota_battery_seen/ms`、`ota_keys_*` | 统计哪个条件在打断计时 |
| B. 静默租约 | `quiet`（阶段、租约序号、获准）、`g_ota_quiet_trace`（各步骤标记）、`g_ota_quiet_first_timeout`、`yp001_ota_quiet_denial` | 区分 CAT1 没回 241 / CAT1 拒绝 / GR 自己的安全检查不过 |
| C. Boot 确认 | 租约步骤做完但 `health_check.boot_state` 仍是 TRIAL | `yp_boot_confirm` 失败 |
| 前提 | `known`、`state`（owner 的 RAM 副本） | 不在"INSTALL_PENDING + GR5526"阶段就显示【不适用】，不下卡点结论 |

- 位置：源码 `tools/gr_trial_probe/src/YpTrialProbe.cs`，构建 `python tools/gr_trial_probe/build_exe.py`。
- 交付：`YP001_工具包/7_GR试运行卡点读取/`（`YpTrialProbe.exe` 和 `使用说明.txt`），exe 的 sha256 是 `47df218d…baf700a`。
- 已登记到 `tools/toolkit/make_toolkit.py`，但还没有重新生成整个工具包。

## 2. 落实了 GR_JLink_Flash_Tool 复盘里的哪些教训

复盘原文见 `doc/2026-11-10_GR烧录工具失败复盘_成功证据与后续注意事项.md`。

| 复盘教训 | 本工具的做法 |
|---|---|
| 设备库、XML 的加载顺序出错，实际选中了别的设备 | 只读 RAM，不需要 Flash 算法或自定义设备库。用命令行参数 `-device CORTEX-M4`，在连接前就选好设备 |
| 请求参数不等于实际状态 | 每次都从 J-Link 输出里核对 `Device "CORTEX-M4" selected`、`Cortex-M4 identified` 和探针 S/N；探针中途变了就停 |
| 错误即停，不信"完成"字样 | 任一情况都停止并说明原因：J-Link 报错、文件没生成、长度不对，或者 .map 里的符号缺失、重名、大小和结构不符 |
| 运行中读取曾出现错位 | 不停核（停核会丢 UART 字节，反而改变要诊断的状态）。核对版本时 Flash 连读两次，不一致就判"无法核对"，不去停核重读。trace 数组用它自带的奇偶序号判断是否正在更新 |
| 必须证明没有影响设备 | 每次读取前后各读一次 DHCSR，要求 S_HALT=0。样本之间 GR 的 now_ms 必须前进，否则停止。工具只发 `mem32` / `savebin`，不发 h/g/r 或任何写命令 |
| 验证必须走用户实际使用的执行链 | 台架上运行的就是交付的 exe：用 `--auto` 自动点同一个"开始"按钮，走同一套 Start/Run 流程，没有另写测试路径 |
| .map 必须对应板上固件 | 拿 .hex 和板上 Flash 对比（向量表、版本信息区、OTA 代码段），不一致直接停 |
| 中文路径 | J-Link 只使用记录目录里的相对文件名 |
| 现场要可追溯 | 每次 J-Link 的命令文件、完整输出和 SDK 日志都保存在 `logs\<时间>\jlink\` |
| 单次成功的适用范围要写清 | 见第 3 节 |

## 3. 实板验证（本机台架，GR 1.5.31，J-Link 69407663）

| 项目 | 结果 |
|---|---|
| .map 核对 16 个变量 | 通过（`s` 376 字节，为短枚举；`state` 344 字节） |
| .hex 与板上 Flash 对比 | 一致，共 1280 字节 |
| 用改了 1 字节的 .hex 测试 | 被拦下："板上固件和这份 .hex 不一致" |
| 是否停核 | 所有样本的 DHCSR 都是 `01010001`（S_HALT=0）；J-Link 输出中没有 reset/halt；56 秒内 now_ms 持续前进 |
| owner 解码 | `COMPLETE 目标 CAT1 1.5.30→1.5.31`，与台架历史一致，给出【不适用】 |
| 台架日志 | `tools/gr_trial_probe/bench_logs/` |

**尚未验证**：A/B/C 三类卡点的判断逻辑还没在真正卡在 TRIAL 的设备上跑过，因为台架板现在不在这个阶段。第一次实际使用就是同事那台机器。判断依据就是上表列出的源码变量，结论出来后要和 CAT1 日志对照一次。

## 4. 同事怎么用

1. 设备保持上电，J-Link 一直接着，不要重刷、不要复位。关掉 Keil 调试；6 号工具如果开着 J-Link 读进度，先停掉。
2. 准备 **1.5.30 那次编译**的 `Listings\YP001_GR5526.map` 和 `Objects\YP001_GR5526.hex`。
3. 双击 `YpTrialProbe.exe`，选 .map（.hex 会自动找），采样时长选 5 分钟，点"开始读取"。
4. 把 `logs\<时间>\` 整个文件夹发回来。

## 7. v1.0.1（同事首次运行报错后修正）

- **现象**：同事运行后提示"这不是 Keil（ARM Compiler）生成的 .map 文件"。
- **原因**：v1.0 只认我们 Keil 6.14 的抬头 `Component: ARM Compiler`；新版 Keil 写的是 `Arm Compiler for Embedded`，大小写和措辞都不同。我只用了自己的 .map 测试，这正是复盘里"只在本机验证"的同类错误。
- **修正**：改为认 armlink 生成的 `Image Symbol Table`；报错时显示 .map 第一行，方便判断。真正把关的仍是 16 个变量的核对（对象文件、地址、大小）和 .hex 对比，这两项没变。
- **验证**：在台架实板上用两种抬头各跑一次（原 6.14 抬头，以及改成 `Arm Compiler for Embedded 6.19` 的副本），都通过，.hex 一致，GR 未停核。
- **仍未覆盖**：如果同事那个编译器版本的符号表行格式也不一样，会报"找不到变量"并停止，不会读错。到时要拿他的 .map 再改。
