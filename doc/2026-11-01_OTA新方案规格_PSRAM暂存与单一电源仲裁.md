# YP001 整机 OTA 新方案规格：PSRAM 暂存 + 单一电源仲裁（v1，待评审）

SAM | 2026-11-01 +08:00 | 读者：本项目开发与 D:\SVN 维护同事。取代"CAT1 发 [OTA_HOLD] 让 GR 保电"的思路（不再继续）。基础资料：`2026-10-30_PSRAM暂存OTA方案_重点跟进.md`。**状态：规格，未改代码。**

## 一、为什么换方案
旧流程里 CAT1 要连续在线十几分钟（下载→存 CAT1 文件区→验证→UART 慢慢写 GR 的 B 区），而 CAT1 的电由多处代码各自决定（同事低功耗 AO、业务、OTA 规则、CLI），OTA 规则还依赖 Flash 日志阶段和 CAT1 发来的文本行。任何一处没对上就断电，断电即票据作废、任务卡死。修补式保电两天没解决，所以从结构上改：
1. **缩短 CAT1 必须在线的时间**：边下边转发，不落 CAT1 文件区，传输期间 GR 不写 Flash。
2. **CAT1 电源只有一个决定点**：GR 内一个仲裁函数，OTA 会话由 GR 自己在内存里登记，不靠日志、不靠 CAT1 文本行。
3. **失败可直接重来**：暂存在易失 PSRAM，B 区一字节没动之前失败不消耗票据。

## 二、资源

## 三、新流程
```
平台 ─HTTP顺序流→ CAT1 ─UART OTA2 帧(460800)→ GR PSRAM 512K ─GR本地验签→ 写 B 区 → 激活/重启/健康观察(沿用)
                     └─ CAT1 组件 → 原生 FOTA 区（GR 组件完成后）
```
1. **开始**：CAT1 收到 OTA 指令 → 先下载并验 `bundle.json` + `signature.json` → 发 `STAGE_OPEN(任务号, GR组件长度, SHA-256, 版本)`。
2. **GR 接受**：检查安全门（provisioned、电量、静止）→ `yp_psram_ota_region()` 拿区域，长度超出即拒 → **登记电源占用 `OTA`** → 回 ACCEPT。
3. **流式转发**：CAT1 下载到 GR 组件数据，按块（如 2 KB）带序号发 `STAGE_DATA`；GR 写 PSRAM 并确认，CAT1 收到确认才发下一块（背压）。CAT1 只在内存里留一块，不写文件区。
4. **结束**：`STAGE_CLOSE` → GR 对 PSRAM 整体算 SHA-256、按现有 `yp_receive_verify` 做签名/型号/布局/数据保护/版本检查。
5. **写 B 区**：全部通过后 GR 自己从 PSRAM 写 B 区（擦→写→读回→持久化），之后沿用已验证的激活、重启、健康观察、回滚。此阶段不需要 CAT1 参与。
6. **CAT1 组件**：GR 组件写完后 CAT1 做原生 FOTA；GR 保持 `OTA` 占用直到 CAT1 报告完成/失败。
7. **释放**：完成、失败、`STAGE_ABORT`、或 90 秒没有任何帧 → 释放 `OTA` 占用、`yp_psram_free`/清区，状态回 IDLE。

## 四、CAT1 电源仲裁（GR 内唯一入口）
```c
/* owner: YP_PWR_BUSINESS / YP_PWR_OTA / YP_PWR_CALL / YP_PWR_DEBUG */
void yp_cat1_power_claim(uint8_t owner);    /* 需要 CAT1：置位并确保上电 */
void yp_cat1_power_release(uint8_t owner);  /* 不再需要：清位；全部清零才真正断电 */
```
- 同事 AO 的 `cat1_power off` / `reset`、业务关电、CLI `cat1_power off/isolate/key` 都改为调用仲裁；`OTA` 位在时，断电和 PWRKEY 一律拒绝并打印 `[PWR] deny off: owner=OTA`。
- `OTA` 位只由 GR 的 OTA 会话代码在 `STAGE_OPEN` 接受时置位、第 7 步释放；不依赖 CAT1 发的文本行，也不依赖 Flash 日志阶段。
- 每次断电/上电都打印一行带原因的日志（解决这次"不知道谁断的电"）。
- 规则只有一条：**有任何占用就不断电**。平时业务照常 claim/release，低功耗不受影响。

## 五、失败与票据
| 阶段 | 失败后 | 票据 |
|---|---|---|
| 下载/流式转发/验签（B 区未动） | 释放 PSRAM，回 IDLE，可立即重发 | **不消耗** |
| 写 B 区开始之后 | 沿用现有持久化恢复/回滚 | 按现有规则 |
- GR 复位或断电：PSRAM 内容丢，B 区没动，等同未开始。
- 新旧混合（一端不认 `STAGE_*`）：CAT1 收不到 ACCEPT 即报 `PEER_OLD` 停止，不静默失败。

## 十一、v1.1 补充（11-01，同步 SVN 后核对 + 你的硬要求）

### 1. `yp_psram_ota_region()` 已有（D:\SVN 11-01 16:48）
- `user/yp001_psram_mem.c:51`：固定区 **0x30800000，512 KB（0x80000）**，即 8 MB PSRAM 的最后 512 KB；PSRAM 堆截止到它前面，不会和墨水屏/LVGL 缓冲重叠。
- 注释写明"在 `yp_psram_mem_init` 之前也可调用、内容易失"。返回值恒为 true，**不检查 PSRAM 是否已初始化**，OTA 代码自己要先确认 `yp_psram_mem_init()` 成功（否则写进去的是未初始化的总线）。
- GR 镜像 ≈443 KB，放得下，余约 81 KB。

### 2. 硬要求：收到 OTA 指令后，第一件事就是锁电（在任何下载、校验、回复之前）
GR 收到 `STAGE_OPEN`（或任何 OTA 开始指令）时，**先执行 `yp_ota_power_lock()`，成功后才处理别的**：
```c
bool yp_ota_power_lock(void)   /* 第一步，失败则直接拒绝 OTA */
{
    yp_cat1_power_claim(YP_PWR_OTA);          /* ① CAT1：置 OTA 占用；轨若断则立刻上电。此后 off/isolate/key/reset 全部拒绝 */
    yp_sleep_block(YP_SLEEP_OTA);             /* ② GR：禁止进入睡眠（sleep_test/PMR_MGMT_SLEEP_MODE 一律拒），保持 ACTIVE */
    mem_pwr_mgmt_mode_set(MEM_POWER_FULL_MODE);/* ③ PSRAM/内存：全供电模式，不允许降级 */
    return yp_psram_mem_init();               /* ④ 确认 PSRAM 已就绪，否则释放上面三项并拒绝 */
}
```
- **解锁只有一处** `yp_ota_power_unlock()`：OTA 完成/失败/ABORT/90 秒无帧超时时调用，按 ④③②① 反序释放。
- 锁在 GR 内存里，不依赖 Flash 日志阶段，也不依赖 CAT1 发什么文本行；CAT1 端的 `[OTA_HOLD]` 行全部删除。
- 每一次被拒的断电/睡眠请求都打印 `[PWR] deny <动作> owner=OTA by=<调用者>`；每一次真正的上/断电打印原因——以后掉电能直接查到是谁。
- 当前 SVN 里会让 PSRAM 失效的入口：`bsp.c:305` `sleep_test` 进入 `PMR_MGMT_SLEEP_MODE`（ultra 睡眠唤醒即重启，PSRAM 内容丢）；会断 CAT1 的入口：`cat1svr.c` `Cat1Svr_power_on` 退出时 `cat1_power off`、进入时 `cat1_power reset`，以及 CLI。这些都要改走仲裁/睡眠闸门。

### 3. CAT1 端对应顺序
收到平台/本地 OTA 指令 → **先发 `STAGE_OPEN`、等 GR 回 `LOCKED`** → 才开始下载 ZIP。GR 没回 `LOCKED` 就不下载、不消耗票据。
