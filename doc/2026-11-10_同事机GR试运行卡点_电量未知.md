# 同事机器 GR 卡在 Boot TRIAL 的原因：电池电量未知

SAM | 2026-11-10 23:45 +08:00

**适用设备**：同事的 YP001（IMEI 864317088500841），OTA 1.5.29→1.5.30。
**数据来源**：7 号工具 v1.0.1 的记录 `D:\123\20261110_232940\`（J-Link 69730340，.hex 与板上固件一致，59 个样本，覆盖 296 秒）。

## 1. 读到的事实

- OTA 记录始终是 `INSTALL_PENDING 目标 GR5526 1.5.29→1.5.30`，GR 已核对运行镜像身份，Boot=TRIAL。
- **120 秒健康计时最长只连续了 6 秒**。59 个样本里 47 个处于"计时未开始"，其余 12 个都在 1–6 秒之间，随即被清零。
- **静默租约序号为 0**：GR 开机以来一次也没有申请过，CAT1 根本还没参与。之前"CAT1 不掉电 / CAT1 拒绝 / 串口错误被锁住"这几条怀疑都排除。
- 告警无、通话空闲、链路正常且为 MQTT、电量记录每约 1 秒更新（距今都不到 1.9 秒）。这些条件在所有样本里都满足。
- **`s.battery_known = 0`，59 个样本全部如此**：GR 读不到电池电量。

## 2. 为什么会一直清零

GR 判断"电量已知"的代码在 `yp001_business.c` 的 `yp_business_ota_inputs_with_usb`：

```
known = 电量记录已出现 && (电池电量已知 || USB 供电证据) && 电量记录 3 秒内更新过
```

- 电池电量未知时，只能靠 USB 供电证据，即 `yp001_ota_port_usb_power()`。它每次都要现读充电芯片的三个寄存器，并且同时满足以下条件：
  - 缓存的显示状态不超过 1 秒；
  - 有输入、power good；
  - 无过热、无故障位、不是 OTG。
- 健康计时每秒检查一次，**只要有一次不成立，就清零重新计**。I2C 偶尔读失败、缓存刚好超过 1 秒、或者故障寄存器某一位闪一下，计时就清零，永远攒不够 120 秒。
- 7 号工具在 5 秒一次的采样点上看不到 USB 证据本身，因为它是临时算出来的，没有存在变量里。所以"USB 证据时有时无"是推断，但它是唯一剩下的、而且会让计时清零的条件。电池未知是实测事实。

## 3. 为什么我们台架几次都成功

我们代码里 `yp001_business.c:14` 写的是 `#define TEST_DATA 0`，而第 489 行用的是 `#ifdef TEST_DATA`。宏被定义为 0 也算"已定义"，所以**这段测试代码在我们的编译里一直生效**：
- 每次收到电量样本，都把电量强制改成"已知、80%"；
- 同时把 IMEI、时间设为已知，空姓名时填测试姓名。

台架 7 号工具实测显示"电量√80%"，与此吻合。

所以我们的 OTA 成功从没走过"电池电量未知、只靠 USB"这条路。同事 1.5.30 的编译里电池是真实读数（未知），说明他那边的这段测试代码没有生效。他的源码在他电脑上，我没看到，以 7 号工具的读数为准。

之前"CAT1 一直有电是区别"的说法，只是巧合的相关，不是原因。

## 4. 现在怎么处理同事这台（不重刷，保留现场）

1. **不要复位、不要断 GR 的电、不要重刷。** Boot 处于 TRIAL，GR 重启后会按 Boot 规则回退到 1.5.29（试运行未确认就回退），这次 OTA 就白做了。
2. 先问同事：
   - GR 板子上接电池了吗？
   - 屏幕上显示电量吗？
3. 如果没接电池，或电池没被识别：在**不断电**的前提下接上电池（USB 不拔），让 GR 能读到电量。然后用 7 号工具 v1.0.2 再读一次，"电量"一栏应显示"√xx%"。之后如果健康计时能走到 120 秒，GR 会申请租约、确认新版本，owner 会切到 CAT1。
4. 接电池有风险（接触瞬间可能掉电）就先别接，告诉我，我们改代码解决。

## 7. 补充（23:55）：用 J-Link 临时跳过 120 秒等待

- **同事情况**：GR 只接 USB，没有电池；电池只给 CAT1 供电。所以 GR 电量未知是正常的，卡点就在 USB 证据时有时无。
- **为什么不改电量值**：GR 约每 1 秒用真实读数覆盖 `s.battery_known`，写进去马上被冲掉。
- **做法**：每 0.1 秒向 `health_started` 写 1、向 `health_since` 写 0，GR 就认为计时已满。只要某一秒 USB 证据成立，GR 就按正常流程申请租约、Boot 确认、写 owner、切到 CAT1。不写 Flash、不停核、不复位。
- **台架验证**：在本机板上用我们的地址（`0x2000C9A9` / `0x2000C9CC`；这块板不在 TRIAL，这两个变量不起作用）写了 100 次，全部生效。DHCSR 前后都是 `01010001`，GR 时钟前进 5.3 秒。
- **交付**：`tools/gr_trial_probe/force_confirm_864317088500841/`，内含 `run.bat`、`force.jlink`、`说明.txt`。地址取自同事 21:43 编译的 .map（`health_started 0x2000C9A5`、`health_since 0x2000C9C8`），23:29 已用 .hex 核对过板上固件。**只能用于这一台。**
- **代价**：跳过了"新镜像连续健康 120 秒"这一项台架检查。后续 CAT1 阶段 GR 授权时仍要求那一刻 USB 证据成立，可能要多重试几次。
