# 工厂单命令进入船运模式：修订方案

SAM | 2026-11-06 +08:00 | 用户明确修正工厂流程：COM31 只发一个命令，准备、检查、关机与确认全部由 GR 完成。本文覆盖此前把左键授权、CAT1 下电、prepare/confirm/token 暴露给工厂的方案。本文为实施设计，尚未实现，不代表现有固件/工具已有一键船运功能。

## 工厂入口

串口页输入 `charger ship start`，或工厂页选择“船运模式”后点击唯一的“进入船运模式”按钮。两者进入同一个 GR 任务入口，不由上位机依次拼接旧命令。

不再要求操作员按左键、手动关 CAT1、手动取消保电、发 prepare、查询 token 或发 confirm。旧分步命令可保留在工程诊断中，工厂正常界面不展示。

## GR 内部流程

1. 先检查当前船运任务和业务/电源 owner：有报警、通话、找人、受保护 OTA 或状态无法确认时，明确拒绝，不开始关电。已存在本任务则返回同一任务状态，不再执行一遍副作用步骤。
2. 外部 5V 仍存在时进入 WAIT_USB_REMOVED，工具仅提示“请移除卡端 USB”；默认等待至多60秒，超时返回失败。此阶段不提前切断 CAT1。移除后继续同一任务，不再授权或重发命令。
3. 核对无外部 5V 后设备仍稳定供电及电池相关状态；仅 USB、无电池时拔线会直接掉电，不能判为船运成功。不能把 USB 下测到的一个 BAT 电压直接当成电池存在证据。
4. 获得维护关机资格后，自动结束厂测保电；此处只释放独立厂测 RAM 状态，不能清除或冒充 OTA owner。对占用资源的厂测任务要求安全退出；未知或未能退出时拒绝继续。
5. GR 发起有界、异步的业务收尾：有待报定位/事件时按 F-010 处理发送或持久待补报，按已有协议完成 CAT1 关机交接。核对真实业务收尾状态后再控制 CAT1 下电，不把 GPIO 请求位当成网络离线或供电测量。
6. 调用底层 ETA69631 船运检查/准备；稳定检查通过后由 GR 自动完成内部确认，不向工厂暴露 token。注册值回读明确成功后，在芯片延迟关断窗口内报告执行结果，再等待硬件关断。
7. 报警、通话、OTA 或电源条件在流程中变化时，在 BATFET 写入前中止；写入已尝试或结果不确定后禁止自动重复写入、复位或撤销，用明确的结果未知状态处理。

插入 5V 恢复仍沿既定硬件方案，不改姓名、用户参数、绑定或 NVDS。关断后 GR 无法继续发日志，不把蓝牙断线当成物理断电成功。

## 工具显示

- 等待外部条件：`请移除卡端 USB`。
- 软件流程：`正在进入船运模式`，内部进度自动刷新，操作员不切换子项。
- 成功：`OK：船运关断指令已执行`，仅在明确的寄存器操作及回读成功后显示。
- 失败：`失败：具体原因`，如报警中、OTA处理中、等待移除USB超时、关机收尾未完成、充电芯片无响应。
- 可能已执行但应答丢失/回读不确定：`结果未知，请检查设备`，不自动重发，不伪装为确定失败或OK。

工程样机需要验证真实 SYS/电池电流及插入5V恢复；这些是工程/工装验收，不要求操作员逐条执行旧软件调试步骤。如果量产需要逐台证明实际关断电流，需工装提供测量输入，不能由已经断电的GR自证。

## 当前代码需要补的地方

- `yp001_factory_ble.c`、协议与上位机：增加单命令任务入口与任务状态，针对这一明确的工厂指令取消左键与外部 token 步骤；不放宽其他维护命令。请求受理与任务完成分开。
- `yp001_charger.c/h`：增加非阻塞的自动船运编排，复用底层寄存器检查、延迟断电及回读；不能仅把旧 prepare/confirm 连续调用两次来代替整个流程。
- 现有 `ship_business_guard()` 的 `!yp001_ota_port_provisioned()` 是旧台架限制，不能永久阻止已配置产品进入船运。改为检查真实 OTA owner/事务可否关电及状态是否可信，不能删除 OTA 检查或清除 OTA 配置来满足条件。
- 现有 CAT1 电源 CLI 能发电源请求，但已查看的 GR business 公共入口没有完整可复用的“关机收尾完成”事务。该异步接口、CAT1配合及超时/待报数据处理必须补齐后才能承诺在线产品一键船运；不得用强制断电凑通过。
- 保留已有扫描回调延迟投递修复、原主工程F7缓存/配置、OTA和用户数据保护；只修改主工程，不同步交付副本。

## 失败及验收

任务独立于 BLE 连接推进：受理后断线不重复创建任务；重连只查询真实状态。上电周期内重复 start 返回同一任务状态；写 BATFET 后及结果未知时不可自动重试。设备重启后不自动继续半途船运，先检查芯片和现有事务。

先验证：电池供电无USB的一条命令完整闭环；其次验证带USB先受理、拔线后自动继续；再验证CAT1在线、厂测保电、重复点击、连接中断、报警/通话/OTA抢占、芯片失败与写入不确定。保留姓名/用户区/NVDS，核对真实关断和5V恢复。静态/主机测试不能替代这些实板证据。

本轮只更新方案，无固件修改、编译、烧录或电源操作。当前0.2.1工具及既有固件源码仍是分步船运入口，不能当作单命令流程已交付。
