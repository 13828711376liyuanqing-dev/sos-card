# 整机 OTA 一键工具（ota_oneclick）

SAM | 2026-11-02 +08:00 | 读者：用户（自己用）。把 `YP001_工具包` 的 4 个工具和主机测试串成一条流水线。你只给两个位置，中间的检查、签名、打包、生成刷机目录全部自动。

## 用法

双击 `oneclick.bat` → 菜单：

1. **一键生成**：弹窗选 ① GR 编译出的 HEX（未签名的 `YP001_GR5526.hex`）② CAT1 源码目录（含 `main.lua`，目标版本）。选过的位置下次自动记住。
2. **只检查**：同样的检查，不生成文件。
3. **读设备**：接板子（COM26 不被占用），读 GR 版本和 CAT1 可用空间。
4. **OTA 实板成功后记录**：把设备当前版本和“验证基线”改成本次，下一轮以它为起点。
5. **查看当前记录**。

命令行：`python oneclick.py run --gr-hex <hex> --cat1-src <目录> [--from 1.5.8 --from-build 12] [--free <字节>] [--no-device] [--auto-prune] [--clean-ota-log]`

## 生成什么（`firmware_releases\ota_<源>_to_<目标>_<时间>\`，永远是新目录）

| 位置 | 内容 |
|---|---|
| `1_GR烧写文件\` | 签名后的 `GR5526_<版本>_b<build>_signed.bin/.hex`（给 GR 有线烧写工具；升级包里的 GR 部分就是它） |
| `2_CAT1刷机目录\USB_IMPORT` | Luatools 刷的接收端：设备当前版本代码 + 冻结了升级包 MD5 |
| `3_上传平台的升级包\` | `YP001_<源>---<目标>_FIRST.zip`，报告里有 MD5 |
| `报告.md` | 每步结论、警告、下一步 |
| `work\` | 中间产物和每个工具的原始输出（`logs\`） |

## 自动做的检查（任何一步失败就停，并说清原因）

1. GR HEX 的版本标记、大小（≤ 441464）；CAT1 源码版本；**两端版本和 build 必须相同**。
2. 设备当前版本（读设备；读不到用 `state.json` 记录；可 `--from` 指定）；目标必须高于它。
3. **OTA 规则**（`tools/tree_sync/ota_guard.py`）：对照验证基线，`ota_*`/`business_*`/`update.lua` 等受保护文件不许有任何改动，不许新建目录、缺库、重复命令、UART 乱注册、重启前不查 OTA。验证版里已有的遗留（如 `mqtts_receiver` 的 `pm.reboot`）只提醒。
4. **评审声明**：授权文件要求人确认“已评审激活流程”“Boot 已实板验证”。这是人的声明，工具不替你下：**首次运行问你一次**（显示依据，输入 y），之后记录在 `state.json`；OTA 受保护代码被有意改动时会重新要求确认（`--reviewed-ota-change`）。
5. CAT1 脚本区容量（≤ 524288）、主机测试：全链路 OTA 流程、数据快照。
6. GR 签名（Gr5526Tool）→ CAT1 包 + review（YpOtaPack cat1，评审留痕里写入主机测试结果）→ 授权文件 → **设备可用空间读数**（≥ GR 正文 + 904 + 16384）→ 打包 → 独立验证 → 接收端（版本改回设备当前版本、冻结 MD5）→ 接收端主机测试 → USB_IMPORT（Cat1UsbImport）并核对 MD5 已冻结。

## 必检功能（SAM | 2026-11-04，用户规定）

OTA 发令前必须清 CAT1 日志：打包时检查 CAT1 源码里 5 项代码齐全（`update.lua` 删 `/log/app.log`、`.bak`，回报 `[OTA] LOG_CLEARED`，台架和平台两个入口都清，OTA 中暂停写日志；`fs_log.lua` 配合暂停），缺一项就停，`--reviewed-ota-change` 也不能放行。发令时 `tools/ota/bench/start_ota.py` 必须看到 `MUST LOG_CLEARED: PASS`。

## 大小红线（SAM | 2026-11-04）

`tools/toolkit/budget.json`（工具包根目录有一份副本）定红线，`budget.py` 检查：GR 签名镜像 ≤ 393216、CAT1 LuaDB ≤ 507904、.sota ≤ 262144、OTA 时 CAT1 可用 ≥ GR 镜像 + 32768。打包时每一步自动查，**超红线停止**；超黄线或比上次实板成功版本增长 > 4 KiB 会提醒。编译后可单独跑：`python budget.py --gr-hex <HEX> --cat1-src <源码>`。说明见 `doc/2026-11-04_OTA空间红线_GR与CAT1大小管控.md`。

## 空间不够怎么办

打包需要 CAT1 的真实可用空间读数（不允许估算）。每次 OTA 后设备会多出 OTA 历史，下一轮常常不够（1.5.8 之后实测可用 430080，需要 ≥ 440552）。三种办法：

- `--auto-prune`：工具自己用 `YpVersionTool prune` 清理设备上 OTA 自己的历史记录（**会写设备文件**，所以必须显式加这个开关）；
- `--clean-ota-log`：接收端带一次性清理块，刷机后第一次开机清掉 OTA 状态/候选文件/旧清理标记；注意这样打包时读到的空间仍是清理前的，需要另外保证；
- 不接板子时用 `--free <字节>`，必须是 `cat_at OTA_FS` 的真实读数。

## 它不做的事

- 不编译 GR（HEX 由你编译好给它）；不改你选的源码目录（在 `work\` 里的副本上改版本和升级范围）。
- 不烧写 GR、不刷 CAT1、不上传平台、不发起 OTA（这些是板上/平台动作，仍按技能 `yp001-whole-ota-run` 由你和 Claude 做）。
- 不碰 Git/SVN；不删除任何文件。

## 状态文件

`state.json`：设备当前版本、验证基线目录、评审声明确认记录、最近一次生成。`config.json`：密钥路径、串口、输出位置、上次选择的路径。密钥用项目里的测试密钥 `OTA_keys\OTA_TEST_*`，不是产品发布密钥。

## 串口（2026-11-09）

GR 命令口的 COM 号会变，不写死：`--port` 参数 > 环境变量 `YP_GR_PORT` > config.json 里的 port（该口当前存在才用）> 自动识别（排除 CAT1 的 USB 口和 nRF 抓包器，只剩一个就用；没有或多个会列出所有串口，让你用 `--port` 或 `YP_GR_PORT` 指定）。台架脚本（`tools/ota/` 下的 gr_cli、ota_monitor、ota_watch、bench/*）同一规则。

## 2026-11-10：不再生成"接收端"

OTA 出厂即可接收（设备从它当前的版本升级到任何更高的、带有效签名和授权的版本），所以不再需要"接收端"。`2_CAT1刷机目录\USB_IMPORT` 现在是**目标版本的完整 CAT1 脚本**，只在出厂、或台架换新基线时用，**OTA 不需要刷它**。
流程：改版本 → 编译 → 签名 → 打包 → 上传 → 推送。设备当前版本（`--from`）仍然要给，它是授权文件的源版本。
