## 内部 UART 契约

CAT1 → GR：`OTA_CTL=<json>\r\n`；GR → CAT1：`OTA_GR=<json>\r\n`。线上平台协议未增加字段。普通请求携带 `op/job/hash/target/version/epoch`；job/hash均64位十六进制，target为CAT1或GR5526，version最长63字节。

- QUERY 返回 STATUS；phase 为 IDLE、DOWNLOADING、PREPARED、INSTALL_PENDING、COMPLETE 或 UNKNOWN。未知存储不当作空闲。
- REQUEST 用 epoch=0，请求 version 为目标版本。仲裁器独立取得可信源版本、检查已知业务空闲及对端稳定，再持久新 epoch/DOWNLOADING，成功才回复 GRANT。
- PREPARED 必须匹配 owner/epoch/身份，独立包验证成立后持久 PREPARED，回复 STATUS。
- ACTIVATE 仅从 PREPARED 准入；实时全部满足已知、稳定静止、充电、70%～100%、无报警/通话/用户活动及对端稳定，再次验包；持久 INSTALL_PENDING 后才单次回复 GRANT。同一 ACTIVATE 重放拒绝。STATUS 不是新的激活授权。
- COMPLETE 的 `version` 表示真实结果版本，增加内部 `outcome=success|fail`。实际版本仅允许已保存 source 或 target；success必须为target。目标版本不修改。产品端口须独立核验健康、真实版本、厂商pending清除及持久结果outbox，不能相信请求本身。持久 COMPLETE/actual_version/outcome 后才 RELEASED，回复 version 为实际结果。回退 source/fail 不伪报目标成功。

现有产品端口 `provisioned=false`，因此不可能发 GRANT，也不会仅因未启用OTA而让CAT1常开。未来已配置存储读取/写入失败，UNKNOWN将保护可能的安装，不能默认放行电源切断。安装前持有下载/准备锁本身不阻止正常休眠，不引入周期唤醒。
