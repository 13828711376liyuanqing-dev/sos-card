# YP001 字体整体规划方案

SAM | 2026-11-02 | 读者：项目负责人、GR 开发、后台/平台 | 前提：姓名改为平台推送字形（已实板打通，见 `2026-11-02_姓名字库下发_工作总结与后续改善.md`）

## 一、结论

1. **原则**：姓名用平台推送的字形；其余所有文字（房号、园区、提示语、时间、状态）用设备里**固定、按用途精简**的字库。
2. **现状浪费**：16/24/28/32px 四个字号里装的是**同一套 185 个汉字**（大部分是常见姓名用字），每个字号各存一遍，共约 76.5 KB。姓名改为推送后，这些姓名用字基本不再需要。
3. **规划后**：固定字库约 **22 KB**，**省约 54 KB GR Flash**（以下数字是按现有字形大小估算，以实际编译为准）。
4. **顺带解决 OTA 空间问题**：GR 正文每少 1 KB，整机 OTA 要求的 CAT1 可用空间就少 1 KB。现在差约 10 KB（可用 430080，要求约 443656），精简后要求降到约 390 KB，**留出约 40 KB 余量**。

## 三、规划：每个字号只装它要显示的字

| 字号 | 用途 | 规划字符集 | 约占 | 省 |
|---|---|---|---|---|
| **32px** | 主页姓名 | ASCII（数字、字母、`-`）。汉字**全部靠推送** | 3.9 KB | 21.6 KB |
| **28px** | 房号 | ASCII + 房号用字：号楼栋幢单元层室区座 | 4.3 KB | 16.8 KB |
| **24px** | 标题、提示、通话、星期、日期 | ASCII + 界面固定文字：当前电量低、请及时充电、正在呼叫、通话结束、星期一二三四五六日 | 4.7 KB | 11.0 KB |
| **16px** | 园区、状态、提示；低电页姓名的兜底 | ASCII + 上面的界面字 + **园区名用字** + 房号用字 + `·` | 3.5 KB | 4.7 KB |
| **40px** | 时钟 | 不变（ASCII） | 5.9 KB | 0 |
| 合计 | | | **约 22.4 KB** | **约 54 KB** |

说明：
- **园区名用字**我先按泰康之家常见园名估了一份（泰康之家、燕申粤蜀吴楚赣桂鹭豫甬闽渝湘园、大清谷），**需要客户给出正式园区名单**后再定。名单有新园区时，重新生成 16px 字库即可，每个字约 30 字节。
- 房号如果平台下发的格式里有别的汉字（例如"栋""区"之外的字），同样要客户确认格式。
- 界面文字由我们的代码决定，改界面文案时同步更新字符集。

## 四、精简后的行为变化

| 场景 | 现在 | 精简后 |
|---|---|---|
| 姓名已推送 | 推送字形显示 | 不变 |
| 姓名还没推送（首次开机、断网重启） | 常见姓名字能用自带字显示，生僻字画方框 | **姓名汉字全部画方框**，联网后 GR 自动请求补发（已实现：CAT1 内存有就直接补，没有就向平台要） |
| 房号、园区、提示、时间 | 自带字 | 不变（字符集覆盖它们） |
| 园区/房号出现名单外的字 | 显示 `--` | 不变（`--`）；需要时见第六节"第 3 阶段" |

**需要你决定**：姓名没推送到之前显示方框，能不能接受？
- 能接受：按上表执行，省得最多。
- 不能接受：32px 保留约 100 个最常见姓氏（约 +9 KB），或者把推送来的字形存进 GR（见第六节"第 2 阶段"）。

## 五、怎么实现（可重复、可校验）

1. **字符集清单文件**：`tools/glyph_maker/fonts/charset.json`，每个字号列出字符（ASCII、界面字、园区、房号分组写，方便以后增减），作为唯一来源。
2. **生成脚本**：`tools/glyph_maker/build_fonts.py`
   - 用与现有字库同一个 `lv_font_conv`（`--font simhei.ttf --bpp 1 --no-compress`）按清单生成；
   - 套用现有 `tools/import_guider_ui.py` 里的"每行按字节补齐"处理（GR 显示要求）；
   - 输出 `font_cn_16/24/28/32/40.c`，保留原文件名和 `font_cn_xx` 名字，**界面代码不用改**；
   - 自检：新字库里保留的字与旧字库逐字节一致；扫描界面代码里的所有字符串常量，确认每个字在对应字号都有；
   - 打印每个字号的字数和大小。
3. **GR 编译**：增量编译（只重编 5 个字库文件），确认 0 错误 0 警告，记录正文大小。
4. **改前备份**：旧字库放 `D:\CODEX\_archive\`，出问题可直接换回。
5. **字符串检查放进流程**：以后改界面文字，跑一次 `build_fonts.py --check`，缺字直接报错，避免上板才发现方框。

## 六、分阶段

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **第 1 阶段（建议马上做）** | 32px 精简为 ASCII；24px、28px 精简为界面字/房号字。这三项不依赖客户名单，省约 49 KB | 你确认第四节"方框"可接受 |
| 第 1.5 阶段 | 16px 按园区正式名单精简（再省约 5 KB） | 客户给园区名单、房号格式 |
| 第 2 阶段（可选） | 推送的姓名字形持久化到 GR（约 1.3 KB/人），断网重启也能显示 | 你决定；需 NVDS 空间审计，OTA 不得清除 |
| 第 3 阶段（可选） | 房号、园区也支持推送字形（协议加字段，GR 加 28px/16px 动态字体） | 有名单外园区/房号字时再做 |

## 七、验证计划

| 步骤 | 通过标准 |
|---|---|
| 生成自检 | 保留的字与旧字库逐字节一致；界面字符串全部覆盖 |
| GR 编译 | 0 错误 0 警告；正文约减少 50 KB（以实际为准） |
| 实板逐页 | 6 个页面（默认/主页/时间/低电/呼叫/结束）用 `epd_page` 逐页看：房号、园区、提示、时间都正常，没有方框 |
| 姓名 | 推送"欧阳䶮𠮷"正常；重启后先方框，联网后自动补齐 |
| OTA 空间 | 用一键工具重算：要求的 CAT1 可用空间低于设备实测 430080 |

## 八、风险

- **园区名单不全**：上线后出现新园区，园区名会显示 `--`，要重新生成 16px 字库并发版本；所以名单要尽量全，或尽早做第 3 阶段。
- **界面文案改动忘记更新字库**：用第五节的 `--check` 拦截。
- **首次开机姓名方框**：依赖联网补发；CAT1 和 GR 都重启过时，需要平台响应 `residentNameNeed`（平台待实现）。
- **字体授权**：精简不改变字体来源（仍为黑体），授权问题同前，待确认。
