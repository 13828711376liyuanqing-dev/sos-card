# 首次ADC异常状态全刷修正

修改人：SAM；修改时间：2026-10-09 18:33 +08:00。

## 现象和证据

用户下载ADC饱和保护版后照片显示BAT --、--.-- V，状态行仍像EXT IDLE且首字缺笔。COM26本轮读回VBUS=0、VIN=0、CHG=0、CHG_EN=0、FAULT=00；采样为ADC RANGE，raw_avg=2、min=2、max=2。因此占位符符合无效采样状态，但屏幕旧状态与当前目标ADC RANGE不一致。首次无效采样走局刷，未触发只针对首次有效电压的全刷条件。

## 修改

双工程 `Src/platform/bsp.c` / `battery_display_poll()`：全刷条件由 `voltage_known && !last_known` 改为 `last_text == NULL || voltage_known != last_known`。首次采样不论有效与否均请求一次全刷；以后有效性切换也全刷；普通数值/充电状态变化仍保持局刷。last_text和last_known仅在显示调用成功后更新，失败继续重试。

更新 `tools/test_battery_display.py` 的已有源码检查。本轮不修改ADC、充电、GPIO、Keil配置。当前固件仍包含180秒充电期限及ADC饱和保护；全刷不能恢复饱和输入的准确测量。
