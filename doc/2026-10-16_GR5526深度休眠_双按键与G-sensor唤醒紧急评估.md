# GR5526 深度休眠：双按键与 G-sensor 唤醒紧急评估

日期：2026-10-16

## 结论

**可以实现，现有原理图不需要为了接入这三路唤醒而改板。** 但必须把三路 AON 输入配置为 GR5526 深度休眠的外部唤醒源；仅注册运行态 GPIO 中断、仅靠按键轮询，均不能保证从深度休眠唤醒。

当前代码还没有进入深度休眠：`Src/platform/user_periph_setup.c` 的 `app_periph_init()` 固定调用 `pwr_mgmt_mode_set(PMR_MGMT_ACTIVE_MODE)`，主循环虽运行 `pwr_mgmt_schedule()`，但策略处于 Active 模式。因此当前按键/传感器中断只能证明正常运行时有回调，不能证明深睡唤醒。

## 现板连接核对

| 唤醒源 | 原理图网络和 MCU 脚 | 当前固件配置 | 深睡结论 |
|---|---|---|---|
| 左键 CON902 / KEY1 | AON_GPIO1，QFN39；按下接地 | 上拉、下降沿中断 | 可作为外部唤醒源，触发极性应为低电平/下降沿 |
| 右键 CON2 / KEY2 | AON_GPIO4，QFN42；按下接地 | 上拉、下降沿中断 | 可作为外部唤醒源，触发极性应为低电平/下降沿 |
| G-sensor U1104 INT1 | `GS_INT` → AON_GPIO7，QFN45；R1103 4.7 kΩ 拉至 VDD_1V8 | 双沿中断 | 可作为外部唤醒源，但触发极性必须按已验证的实际传感器型号和寄存器配置确定 |

三路均为 AON GPIO，正是 GR5526 深度休眠可保留的外部唤醒域。按键的 VDDIO0 为 3.3 V；传感器 INT 上拉为 1.8 V，符合目前传感器 VDDIO 设计，但不能把未测波形或旧 DA221 寄存器注释当作有效极性证据。

## 是否需要“5526 中断接入”

需要，但要分成两层：

1. **运行态中断**：用于唤醒后把按键/运动事件送入业务状态机。两键已由 `app_key_init()` 以 AON 下降沿注册；G-sensor 已由 `DA221_io_int_init()` 以 AON 双沿注册。
2. **深度休眠外部唤醒**：用于让 AON 域解除 MCU deep sleep。应显式启用 `PWR_WKUP_COND_EXT`，并为 AON_GPIO1、AON_GPIO4、AON_GPIO7 写入正确的外部唤醒极性和清除状态位。

第二层是本需求的关键。SDK 1.0.4 的 `app_io_event_register_cb()` 虽会为 AON GPIO 配 IRQ 和回调，但自动调用 `hal_pwr_config_ext_wakeup()` / `pwr_mgmt_wakeup_source_setup(PWR_WKUP_COND_EXT)` 的代码仅编译在 GR551X 分支；GR5526 不能假定 `APP_IO_MODE_IT_*` 自动完成深睡唤醒设置。

## 软件实施顺序

1. **入睡资格**：仅在无 SOS、无通话、无 OTA、无 CAT1 上线传输、无按键按下、无未处理传感器中断时允许深睡。保留既有“静止后 CAT1 真断电”的业务要求。
2. **入睡前配置**：
   - 传感器保持供电：GPIO7 / LDO_EN3 必须为高；U13 输出 VDD_3V3、U1104 VDDIO 的 VDD_1V8 必须持续存在。
   - 把传感器配置成低功耗运动检测，只打开运动 INT，不打开持续新数据 INT；建议使用锁存或确保运动输出脉宽大于 GR5526 的唤醒建立时间。
   - 读取并清除传感器历史中断，确认 AON_GPIO7 已回到非触发电平。
   - 配 AON_GPIO1、AON_GPIO4 为低电平/下降沿外部唤醒；AON_GPIO7 的极性按实测确定。清 AON 外部唤醒状态后启用 `PWR_WKUP_COND_EXT`，最后切换 `PMR_MGMT_SLEEP_MODE`。
3. **唤醒后处理**：先读取并记录 GR5526 外部唤醒状态，区分 key1、key2、GS_INT；恢复必要外设和中断；对按键执行 20–50 ms 去抖；对传感器读状态寄存器并清中断后才允许再次休眠。
4. **业务分流**：
   - 单键：唤醒并进入活动态；保持原有短按/双键 SOS 语义，不把“单键唤醒”直接判为 SOS。
   - 双键：若两键满足现有 3 秒、时差≤500 ms 条件，再触发 SOS；睡眠唤醒阶段不能丢失第二键窗口。
   - 运动：唤醒 GR，确认传感器事件后启动 CAT1 上电/驻网流程；传感器毛刺、I2C 失败或未确认的型号不得直接判定有效运动。

## 当前阻塞与硬件风险

- U1104 当前型号没有被实板 I2C 读 ID 证实。历史记录为 `ret=3, id=0x00`；现有代码按 DA221 地址 `0x27` 和寄存器表配置，而已收集的 DA215 资料指出本板 SA0 低时可能应为 `0x26`。在传感器通信、型号、INT 极性和锁存机制确认前，不能把 G-sensor 唤醒写成已实现。
- 现有低功耗寄存器表把 INT 配成推挽、低电平有效、非锁存，同时有注释与具体配置不完全一致；这不适合作为深睡可靠唤醒的最终依据。需要对实际 U1104 数据手册及波形确认后定案。
- 若关掉 GPIO7 使 U13 / G-sensor 断电，AON_GPIO7 不会产生运动中断；因此要 G-sensor 唤醒就必须保留该传感器电源。它的静态电流需单独实测。
- AON_GPIO1 与 AON_GPIO4 同时还连接既有硬件按键/复位网络。深睡改动前必须实测松开电平、按下低电平和按键波形，避免上电即唤醒或无法再次休眠。

## 最小实板验收

1. 烧录新固件后确认可见 deep-sleep 电流下降，且 CAT1 已按业务要求断电；不能以日志出现“sleep”代替电流证据。
2. 分别按左键、右键：每次各 20 次，从深睡稳定唤醒，记录外部唤醒源、去抖结果和业务结果。
3. 双键：从深睡下同时/错开按下，验证 3 秒 SOS 与 500 ms 时差规则；单键不得误报 SOS。
4. 按传感器实际阈值做静止、轻碰、正常佩戴移动、摇晃测试，各至少 20 次；记录漏唤醒和误唤醒。
5. 连续“唤醒→业务完成→再睡眠”至少 100 次，验证 AON 状态清除、传感器中断清除、CAT1 供电顺序与用户数据保持。

## 建议

先完成“双按键深睡唤醒”这一个可控功能：硬件路径已明确、按键实板业务此前已验证。G-sensor 作为第二步，在确认 U1104 实物型号、地址、低功耗模式和 INT 波形后并入；否则会把当前 I2C 通信问题误包装成低功耗功能。
