# YP001 LVGL 电池图标进度接入记录

日期：2026-10-12（北京时间）

## 修正原因

上一版错误地在主页面和时间页新增了独立 `lv_bar`，改变了 GUI Guider 已确认的版式。根据实板照片和用户确认，本轮已删除该独立控件，改为复用页面已有的 `screen_main_img_bat` / `screen_time_img_bat` 电池图标对象。

## 本轮修改

- 删除 `setup_scr_screen_main.c`、`setup_scr_screen_time.c` 中新增的 60×8 `lv_bar`。
- 删除 `gui_guider.h` 中新增的 bar 成员。
- `epaper_ui_set_battery(uint8_t percent, bool known)` 继续走活动页面，但只调用已有电池图片对象的 `lv_img_set_src()`。
- 在 `epaper_ui.c` 内置 5 档同尺寸 20×10 1bpp 电池图标数据，对应 0/25/50/75/100% 档位；不新增 LVGL 页面对象。
- 无效 ADC/I2C/NTC/充电状态时保留 GUI Guider 原电池图标，不把故障显示为正常电量。
- 主工程和交付副本已同步，逐文件 SHA-256 校验通过。

## 本轮补漏：二维码/IMEI 页面与主机测试弹窗

- 实板照片显示二维码/IMEI 页右上角仍是固定满格图标。该页为 `EPAPER_UI_SCREEN`，`setup_scr_screen.c` 已创建 `screen_img_bat`；此前 `epaper_ui_set_battery()` 只处理主页面、时间页。现将二维码页原图片对象加入同一 20×10 五档图更新，不新增控件，也不改生成页面、显示驱动或充电控制。电量未知时仍恢复 GUI Guider 原图。
- `tools/test_guider_ui.c` 原来大量使用 C `assert`，检查失败时 MSVCRT `abort` 会在 Windows 弹出 `guider_ui_test.exe` 的 `0x40000015` 应用程序错误，阻塞调试。现改为打印条件、文件和行号后以非零状态退出；图片输出文件打开失败也返回失败。`tools/test_guider_ui.py` 抑制子进程崩溃弹窗，并先故意触发一次失败路径，确认其能在 5 秒内返回可读错误，再运行正常测试。该改动只影响主机测试工具。
- 修改文件/函数：两份 `Src/user/gui/epaper_ui.c` 的 `epaper_ui_set_battery()`；`tools/test_guider_ui.c` 的主流程与模拟显示回调；`tools/test_guider_ui.py` 的 `main()`。

## 继续补齐：低电量提示页原电池图标

- 六页逐页核对：二维码/IMEI、主页面、时间页、低电量提示页各有一张原生 20×10 电池图片；通话中、通话结束页没有电池图片。低电量页原图标位于 `(90, 8)`，此前固定使用 `_battery_1_alpha_20x10`，未接入实际 SOC。
- 本轮在 `epaper_ui_set_battery()` 增加 `screen_lowbat_img_bat` 分支。电量有效时复用既有五档图片；电量未知时恢复该页原本的单格图片，不新增控件或修改 GUI Guider 生成布局。调用链仍为 `bsp.c` 电池采样 → `epaper_lvgl_show_home()` → `epaper_ui_set_battery()`。
- 主机测试先复现失败：低电量页 0%/100% 图标区域黑像素数同为 81；修改后四张原电池图均通过 0%/100% 像素差异检查，且电量未知时恢复各页原图。`tools/test_battery_display.py` 增加主/交付两份 `epaper_ui.c` 一致性检查。
- 本轮只修改主/交付 `Src/user/gui/epaper_ui.c`、两项主机测试和本说明；没有修改清理脚本、Keil 配置、显示驱动、充电控制或通话页。
