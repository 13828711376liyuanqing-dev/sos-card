## 源码改动

主工程和交付副本同步：

1. `Src/user/ota/yp001_ota_wire.c/.h`：新增文本/二进制分流；只在文本行边界识别 `OTA2`；普通 `OTA_CTL=` 不会被误吞。二进制载荷中的换行、NUL和伪业务命令保持隔离。
2. `Src/platform/user_periph_setup.c`：原文本处理提取为 `cat_text_bytes()`，IRQ 仍只入队，前台统一消费；有效二进制交给 `cat_wire_frame()`，现阶段仅统计接收。
3. 超时、UART 丢字节、休眠恢复、波特率重开、CAT1 管脚隔离同步清除半包；丢失状态下舍弃到下一文本边界。二进制接收超时使用当前业务单调毫秒计时，最终调度时序还需实板验证。
4. 坏外层帧内出现有效帧、后面又有残留半包时，保持二进制模式，防止残留长度被用作四字节 Magic 索引。
5. 已通过头校验的接收路径仅继续做完整帧 CRC32，避免重复头校验；独立整帧验证 API 仍完整检查头和帧 CRC。

CAT1 本轮未改动；现有 Lua OTA2 编解码参与交叉回归，但没有自动切换旧 DFU 安装协议。

## 测试与容量

统一命令：`python tools/ota/test_uart2.py`。

新增 `test_uart_mux.c` 测试实际 C 分流实现：正常文本前后衔接、二进制伪 `OTA_CTL` 隔离、坏 CRC 后重同步、半包超时、丢字节复位、嵌套帧残留状态。C/Lua 原有所有分包位置与独立 CRC 测试保留。测试失败只返回错误码，不弹 Windows 断言窗口。

**本轮发现新的容量阻塞：** 实际接入后，打包器拒绝签名镜像越界。原先未引用的帧代码被链接器删除，因此上一轮余 792 字节不代表实际接入后的空间。此次没有改槽位、降低签名长度、移动 NVDS 或删业务功能。

最终两份 HEX 均为 payload 478560 字节，加 904 字节签名为 479464，槽位 479232，**超出 232 字节**。地址、大小、签名后容量见 `logs/uart2_tests/mux-capacity.json`；编译日志分别为 `main-mux-verified.log` 和 `delivery-mux-verified.log`，均为 0 错误、0 警告。减少重复头校验后仍未跨过映像对齐边界，实际载荷长度未缩小。**容量检查未通过前不得用当前 Objects 中的 HEX 生成 OTA 上传包。** 原归档基线未覆盖。
