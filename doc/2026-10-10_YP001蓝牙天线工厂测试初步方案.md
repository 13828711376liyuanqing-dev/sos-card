# YP001 蓝牙天线工厂测试初步方案

2026-10-10 更新：两个独立测试交付包已生成，入口见 [蓝牙 DTM 双方案交付](../tools/ble_dtm_factory/README.md)。测试固件已在主机编译，尚未烧写及暗室验证；本文保留方案论证记录。

日期：2026-10-10  
状态：初步方案；测试场景为天线厂暗室，发射与接收性能均属测试范围。尚未修改上位机或固件，尚未完成蓝牙射频实测。

## 一、目标与边界

在现有 `tools/cat1_antenna/bin/CAT1Antenna_停止修复.exe` 的基础上增加蓝牙天线测试功能，配合天线厂暗室的仪器分别测量 YP001 的**发射性能和接收性能**。原有 4G、GNSS 测试功能继续保留。

测试需分两条链路：**发射**由 YP001 发测试包，暗室仪器测量辐射信号；**接收**由仪器发已知功率和包数的信号，YP001 回报正确接收包数，由仪器/上位机计算 PER 并扫描接收门限。两者应覆盖约定的低、中、高频点，以及天线厂规定的姿态和转台角度。RSSI 可作为辅助观察量，但单独一个 RSSI 不能代表完整天线性能。

具体报告项由天线厂仪器能力决定：发射侧可包含辐射功率/EIRP、TRP、方向图、频偏和调制质量；接收侧可包含指定功率下的 PER、接收灵敏度或 TIS。TRP/TIS 属于整机 OTA 指标，包含芯片、匹配、天线和结构影响，不能直接等同于单独天线增益。阻抗/驻波/匹配仍需检查射频测试接口并使用矢量网络分析仪。

## 二、RSSI 由谁输出，是否需要单独汇顶固件

| 测试方向 | 信号流向与结果来源 | 汇顶固件要求 |
|---|---|---|
| 发射侧预试 | YP001 普通广播 → 暗室接收器/仪器；**RSSI 由接收器/仪器输出** | 当前产品固件可先验证链路；`ble_status` 只确认广播状态。普通广播不能覆盖完整 TX 性能测试 |
| 发射侧正式测试 | YP001 按指定频点、功率和包模式发射 → 暗室仪器测辐射功率、TRP/方向图等 | **需要受控的汇顶射频测试模式，建议独立测试固件**；是否支持连续波及具体指标要按仪器和 SDK 能力核实 |
| 接收侧正式测试 | 仪器按已知功率、频点、包数发射 → YP001 回报正确接收包数 → 计算 PER/灵敏度或 TIS | **需要汇顶接收测试模式**。SDK DTM 测试结束回报接收包数，**不等于逐包 RSSI 输出**；若要求板端逐包 RSSI，需核实 SDK API 并另行开发、校准 |

因此，普通广播只适合预试。对天线厂要求的**发射加接收**暗室测试，建议单独做汇顶产测固件，提供 TX_START、RX_START、TEST_END/结果查询等受控入口，并与仪器的实际命令集对齐。测试固件应以 YP001 板级引脚、供电和射频路径移植，不能直接烧 SDK 开发板示例。SDK 的 DTM 示例使用 `hci_uart`，而其 `board_SK.h` 默认是 UART3/GPIO4、GPIO5；YP001 现有调试口为 UART0 GPIO28/29，端口和命令协议需要专门适配。测试后还要恢复产品固件并复核版本、地址和基本功能。

## 三、当前工程现状

| 项目 | 已核实情况 | 对方案的影响 |
|---|---|---|
| 现有上位机 | Windows WinForms 工具通过汇顶 UART0 串口控制 CAT1，并保存原始日志与 CSV | 串口连接、界面框架、会话日志和导出方式可复用；BLE 测量需要增加独立数据来源 |
| GR5526 蓝牙 | 产品固件以 `YP001` 名称进行可连接广播，使用 37/38/39 广播信道，广播间隔配置为约 100–150 ms | 可先利用现有广播做发射侧的相对筛选 |
| `ble_status` | 只返回名称、就绪、广播和连接状态 | 可用于确认板端状态，不能作为蓝牙天线性能数据 |
| `ble_scan` | 项目记录显示启动扫描曾触发 INVSTATE HardFault，正常启动路径已禁用扫描 | 不作为现成工厂测试入口，不能让被测板扫描自身广播来测自身发射性能 |
| BLE 地址 | 当前产品固件在 `user_periph_setup.c` 设置固定地址，广播名也固定为 `YP001` | 多块板同时靠近时无法可靠凭名称/地址区分；正式量产前须确定唯一身份方案 |
| DTM | 当前 `DTM_TEST_ENABLE=0`；SDK 有 DTM 示例 | 射频仪器测试需单独评估测试固件、接口和恢复产品固件的工序，不能当作现成功能 |
| 实板证据 | 既有 LightBlue 发现并连接 `YP001` 的记录 | 证明基本广播/连接曾可用，不证明蓝牙天线射频指标达标 |

上述现状依据当前主工程源码及已有联调记录；正式上线前应复核交付固件版本、BOM、PCB 射频走线、匹配网络和天线装配方式。

## 四、推荐工站架构

```text
YP001 被测板 ── UART0/USB串口 ──┐
                                  ├── 同一个 Windows 上位机 ── 测试记录/CSV
暗室 BLE 射频仪器 ── USB/串口/厂商接口 ─┘
            ⇅ TX 时接收 YP001；RX 时向 YP001 发已知功率测试包
```

- **被测板串口**：预试时可读取现有 `ble_status`；正式测试时由射频测试固件接受 TX/RX 命令并回报状态及 RX 接收包数。读取板号和固件版本用于追溯；串口连接不等于天线合格。
- **暗室 BLE 射频仪器**：TX 测试时接收并测量 YP001 辐射信号，RX 测试时产生已知功率与包数的测试信号。须取得仪器型号、支持的 BLE 测试模式、PC 控制接口和数据协议，确认能导出的 TX/RX 指标。普通电脑内置蓝牙不作为暗室射频仪器。
- **暗室与夹具**：按天线厂校准要求固定测试距离、被测板姿态、极化、仪器天线、供电和测试时间；转台角度及路径损耗按仪器流程记录。

暗室内一次只测试一块板，并将板号与本次仪器结果绑定。当前固定 BLE 地址会影响普通广播预试的多板识别，但受控 DTM 包测试的追溯重点是工位上的板号、串口会话和仪器会话配对。

## 五、上位机拟增加的功能

在现有工具新增“蓝牙天线”区域，分别提供发射和接收测试流程；保持 4G/GNSS 页面和数据流程不变：

1. 选择被测板串口、暗室仪器连接及工位编号；输入或扫码板号、天线批次。
2. 查询并显示测试固件版本、板号和当前 TX/RX/空闲状态；板号无法确认时不生成合格判定。
3. 发射测试：设置频点/信道、功率、包模式和时长，命令汇顶开始发射；从仪器读取辐射功率、方向图/TRP 等其实际支持的结果，停止后确认 DUT 已退出测试模式。
4. 接收测试：设置频点/信道及仪器输出功率，命令汇顶进入接收模式；仪器发送已知包数，汇顶回报正确接收包数，上位机记录 PER 与灵敏度扫描结果。若做 TIS，由仪器/暗室流程按角度和门限汇总。
5. 根据已批准的 TX/RX 阈值分别显示“通过/不通过/无法判定”；仪器断开、板号不明、DUT 未进入指定模式、有效样本不足或日志写入失败均显示“无法判定”，不自动判为通过。
6. 保存测试时间、板号、BLE 地址、测试固件版本、仪器型号/编号、校准/夹具配置、频点、功率、角度、TX/RX 原始结果、统计值、阈值版本和判定结果。蓝牙数据建议写入独立 CSV，避免与现有 CAT1 `samples.csv` 字段混淆。

## 六、工厂测试流程草案

1. 每班或每次工位变更时，用合格金板和仪器自检/校准确认暗室及夹具处于基准范围。
2. 将单块被测板放入夹具并供电；上位机读取板号、测试固件版本及状态。
3. 依次执行低/中/高频点的发射测试，再执行相应频点的接收测试；转台角度、功率扫描、测试包数与 PER 门限由天线厂测试规范确定。
4. 上位机保存仪器原始结果及汇顶回报，再按批准的 TX/RX 阈值分别判定；异常板复测一次并保留初测记录。
5. 对边界或不良样品检查天线本体、焊接/连接、射频匹配器件和 PCB 装配；需要定位射频根因时转工程射频测试工位。

阈值不应凭经验预填一个通用 dBm 数。应由天线厂结合设计目标、仪器校准、合格金板及已知不良样品，分别批准发射指标和接收 PER/灵敏度/TIS 门限。测试固件的输出功率设置、供电、夹具或仪器变更后要重新比对基准。

## 七、射频性能调校与匹配分析

天线厂应先确认板上 GR5526 射频走线、匹配网络、天线接口/测试点和实际 BOM。工程样机可用矢网检查匹配和驻波；暗室仪器测发射方向图/功率与接收灵敏度/PER/TIS，并覆盖约定频点/角度。RSSI 是接收端测得的链路电平，受发射功率、路径损耗、极化、方向、接收器校准等共同影响，不能单独作为天线效率结论。

SDK 中有 DTM 示例，但当前产品工程未启用 DTM。若采用独立 DTM 测试固件，须制定烧入、测试、恢复产品固件及恢复后复核身份和业务功能的完整流程；在完成编译、下载、仪器联调和实板验证前，不把 DTM 写成已可用的产测功能。

## 八、实施顺序与待定事项

1. **取得天线厂测试规范**：明确 TX 的 TRP/EIRP/方向图等项目，RX 的 PER/灵敏度/TIS 项目、频点、角度、门限和报告格式。
2. **取得暗室仪器型号和控制协议**：确认发射及接收两方向的 BLE 模式、PC 接口、数据格式和校准方法。
3. **核实板级射频资料**：核对 GR5526 至蓝牙天线的 PCB、BOM、匹配器件和装配方式；制定工装位置与供电条件。
4. **解决测试追溯**：确定每板板号与串口、仪器会话的绑定方式；若保留普通广播预试，再解决固定 BLE 地址造成的多板识别问题。
5. **开发汇顶测试固件与上位机并联调**：移植 DTM/受控射频模式到 YP001，新增 TX/RX 控制、仪器采集、日志和结果页；先用金板/已知不良样品验证重复性，再批准阈值。
6. **形成工厂作业指导书**：写明开机检查、放板方向、采样时间、判定、复测及不良处理。

当前只有软件与既有联调记录层面的可行性评估；尚无天线厂仪器型号/接口、TX/RX 测试规范、金板数据、阈值或蓝牙射频实测，因此**现有 EXE 不能直接作为蓝牙发射与接收性能判定工具**。

## 十、汇顶原厂方案核对与最简执行路径（2026-10-10 联网核对）

汇顶官方《GR5xx DTM测试指南》V3.6 将 DTM 定位为蓝牙射频性能测试模式，覆盖发射功率、接收灵敏度、频偏、调制和误码/丢包等项目。其基本架构是 **DUT 固件 + 两线 UART/HCI + 蓝牙测试仪**；测试仪通过 HCI 命令控制 DUT 的 RF PHY。官方还提供 GRDirect Test Mode Tool（DTMTool），可在 Windows 上通过串口手动让 GR5526 进入 TX 或 RX 测试。DTMTool负责**下发模式命令**，不能替代暗室的射频测量仪器。

原厂示例路径为 `SDK/projects/ble/dtm/direct_test_mode/`。官方指南明确：开发板示例的 GR5526 HCI 口默认是 UART3，换实际待测板应依原理图改 UART 及引脚。本仓库的 `board_SK.h` 为 UART3/GPIO4、GPIO5，YP001 的现有外部调试口为 UART0/GPIO28、GPIO29；不能把开发板预编译 `direct_test_mode.bin` 直接当成 YP001 可用固件。需以 YP001 编译/下载配置移植并验证，保留现有产品固件备份及测试后的恢复步骤。

**推荐先做最小闭环，不先开发新的蓝牙上位机：**

1. 取得天线厂仪器型号、是否支持 BLE DTM/HCI UART，以及仪器的 OTA/暗室测试流程。若仪器能直接控制 DUT 的 UART/HCI，由仪器软件负责 TX/RX 命令和报告；若不能，使用汇顶 DTMTool 手动控制 DUT，仪器单独测量和记录。两者不能同时占用同一个 DUT 串口。
2. 只为一块 YP001 工程样机制作独立 DTM 固件，将 HCI UART 映射到可接线的 YP001 串口；先在台架上验证 HCI 通信、指定频点 TX、RX 和停止回执，再进暗室。保持产品固件与 DTM 固件的镜像、版本和烧录记录分开。
3. 天线厂按其仪器规范做低/中/高频点的 TX 测量，再做相应频点的 RX 包接收/灵敏度测量；如需 TRP、TIS、方向图，按暗室 OTA 转台与校准流程执行。官方示例中 RF cable 到测试板接口属于传导连接示意，YP001 的天线 OTA 测试应按天线厂暗室的空间耦合工装进行，不能把传导结果冒充天线辐射结果。
4. 保存仪器原始报告、DUT HCI 日志、样机板号、固件版本、测试条件和金板对比。完成后恢复产品固件，复核启动、BLE 广播和原有业务。只有本轮实板结果可写成测试通过。

这条路径的工程工作量主要在 **YP001 DTM 固件的板级 UART 适配与实板验证**，以及仪器/工装对接；原 CAT1 上位机可暂不修改。待仪器流程与指标确定、手动跑通后，再决定是否把 HCI 控制与仪器报告整合进同一个上位机。
