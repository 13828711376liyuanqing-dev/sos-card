# YP001 蓝牙暗室 DTM 双方案交付记录

## 范围与产物

本轮只新增独立测试工程 `SDK/projects/ble/dtm/yp001_ble_dtm/` 与 `tools/ble_dtm_factory/`。产品主工程 `ble_app_uart_c`、交付副本 `SVN交付_YP001_GR5526_20261001/ble_app_uart_c`、CAT1 `Air780EGH` 及既有下载配置均未由本轮修改。工作区原有大量未提交修改，保留原状。没有对实板下载或擦除。

| 文件/函数 | 修改前 | 修改后及原因 |
|---|---|---|
| `yp001_ble_dtm/Src/platform/board_SK.h` HCI UART 宏 | 汇顶示例使用 SK 专属 HCI 串口 | 独立测试镜像使用 YP001 UART0、GPIO28/29、115200 8N1；适配板级接口，不改产品板级配置 |
| `yp001_ble_dtm/GCC/Makefile`、链接脚本 | SDK 示例工程目标与构建规则 | 生成专名 `yp001_ble_dtm_test` 的 HEX/BIN；修正默认静默模式在 Windows 只打印命令却不执行的错误；Windows MinGW 可构建；不使用危险递归清理；应用起点仍为 `0x00202000` |

## 构建与检查

- 使用本机 xPack GNU Arm GCC 15.2.1 和 MinGW `mingw32-make -B V=1 -j 1` 完整重编独立 DTM 工程，退出码 0；随后强制重编一个目标验证默认 `V=0` 真正更新目标文件，再用默认模式完成链接。最终 `build_gcc.log` 有 0 错误、889 条链接警告：882 条为旧 SDK 库对 ROM 绝对符号的 Thumb 分支提示，7 条为 `libnosys` 未实现系统调用提示。警告不等同于实板功能通过，首次烧录必须验证 HCI。编译日志：`SDK/projects/ble/dtm/yp001_ble_dtm/build_gcc.log`；静默模式验证日志：`SDK/projects/ble/dtm/yp001_ble_dtm/build_v0_check.log`。
- HEX 与 BIN 按 Intel HEX 逐记录校验、比较有效数据均一致；起点 `0x00202000`，末字节 `0x0021D717`，BIN 为 112408 字节。测试工程 `custom_config.h` 中的 `0x0027E000` NVDS 地址定义已注释，不能把它当作当前生效的 NVDS 起点；镜像文件地址也不能证明现场烧写器的擦除范围或 NVDS 安全。
- 使用 .NET Framework 4 编译 `ProtocolTests.exe` 并运行，输出 `HCI protocol tests PASS`；重新编译方案 2 的 WinForms EXE，隐藏启动 2 秒进程仍存活后关闭。尚未连 YP001 串口。
- 两方案分别生成 `SHA256SUMS.txt`；两份 HEX 哈希一致、两份 BIN 哈希一致。最终校验清单以各文件夹内的文件为准。

## 安全与实板边界

测试镜像与产品程序使用同一应用地址，因此**烧入测试镜像会暂时替代板上产品程序**；“不影响现有固件”在本轮指不改产品源码、已有产品 HEX、产品 Keil 配置和交付副本。若现场没有当前板的确切恢复镜像，只能用专用工程样机。烧入、应用区擦除、写后校验、HCI 回执、暗室 TX/RX、停止、恢复产品镜像及身份/业务复核均未实板验证。不得把主机编译和文件地址检查写成现场通过。

恢复补充：主工程 `ble_app_uart_c/Keil_6/Objects/YP001_GR5526.hex` 与交付副本同名 HEX 的 SHA-256 分别为 `5663FED172E06D84A5D6409D6B70009B8CDC242E6CE0ABA32DD333EE02450BA8`、`9222459F5FC72CFD7F6D26AD8C70A04418863542D0935D512B187BAB831E55A0`，内容不同，且未证明其中任一份就是当前板正在运行的版本。测试后原则上可用 J-Link/SWD 重新烧回匹配的产品 HEX，无需预先手动整片清空；须核对 SCA 处理及实际擦除范围，仅擦写必要的应用/SCA 扇区，保留 NVDS、身份/校准等非目标数据，并在恢复后检查版本、身份及业务功能。当前未完成此恢复流程的实板验证。

第三方 GR5526 烧写器/驱动与暗室仪器软件仍需现场提供。不同烧写器的擦除行为和仪器 HCI 支持方式未确认，本轮不提供盲烧脚本。方案 1 正式适配还需天线厂的仪器型号、DUT 串口控制模式与测试规范/阈值；方案 2 的 RF 指标仍由仪器报告给出，PC 工具不测辐射功率、TRP 或 TIS。

2026-10-10 工厂包复核补充：方案 2 的 HEX 向量表与产品镜像均位于 `0x00202000`，初始 SP 均为 `0x20080000`；`0x00202200` 的 AppInfo 模式值、芯片 `0x5526`、装载/运行地址和校验字段与产品镜像一致。这说明镜像结构与板上芯片配置静态匹配，**不证明它在当前板上启动**。GR5526 启动还依赖 SCA；现有 HEX 不包含 `0x00200000–0x00201FFF` 的 SCA，须用支持 `BUILD_IN_APP_INFO`/SCA 的已验证下载流程，不能只做原始 HEX 写入。当前用户无确切恢复镜像，仅有产品板，因此未下载。

电源补充：DTM `main()` 只初始化 HCI UART 和 BLE 栈，没有调用产品 `BSP_init()` 的 `charger prepare`、`gpio_init()` 等板级流程。产品安全基线记录指出 ETA69631 的 nCE 硬件接地、上电默认 `CHG_CONFIG=1`，软件也无法消除初始化前窗口。用户拟同时接电池与 USB/5V 时，本测试镜像不能保证禁充，**不得直接用于该接法**。先用电池断开、已验证 5V 路径供电的专用样机测 GR5526 供电，并验证 HCI Reset/TX/RX/End；正式电池/充电安全仍需单独验收。

方案 2 工厂评估包：`tools/ble_dtm_factory/YP001_蓝牙天线暗室测试_方案2_待样机验证_20261010.zip`。包内 5 个文件已与源目录逐字节比较，并复核 `SHA256SUMS.txt`；ZIP SHA-256 为 `D71EF026593D62D36A35D4E78C18DB49E756BC93B157E32D1F6D311D890253FC`。文件名和使用说明均标明“待样机验证”，不等于工厂投用批准。

SCA 依据：[汇顶 GR5526 开发者指南的 SCA 说明](https://docs.goodix.com/zh/online/detail/developer_guide_bl_b/V1.0/b85e5240d92eb717ca673c73339fc81c)。

烧写接口补充：J-Link 的 SWD 可以用于 GR5526 下载；不需要 Keil 重新编译。工厂专用样机建议使用汇顶 GProgrammer 配 J-Link SWD，Firmware 页导入 HEX，核对 Layout 后执行下载；[GProgrammer 用户手册](https://docs.goodix.com/zh/online/detail/gprogrammer_user_guide/V2.7/5794b21208377bf3125e21a051c61e5a)明确支持 HEX/BIN 文件。通用 J-Link `loadfile` 仅写原始地址的行为不等同于 GProgrammer 的固件/SCA 流程。当前无恢复镜像、电池+5V 接法不满足测试前提，因此仍未操作当前板。
