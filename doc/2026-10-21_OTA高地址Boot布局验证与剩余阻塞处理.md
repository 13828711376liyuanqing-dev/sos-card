# OTA 高地址 Boot 布局验证与剩余阻塞处理

SAM | 2026-10-21 +08:00 | 将Boot与当前应用重叠问题收敛为高地址候选布局，验证全尺寸交换与受限链接；不修改生产布局或用户数据。

## 本次实际推进

此前参考Boot从0x00204000运行，与现有0x00202000起始应用重叠，不能用于产品。此次保留A槽入口和APP_INFO位置，把独立Boot候选放在0x002EC000，NVDS仍在尾部原址。高地址隔离工程已全编成功，0错误/0警告，硬链接上限36KiB；主/交付现有HEX均通过只读候选布局检查。

已有事务核心+白名单后端+启动选择器以两个完整468KiB槽进行主机安装、试运行超限及反向回退联测通过，确认模拟Boot、NVDS、仲裁及未分配区保持；用户最新数据随程序回退保留。该验证不等于真实芯片断电试验。

**本次没有烧录或改写SCA，没有启用安装，没有生成可发布固件。** 解决的是候选布局冲突及其软件检查，不是宣称完整OTA已经可用。

## 1. 官方规则核查与首次部署处理

重新核对[汇顶GR5526开发者指南SCA章节](https://docs.goodix.com/zh/online/detail/developer_guide_bl_b/V1.0/b85e5240d92eb717ca673c73339fc81c)：主Boot信息有备份；非安全模式默认使用主信息，安全模式描述了主信息校验失败后的备份校验路径。因此不能把备份存在推论为当前普通模式现场改写一定掉电安全；也不能用应用软件签名开关推定芯片安全模式。

处理路线建议：

1. 新生产板在受控工装阶段一次性配置最终Boot和启动信息，后续常规应用OTA保持SCA与Boot固定，通过A/B事务升级应用。
2. 当前开发板首次引入Boot单列为受控迁移项目，先备份和核对SCA、用户区、ROM模式及工具写入范围，再准备签名镜像和完整恢复流程。未核实前不在线改SCA。
3. 现场远程首次迁移暂不开放；若要求无人值守，必须继续获得对应模式ROM选择规则及逐点断电证据。不能把工装可救回当成远程原子迁移通过。
4. 不为获得备份路径擅自写eFuse或切换芯片安全模式。

上述是部署路径划分，不是本轮已执行的工装操作。用户数据保持仍是首次部署/迁移的硬门槛。

所有区间右端不包含，均按4KiB对齐。机器清单为 `tools/ota/boot/layout_candidate.json`，明确 `approved=false`、`candidate_do_not_flash`。

Boot执行区不属于被交换A/B，保持A运行地址不变，避免每轮应用升级还要重定位入口。但当前Boot只有隔离停留入口；还没有正式向量/跳转与可信首次配置。仲裁区只是预留，持久仲裁后端尚未实现。额外用户区仍须完整盘点；不能据此表声明B/Boot区域当前一定不存在其他用户内容。

Boot部署后，普通Keil/GProgrammer再次下载裸主应用时可能同时更新SCA启动选择，需验证下载算法行为并提供专门配置。不能默认继续使用旧“下载主HEX”流程仍会保留Boot入口；本轮未修改既有Keil下载设置。

## 3. 本次代码和工具

| 文件 | 作用 |
|---|---|
| tools/ota/boot/layout_candidate.json | 完整候选区域清单，不含安装许可 |
| tools/ota/check_layout.py | 只读解析HEX和Boot Map，检查分区完整/对齐/不重叠、原A入口、NVDS不变、槽容量和Boot上限 |
| tools/ota/test_layout.py | 9项验证，覆盖应用超区、Boot超区/旧入口、签名预算不足、重叠、NVDS改变及禁止清单自批准 |
| tools/ota/test_gr_flash.c | 扩展到完整468KiB候选槽，实际核心+适配器安装/回退与保护区检查 |
| logs/ota_preflight_20261021/boot_high_reference | 从上轮隔离工程复制，重定位Boot到高地址；不修改原SDK或生产应用 |

`check_layout.py`同时验证HEX记录校验和、冲突字节及EOF，再以镜像跨度估算空间。856字节签名+48字节信息只作SDK格式预算，**不是正式包解析或验签**。输出始终install_enabled=false/layout_approved=false；修改approved字段不能把本检查器变成发布授权。

运行示例：

```powershell
python tools/ota/test_layout.py
python tools/ota/test_gr_flash.py
python tools/ota/check_layout.py --app-hex ble_app_uart_c/Keil_6/Objects/YP001_GR5526.hex --boot-map logs/ota_preflight_20261021/boot_high_reference/Listings/DO_NOT_FLASH_boot_high.map
```

测试先复现缺少检查模块；新增Boot签名空间用例再次复现只校验裸Boot会错误放行，再修复并通过。未删除失败用例、未跳过检查。

## 4. 构建与容量结果

目标 `BOOT_HIGH_REFERENCE_NO_FLASH`，ARMCC5.06 update6 build750，所有SDK输入来自活动1.0.4；生产Keil6/AC6不变。

- Boot起点0x002EC000，scatter的Load Region硬上限0x9000，超出应链接失败。
- Code31224、RO352、RW2192、ZI30036字节，与上轮最小参考同口径。
- 原始加载大小33768字节；加签名/信息预算后34672字节，小于36KiB，剩2192字节。这不是栈/时序或正式签名包验收。
- 两份现有应用有效数据/跨度均477536字节；加856+48预算为478440，468KiB槽剩792字节。
- 没有通过挪NVDS、删用户文件或取消签名腾空间。
