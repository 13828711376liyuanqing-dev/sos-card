# GR项目签名头实施合同（候选，尚未部署）

SAM | 2026-10-23 +08:00 | 为独立YP001 Boot定义明确的签名头，消除对未提供厂商头生成工具的依赖。用户已要求连续完成实现；此为内部文件格式，不新增平台协议字段。

## 边界

采用SDK1.0.4 SECURITY_CFG_VAL=0的RSA2048/PSS/SHA256/盐32验证算法、520字节公钥块与904字节尾部跨度。前128字节为**YP001项目格式**，不声明它与GProgrammer或ROM安全启动头兼容，不修改eFuse或ROM安全配置。

只能由识别此合同的项目Boot验证/启动。旧Boot或原生厂商工具不得直接安装该镜像；本轮生成物继续标记device_installable=false，后续独立完成布局、数据保护、Boot部署与实板验收。

## 文件结构

镜像为原A地址应用payload + 904字节尾部，完整长度不能超过479232字节；payload执行地址0x00202000，最大478328字节。

尾部偏移：

| 偏移 | 长度 | 内容 |
|---|---|---|
| 0 | 4 | ASCII YPGR |
| 4 | 4 | payload长度，小端 |
| 8 | 4 | 格式版本1，小端 |
| 12 | 4 | 固定执行地址0x00202000，小端 |
| 16 | 4 | 固定型号编号5526，小端 |
| 20 | 4 | 整机目标数字版本major*1000000+minor*1000+patch，小端，每段0～999 |
| 24 | 4 | 编译build序号1～65535，小端 |
| 28 | 4 | flags=1，声明不迁移/不重置用户数据；实际兼容仍须审查验收 |
| 32 | 32 | 经审核布局合同SHA256，Boot编译时固定，不能由包自行批准 |
| 64 | 32 | payload SHA256，同时与Boot事务记录identity比较 |
| 96 | 32 | 经审核用户数据兼容合同SHA256，Boot编译时固定，不能由包自行批准 |
| 128 | 520 | SDK公钥块n[256]/e[4]/RR[256]/c[4]，小端候选编码 |
| 648 | 256 | payload + 尾部前648字节的RSA-PSS签名，小端 |

公钥必须与外部固定XML指纹对应。布局/用户数据合同SHA256为必填，不提供猜测默认值，不把输入这两个值等同审核通过。版本必须从payload唯一YP001_FW标记读取并匹配指定目标；保留MSP/Reset向量限制。

## 校验顺序

先检查槽范围和完整读取成功，再核对项目头、型号/版本/build/flags、固定布局与数据合同、预期payload identity。验签必须覆盖完整payload和头部公钥，使用外部固定信任根；之后计算实际payload SHA256并比较。任何读失败、格式不符、摘要不符均拒绝，不能调用跳转。

签名头不是批准擦B区的依据。首次部署仍需确认B区已有内容归属，保留NVDS、用户文件和业务最新数据。
