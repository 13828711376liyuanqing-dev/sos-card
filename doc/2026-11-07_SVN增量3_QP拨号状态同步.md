# SVN增量3 QP拨号状态同步

SAM | 2026-11-07 +08:00 | 基于dbfca47及用户认可的b20本地SOS范围，适配同事的通话状态更新函数。候选1.5.17/b21，主机回归通过，等待原主工程F7。

## 本轮范围

需求F-002要求单次呼叫、双向挂断并在通话结束后保持报警，F-022要求屏幕跟随真实业务状态。客户需求、冲突索引及上一轮三方审查已核对。同事的 `yp_business_call_set` 在ENDED/FAILED时清除alarm_active，属于此前审查中拒绝移植的行为。

本项目CAT1已有 `business_runtime -> business_core -> BUS_EVT call -> yp_business_handle_line`，可驱动来电、接通、结束等状态。缺口在GR的QP流程直接执行 `at SIP_DIAL`，没有同步业务层DIALING状态。屏幕已有 `epaper_ui_needs_refresh` 读取revision和 `effective_page` 读取call状态的链路。

## 实际改动

| 文件或函数 | 行为 |
|---|---|
| cat1svr.c / Cat_Sip_dail入口 | 原拨号命令之后调用 `yp_business_call_set(YP_CALL_DIALING)`，使QP拨号请求进入屏幕业务状态 |
| business/yp001_business.c / yp_business_call_set | 仅在状态变化时更新call与revision，报警状态由原报警流程管理 |
| business/yp001_business.c / BUS_EVT call分支 | 复用同一setter，保留原状态白名单及last_rx更新 |
| business/yp001_business.h | 声明供前台QP和已校验CAT1事件调用的setter |
| test_sip_disconnect_qp_states.py | 将真实业务源与现有NVDS/Flash fixture链接至实际QP状态专项 |
| 版本头、CAT1 main.lua、firmware_version.json | 由现有工具分配1.5.17/b21，CAT1只同步源码身份 |

拨号命令发出后的DIALING表示呼叫请求阶段。接通和结束仍由现有CAT1业务消息推进。SIP READY表示初始化就绪，因此本轮没有按同事实现将READY当作正在拨号。既有页面策略在报警有效期间优先保留SOS页面，屏幕实际图像待烧写观察。
