## 命令（双击 `sync.bat` 出中文菜单；或 `sync.bat <命令>`、`python tree_sync.py <命令>`）

| 命令 | 作用 |
|---|---|
| `scan` | 按基线把差异分成 svn_changed / prj_changed / conflict / new_in_* 等，附 CAT1 OTA 规则检查；报告在 `reports/<时间>/summary.md` |
| `baseline` | 两边一致时记基线（哈希）+ 把 CAT1、GR Src 内容存档到 `_archive/tree_sync_base_<时间>.zip`（三方合并用） |
| `pull [--yes]` | 同事单边改的文件 → 项目。**CAT1 受保护文件一律跳过**（`--allow-protected` 才覆盖，只在我们自己确认后用） |
| `push [--yes]` | 项目单边改的文件 → SVN |
| `merge` | CAT1 两边都改的文件：以项目（实板验证版）为底、基线存档为 BASE 三方合并，结果在 `reports/merge_<时间>/merged`，不写两边；同时对结果跑 OTA 规则 |
| `handoff` | 交给同事前：两边一致性、CAT1 OTA 规则、密钥/临时文件（SDK/external 第三方除外）、GR 与 CAT1 版本号是否一致 |

不带 `--yes` 只预览。

## CAT1 OTA 规则（`ota_guard.py`，可单独用：`python ota_guard.py <要查的目录> [实板验证版目录]`）

依据 `doc/2026-11-02_CAT1代码交接清单_同事改代码与OTA.md`：

| 规则 | 级别 | 内容 |
|---|---|---|
| R1 | BLOCK | `ota_*` `business_*` `update.lua` 等受保护文件，或 `main.lua` 的版本/OTA 段/require 顺序，与验证版不同 |
| R2 | BLOCK | 新的 `io.mkdir`（快照遇未登记目录 → DIRECTORY_UNVERIFIED） |

| R5 | WARN | 新增根目录写入（`io.open w/a`、`io.writeFile`、`os.remove`、`fskv.set/del`），`/ram`、`/sd`、`/log`、`/ble` 除外 |

| R7 | BLOCK | `require` 的模块不在目录里，也不是固件内置 |
| R8 | WARN | `fs_log` 的 `LOG_MAX` 超过 16 KB |
| R9 | INFO/WARN | 源码总量比验证版的增量（LuaDB 余量 42012） |
| R10 | BLOCK | Lua 语法错误 |

## 典型流程

1. **同事交回代码后**：`scan` → 看 summary 里每类差异和 OTA 规则。
2. 同事单边改的：`pull`（受保护文件自动跳过，单独看它的 diff，确实需要就由我们改）。
3. 两边都改的：`merge` → 处理 `merged` 里的冲突标记 → 复制到项目 → 主机测试（技能 `yp001-whole-ota-run` §2）→ 上板。
4. 上板通过后：`push` 回 SVN → `baseline`。
5. **交给同事前**：`handoff`，结论“可以交接”或把剩余 BLOCK/WARN 写进交接清单。
