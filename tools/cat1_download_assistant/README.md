## 2026-10-20 连续下载修复

SAM | 2026-10-20 16:28 +08:00 | 分离连接和首次上电，避免重连 PWRKEY 关机，并支持完成/取消后再次下载。

新版使用“仅连接 GR（不动电源）”连接 COM26，不再随连接自动触发电源。只有确认 CAT1 未开机时，才点“首次上电（CAT1 未开机）”。以下旧版步骤中的“连接并给 CAT1 上电”由这两个明确入口替代。

CAT1 已在运行或上一轮已完成时：

1. 点“再次下载 / CAT1 已运行”，助手不发上电/PWRKEY，并释放 GR 串口。
2. Luatools 保持打开，重新点“仅下载脚本”等待设备。确认清除 fs、清除 kv 均未选中，仍使用核对过的脚本集合。
3. 接通 BOOT↔EXT，点助手第 1 步。在 Luatools 点模块重启并点助手第 2 步；或直接点助手“备用：用 GR 串口重启 CAT1”。备用操作自动连接 GR，探测后只发一次 ATREBOOT，再释放串口，不进行 PWRKEY 或电源循环。
4. Luatools 识别下载端口后断开 BOOT↔EXT，再点助手第 3 步。
5. Luatools 成功后点第 4 步，释放 GR 串口；下一轮直接从步骤 1 开始。

失败时先在 Luatools 停止下载，再点助手“取消本轮并释放串口”，随后再次下载。助手的取消只重置自身状态，不替代 Luatools 停止操作。不得在安装/烧写中硬断电。ATREBOOT 若因 OTA 挂起被模块拒绝，不自动绕过保护。

新版没有循环下载、自动上电重试或自动调用 Luatools 烧写的逻辑。不能用本工具的状态代替 Luatools 的实际成功结果。若出现成功后自动重烧，记录当时 Luatools 日志和窗口；当前源码修复不代表该外部现象已经实机排除。

已通过主机连续三轮状态机验证；连续实机烧写、不重启 Luatools 的验收仍待执行。工具不控制 BOOT 飞线，不打开 CAT1 原生 USB 口，不清除用户数据。旧版 EXE 保留作追溯，请停止使用旧版，避免其仍占用 GR 串口。

1. 选择连接 GR UART0 的 COM 口（当前记录优先使用 COM26），点击“连接并给 CAT1 上电”。工具先发送 `help` 探测 GR CLI；接受旧版 `GR5526 CLI`、`Available commands`，以及当前 GUI Guider 固件的 `GUI Guider ... >` 回显。没有这些回显时会停止，不会误发上电命令。确认后才依次发送 `cat1_power on` 和 `cat1_power key`：前者请求 VCC_4G，后者让 GR5526 保持 Air780EGH PWRKEY 约 1.6 秒；两者缺一不可。
2. 等待 Windows 设备管理器出现 CAT1 USB 设备。CAT1 未枚举时，不要进入下载步骤。
3. Luatools 选择已经核对过的底包/脚本集合，保持“等待下载”；CAT1 USB 数据线保持连接。随后把飞线开关拨到 `BOOT ↔ EXT` 接通。EXT 是 `VDD_EXT`，不可接地、接 5 V 或接电池。
4. 工具中点第 1 步，再在 Luatools 点击“模块重启”。
5. Luatools 识别下载端口后，断开 `BOOT ↔ EXT`，在工具点第 3 步，然后在 Luatools 开始下载。
6. 只有 Luatools 显示下载完成，才点第 4 步。该工具不会把串口发送或 USB 枚举当成下载成功。

“备用：用 GR 串口重启 CAT1”仅在 Luatools 的模块重启不可用时使用。选择连接 GR UART0 的 COM 口（115200/8N1），先执行第 1 步，再点击备用按钮。工具发送的文本是 `cat_at ATREBOOT\r\n`：GR 透传到 Air780EGH 的 `ATREBOOT`，模块会在没有 OTA 挂起时软重启。该方式不能控制 BOOT 飞线，也不能确认 USB 下载已完成。

工具不执行清文件系统、清 KV、擦除芯片或更换 SOC 底包。COM 端口、USB 端口和 Luatools 设备实际状态仍需现场核对。
